# 制作の依頼と、Production の面の設計(2026-10-19 に利用者と決めた)

承認された配信を、制作に頼むためのしくみ。前提とする運用は [FLOWS.md](FLOWS.md)、承認は [APPROVAL.md](APPROVAL.md)。作る順番は [BACKLOG.md](BACKLOG.md) の 12 章(PR1〜。2 章の P1〜P5 とは別)。

## 1. なぜ分けるか(利用者の指摘)

- 承認までのやり取りは「**何を配信するか**」(企画 ↔ レビュー・承認する部署)、承認のあとのやり取りは「**どう見せるか**」(企画 ↔ 制作)で、話題も相手も違う。
- 制作の人は、制作に要るもの(プレビュー・テキスト・商品・URL・制作指示)だけを見て、コピーして使いたい。計画の配信カードには、制作に要らないもの(AI の案・承認のやり取り)が多い。
- そこで、計画の配信カードは企画とその関係者の画面、**制作のページ**は企画と制作の画面に分ける。

## 2. 決めたこと

| 項目 | 決めたこと |
|---|---|
| 面 | ヘッダーの切り替えに **Production** を足す(**Plan | Production | Results**)。Plan・Results と**同じカレンダー(配信日)**で、同じ配信が同じ日・同じ位置に出る(表・中・裏)。ツールバー(期間・月 / 週 / 一覧・絞り込み)も同じで、面を切り替えても、期間・見せ方・絞り込みはそのまま |
| 配信の箱 | 色は制作の状態。締め切りを小さく添え、近い・過ぎたものに印。承認前の配信は薄く(押すと「承認のあとに制作に依頼します」) |
| 制作のページ | 箱を押すと、**フロート**で開く(配信カード・結果と同じ開き方) |
| 写し | 制作のページの中身は、配信カードの中身を固めた写し。**承認されたときに下書きとして作り**(企画が制作指示・担当・締め切りを整える時間)、**「この内容で制作に依頼する」で固める**(制作が見始める版)。そのあと配信カードを変えても、制作のページは黙って変わらない。企画が変わって承認がやり直しになったら「企画が変わりました」と知らせ、もう一度承認されたら新しい版を作る |
| 中身 | コピーしやすいことを第一に。項目ごとに「コピー」。プレビュー、テキスト(件名・ヘッドライン・コピー・セクションの見出しとコピー・ボタンの文言。アプリは通知のタイトル・本文・時刻・相手)、選定された商品(画像・名前・コード・価格・商品ページの URL(計測用のパラメーター付き)。セクションごと・メールの並び順)、リンク先(場所ごとの URL。アプリは開く画面)、メイン画像(画像と URL)、制作指示・担当・締め切り、**プレビューの HTML のソース**(コピーと .html の保存) |
| 制作のページの並び | 左から **要素の情報(たためる)| HTML のエディタ | プレビュー | やり取り(たためる)**。材料を見る → 書く → 確かめる → 相談する、の順で、左のコピーを隣のエディタに貼れる。状態と操作は題名のすぐ下の行に、いつも出す。フロートの大きさとペインの幅は変えられ、覚える(共通の部品 `src/floatLayout.ts`)(2026-10-19、利用者と決めた) |
| HTML の編集 | エディタは CodeMirror(色分け・行番号・字下げ)。右のプレビューは、エディタの HTML をアプリの画面とは切り離した枠(iframe)でそのまま描き、直したらすぐ反映。書き出す HTML は要素ごとに改行・字下げ。**直した HTML は版ごとに 1 つ保存**でき、「プレビューから作り直す」でいつでも下書きに戻せる。依頼・配信のしくみへの送信は、エディタの HTML を送る。主に制作の人が直し、企画の人も直せる |
| HTML | 最初は「プレビューと同じ見た目の下書き」。配信のしくみにそのまま入れられる完成品(表で組んで書式を直接書く形)は、要るならあとで。画像は、いまはパスワード付きのサイトから配るので、HTML をサイトの外で開くと見えない(Workbench は、Workbench を開いているブラウザなら見える) |
| 依頼のあとに要素を直す | 承認のあとの文言・メイン画像・商品(替える・足す・外す・並べ替え)・リンク先の調整は、企画と制作のあいだで決めてよく、**承認のやり直しは要らない**(2026-10-19、利用者と決めた: 企画として承認されたことで OK)。制作のページの左のペインで、依頼したあとの版で直して保存する。**配信カードと、承認された写し(`snapshot`)は書き換えず**、直した中身を同じ形で `production_requests.edited_snapshot`(直した日時・人も)に持つ。企画から変えた行には「企画から変更」の印と元の値(打ち消し線)を出し、行ごと・まとめて企画の値に戻せる。保存した HTML は自動では作り直さず、「要素を直したあと、作り直していません」と知らせる(直した HTML を消さないため)。制作指示・担当・締め切りは、ここでは直さない |
| 制作の人ができること | 読む・コピー・**要素を直す**・やり取り(制作の段階のもの)・タスク・**「受け取った」**(状態を「制作している」に。だれがいつ受け取ったかを残す)・**「制作が終わった」**(できたもののリンクとひとことを任意で) |
| 工程の帯 | 題名の下の行は、左から右へ進む工程の帯: **① 制作に依頼する(企画)→ ② 受け取る(制作)→ ③ 制作する(制作)→ ④ 仕上がりの確認(企画)→ ⑤ 配信のしくみに送る(企画)**。終わった段に ✓、**いまの段のボタンだけ**を出す。いちばん新しく終えた段には「やり直す」(依頼の段は「依頼を取り下げる」)があり、1 段ずつ戻せる(`POST /api/production/requests/{id}/undo`。取り下げた版は状態 `withdrawn` で記録に残り、やり直すときは新しい版で依頼し直す)(2026-10-19、利用者の指摘: 依頼と送るが横に並ぶと、どれがいまの一手か分からない。左が始まり・右が終わり) |
| 段階の帯(フロートどうしの行き来) | 配信カード・制作のページ・詳しい結果の題名の左に **PLAN → PRODUCTION → RESULTS**(`src/StageNav.tsx`)。段ごとに短い状態を添え、押すと同じ配信の隣のフロートに切り替える。配信カードは下に開いたまま残し、制作のページ・結果はその上に重ねる(直しかけを捨てないため)。承認前の制作、配信日前の結果は押せない |
| 仕上がりの確認(PR7) | ④。制作が終わった版を、企画がプレビューと HTML で確かめ、「これで OK」(`checked`。`POST /requests/{id}/check`)か「直してほしい」(書いた中身を `revision_note` に残し、③ 制作する に戻す。終わった・確認の記録は消す。`POST /requests/{id}/revise`)。直してほしいことは ③ の段に出る。送れるのは、確認した版だけ(2026-10-20) |
| 配信のしくみに送る | ふだんは工程の最後(⑤)。仕上がりを確認した版を、新しい版を作らずに「送った」にする(`POST /api/production/requests/{id}/send`。HTML はいまのエディタのもの)。制作を通さない近道は、工程の帯の右の「…」のメニューの「制作を通さずに、配信のしくみに送る」(`POST /api/production/send`。新しい版を作る。② ③ は「飛ばした」と出る)。**いまはサーバーに送り先の窓口だけを作り、実際には送らずに「送りました」と返す**(配信のしくみの API が決まったら、窓口の中だけを書き換える)。承認されていない配信は送れない。送ったことは履歴に残し、状態は「制作を通さず、配信のしくみに送った」 |
| やり取り | 計画の配信カードのやり取り(企画の段階)と、制作のページのやり取り(制作の段階)を分ける。表は同じ `card_notes` に列 `stage`(`plan` / `production`)を足す。過去の質問は制作、コメントは企画に振り分ける |
| リアクション | やり取りの書き込みに、Teams のような軽い返事(👍 了解 / 👀 見ています / ✅ 対応します / 🙏 ありがとう / ❓ 確認したい)。状態は変えない。だれが押したかは、マウスを重ねると出る |
| 配信カードとの行き来 | 計画の配信カードの右端に「制作の依頼」の札(状態・未解決の数)。押すと制作のページを重ねて開く。制作のページから「企画を見る」で配信カードを重ねて開く |

## 3. 状態

| 値 | 画面の名前 | 次に動く人 | どうなったら |
|---|---|---|---|
| `draft` | 制作に依頼する前 | 企画 | 承認されたとき(写しの下書きができる) |
| `requested` | 依頼済み(受け取り待ち) | 制作 | 企画が「この内容で制作に依頼する」 |
| `in_progress` | 制作している | 制作 | 制作が「受け取った」 |
| `done` | 制作が終わった(確認待ち) | 企画(仕上がりの確認) | 制作が「制作が終わった」 |
| `checked` | 仕上がりを確認した | 企画(配信のしくみに送る) | 企画が「これで OK」(PR7) |
| `sent` | 配信のしくみに送った | 企画 | 確認した版の「送る」、または近道の「制作を通さずに送る」 |
| `withdrawn` | 依頼を取り下げた | 企画 | ① の「依頼を取り下げる」 |
| `stale` | 企画が変わりました(古い版) | 企画 | 承認済みの配信の中身が変わって、承認がやり直しになったとき |

## 4. データ

| 表 | 列 | 中身 |
|---|---|---|
| `production_requests` | `delivery_card_id`・`version`・`status`・`snapshot`(写しの JSON)・`instructions`(制作指示)・`production_owner`・`production_due`・`requested_at`・`requested_by_name`・`received_at`・`received_by_name`・`done_at`・`done_by_name`・`done_note`・`done_link`・`sent_at`・`sent_by_name` | 配信 1 本の制作の依頼の 1 版。生きている版は配信ごとに 1 つ(古い版は `stale`) |
| `card_notes`(列を足す) | `stage`(`plan` / `production`) | やり取りが、どの段階の話か |
| `note_reactions` | `card_note_id`・`user_id`・`user_name`・`kind` | やり取りの書き込みへのリアクション |

## 5. あとで

- ファイルを上げる(画像・HTML)。要るか見てから。
- 配信のしくみの本物の API。
- メール用の HTML(表で組んで書式を直接書く形)。
