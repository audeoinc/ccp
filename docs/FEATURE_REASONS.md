# 機能の理由の台帳と、ユーザーストーリーとの対応表 — Campaign Contents Planner(CCP)

[USER_STORIES.md](USER_STORIES.md) の作業・確認と、CCP の機能をつなぐ資料。
「この作業・確認を満たすために、この機能があり、その理由はこれ」という筋が、通っているかを確かめるために使う。

- **1. 理由の台帳**: 機能ごとに、なぜその機能があるか(理由)と、その根拠。
- **2. 対応表**: ユーザーストーリーの作業・確認(実装済み・一部)ごとに、対応する機能。
- **3. 両方向の確認**: 機能 → 作業・確認、作業・確認 → 機能の、つながりの漏れ。
- **4. 推測の一覧**: 根拠となる記録がなく、推測で書いた理由。**確認をお願いしたい部分**。

### 根拠の種類

| 印 | 意味 |
|---|---|
| 【要望】 | 開発中の、ユーザー(企画者)の要望・判断。開発時のやり取りの記録による |
| 【文書】 | 設計の資料(ARCHITECTURE.md / BACKLOG.md / FEATURES.md / ONBOARDING.md) |
| 【履歴】 | 開発の履歴(変更の記録) |
| 【コード】 | ソースコードの中の説明(コメント) |
| 【推測】 | **根拠となる記録がなく、推測で書いたもの。確認が必要** |
