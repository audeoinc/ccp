# CCP の AI を Gemini からほかの AI に変える「出口」の作り(プラン)

2026-10-29 作成。CCP は、いま Google の Gemini を使っています。**使う組織の都合で、ほかの AI(Copilot 系・Azure OpenAI・Claude・社内の AI など)を使いたいときに、CCP をどう作っておくか**をまとめました。Microsoft の Copilot 系を使う場合の比較は [AI_PLATFORMS.md](AI_PLATFORMS.md) にあります。

## 結論

- **CCP のサーバーに、AI を外に頼む「出口」を 1 つ設けます。** 設定に外の層の URL が入っていれば、CCP の AI はすべて、その層に頼みます。空なら、いまどおり Gemini を使います。
- **使いたい AI へのつなぎは、CCP を動かす環境の側で「層」として作っていただきます。** CCP は、どの AI にも依らない層との約束(何を送り、何を返すか)を決めて文書にします。層の中で、どの AI を、どうつないで使うかは自由です。
- **Gemini はバックアップとして残ります。** 設定を空にして起動し直すだけで、Gemini に戻せます。
- **CCP の機能の開発は、これまでどおり続けます。** CCP を動かす環境では、CCP の中身を新しい版に入れ替えるだけで機能が新しくなり、AI は層が担ったままです。

## 1. ねらい

- CCP の機能の開発は、いまの開発の環境で続けたい。
- 使いたい AI は、使う組織ごとに違い、その組織の環境からしか使えないことが多い(例: Copilot は、その組織の Microsoft の契約の中でだけ使える)。そのため、AI へのつなぎは、CCP を動かす環境で作るのがよい。
- CCP を動かす環境では、CCP をそのまま動かし、**AI に聞く所だけ**を使いたい AI に任せたい。
- 何かあったときのために、Gemini にも戻せるようにしておきたい。

## 2. 形: CCP から外の層を呼ぶ「出口」

```
  画面 ──► CCP のサーバー(配布する CCP そのまま)
               │  AI が要る所(4 か所)
               ▼
         ┌ 出口の設定が空 ──► Gemini        ← いまどおり。バックアップ
         └ 入っている     ──► 外の層(CCP を動かす環境が作る) ──► 使いたい AI(Copilot 系・Azure OpenAI・Claude など)
```

- 層は、CCP のフォルダの**外**に置きます。CCP を新しい版に入れ替えても、層は消えません。
- 外の層が CCP の窓口(`/api/ask`)を横取りする形も考えましたが、次の理由で、CCP から層を呼ぶ形にしました。
  - CCP の AI は、文章の下書きだけではありません。**画像を AI に見せる所が 3 か所**あります(3 章)。これらは CCP の中で、画像を読む・AI の見分けを残す処理をしてから AI を呼びます。外で横取りすると、層がその処理まで作り直すことになります。
  - 横取りだと、CCP の作りが変わったときに、知らせずに層が壊れます。出口なら、**約束(5 章)だけを守れば**、CCP の中が変わっても層はそのまま使えます。

## 3. 出口を通す所

| # | 所 | 送るもの |
|---|---|---|
| 1 | 文章の下書き・言い換え・商品の選定など | 指示文だけ |
| 2 | メイン画像の説明の下書き | 画像 1 枚 + 指示文 |
| 3 | 部品の画像(ボタン・バナーなど)の説明の下書き | 画像 1 枚 + 指示文 |
| 4 | 商品ページの画像の提案 | 画像いくつか + 指示文 |

開発者向けの画面の AI(データベースの問い合わせを書くものなど)は、利用者の画面の AI ではないので、出口を通さず、Gemini のままにします。

## 4. 設定

CCP のサーバーの設定(環境変数)に、次を足します。

| 名前 | 中身 | 空のとき |
|---|---|---|
| `AI_OUTLET_URL` | 外の層の窓口の URL(例: 同じマシンの `http://127.0.0.1:<ポート>/ask`) | Gemini を使う |
| `AI_OUTLET_TOKEN` | 層に送る合言葉。層は、これがない呼び出しを断る | 送らない |
| `AI_OUTLET_TIMEOUT` | 1 回の待ち時間(秒) | 120 |

- **Gemini に戻すときは、`AI_OUTLET_URL` を空にして、サーバーを起動し直します。** 画面からは切り替えません。使っているうちに AI が変わると、使う人が混乱するためです。
- 層が失敗しても、**自動で Gemini には回しません**。画面にエラーを出します。どちらの AI が書いたか分からなくなるのと、「Google にデータを出したくない」という場合に困るためです。
- 同時に AI を呼ぶ数の上限は、いまの Gemini と同じ考えで、出口にも効かせます。
- 困ったときの確かめ(`python -m ccp.cli check`)に、出口の行を足します。出口が設定されていれば、その URL に届くかを見ます(合言葉は表示しません)。

## 5. 層との約束(版 1)

### CCP から層へ

`POST <AI_OUTLET_URL>`、`Content-Type: application/json`、合言葉があれば `Authorization: Bearer <AI_OUTLET_TOKEN>`

```json
{
  "version": 1,
  "purpose": "ask",
  "parts": [
    { "text": "…指示文…" },
    { "image": { "mime_type": "image/jpeg", "data": "<base64>" } }
  ],
  "response_format": "json",
  "effort": "low"
}
```

| 項目 | 中身 |
|---|---|
| `version` | 約束の版。いまは 1 |
| `purpose` | 使う所(`ask` / `hero_describe` / `part_describe` / `product_image_suggest`)。層が、所ごとにモデルや待ち時間を分けたいときに使う。分けなくてもよい |
| `parts` | 並んだ順に AI に渡す。文だけのときは 1 つ。画像は JPEG・PNG・WebP |
| `response_format` | いまは常に `json`。**答えは JSON の文だけ**にする(説明の文や囲みを付けない)。指示文でも JSON を求めている |
| `effort` | 考える深さの目安(`minimal` / `low` / `medium` / `high`)。層は無視してもよい |

### 層から CCP へ

| 結果 | 返すもの |
|---|---|
| 成功 | `200`、`{"text": "<AI の答え(JSON の文)>"}` |
| 失敗 | `200` 以外、`{"error": {"message": "<使う人に見せてよい理由>"}}`。混み合いは `429` にすると、画面に「混み合っています」と出せる |
| 答えが空 | 失敗として返す |

- 約束を変えるときは `version` を上げ、配布する CCP の文書と、リリースの知らせに書きます。
- CCP は、層が返したものの `text` だけを読みます。

## 6. 層を作る側にお伝えしたいこと

- **1 回の「AI で下書き」で、AI を 6〜9 回呼びます。** 1 回の答えが遅い AI やつなぎ方だと、全体が遅く感じます。API で直接呼べる AI のモデル(Gemini・Azure OpenAI・Claude など)が向いています。
  - 例: Copilot Studio を Direct Line でつなぐと、1 回に 1〜10 秒かかり、遅く感じるおそれがあります。Microsoft なら、Azure OpenAI を使うと速くなります([AI_PLATFORMS.md](AI_PLATFORMS.md) のおすすめ A)。
- **画像を読める AI** を選んでください(3 章の 2〜4)。読めない AI にする場合は、層がその 3 つの `purpose` だけを Gemini などほかの AI に回す、という分け方もできます。
- **答えを JSON の形で正しく返せること**が大事です。AI に「JSON だけで返す」設定があれば使ってください。
- 指示文は日本語です。画面が English のときは、英語に言い換えた指示文が届きます。どちらも同じように扱えば大丈夫です。
- 層は、外から呼べないようにしてください(同じマシンの中だけで待つ、か、合言葉を確かめる)。
- 層は、CCP のフォルダの外に置いてください。
