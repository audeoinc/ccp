# テンプレートの部品を ID で持つ(テンプレートのオブジェクト管理)の設計

2026-10-22 に利用者と決めた方針と、それを作るための設計(何を、どの順で、いまのデータをどう移すか)。
シンプルな配信カード([SIMPLE_CARD.md](SIMPLE_CARD.md)。プレビューの部品を押して直す)と合わせて進める。

---

## 1. ねらい

- テンプレートの**部品ごとに ID を持たせ**、コメント・ピン・直し・制作への指示・あとの分析を、部品にひも付ける。
  いまは、ボタンだけが ID を持ち、セクション・箱の枠・ヒーローは「上から何番目か」で区別している。並べ替えると、コメントや成績が別の部品に移ってしまう。
- テンプレートは、**本部が作るグローバル**と、**各国が作るもの**の 2 種類にする。どの国のテンプレートも、ほかの国がそのまま使える。
- 「同じテンプレート ID・同じ部品 ID」なら同じものとして、国・配信をまたいで比べられるようにする。

## 2. 決めたこと

### 2.1 テンプレートは 2 種類

| 種類 | 作る・直す人 | 使える人 |
|---|---|---|
| グローバル | 本部 | すべての国 |
| 国のテンプレート | 作った国(と本部) | すべての国(ほかの国が作ったものも、そのまま使える) |

- **国ごとのアレンジ(グローバルを元に、親とつながったまま国で直したもの)は持たない。** 変えた時点で別のものになり、分析で比べにくくなるため(利用者の判断)。
- ほかの国のテンプレートは、**写さずに、同じテンプレート ID のまま使う**。国をまたいで同じものとして比べられる。
- 自分の国に合わせて変えたいときは「**複製して、自分の国のテンプレートにする**」。新しいテンプレート(別の ID)で、分析も別。どれを元にしたかだけ残す(`copied_from`)。
- 直せるのは、作った国と本部だけ。ほかの国は「使う」か「複製」だけ。
- 作った国が新しい版にしても、使っている配信は、使った版のまま(いまの版の仕組み。[ARCHITECTURE.md](ARCHITECTURE.md) の 5 章)。

### 2.2 ID の組み立て

```
テンプレート(テンプレート ID)
 └ 版(版の番号)
    └ セクション(sec_…)  … 見出し・コピーは、セクションに持たせる
        ├ 箱(box_…)
        │   └ 枠(cell_…) … 商品が 1 つ入る所
        ├ ボタン(btn_…)
        └ コメント(txt_…) … 文だけの部品
    ヒーローも「ヒーローのセクション」(sec_hero)として、同じ形で持つ
```

- **セクションは入れ物**にする(いまは「箱 1 つ = セクション 1 つ」で、ボタンはセクションの外)。メールの見た目(見出し → 商品 → ボタン)と、AI の作り方(セクションごとに見出し・コピー・商品)に、そのまま合う。
- 部品 ID は、**動かしても、設定を変えても、版が変わっても同じ**。複製したときだけ新しい ID にする。
- 部品 ID は、テンプレートの中で一意(テンプレートをまたいで一意である必要はない。比べるときは、いつも「テンプレート ID + 部品 ID」で見る)。
- 形: 種類の頭 + 短いランダムな文字(例 `sec_k3f9`・`box_2m8q`・`cell_x7`)。画面にはふだん出さず、S1・ボタン A のような呼び名を出す(問い合わせ用に、マウスを重ねたときだけ出す)。

### 2.3 配信カードの側は、新しい ID を作らない

配信カードは、1 つのテンプレートの 1 つの版を使い、構成は変えない(T2 で決めた)。そのため、1 枚のカードの中に同じ部品 ID が 2 回出ることはない。
**配信カード ID + 案(AB の A / B)+ 部品 ID(+ 枠)** の組み合わせで、配信の中の部品が 1 つに決まる。

| ひも付けるもの | 鍵 |
|---|---|
| コメント・ピン・制作への指示 | 配信カード ID + 案 + 部品 ID(+ 枠 ID) |
| 見出し・コピーなどの中身 | 配信カード ID + 案 + セクション ID |
| 枠に載せた商品(`delivery_products` の行) | 行の ID はいまのまま。どの枠かを `cell_id` で持つ |
| 結果(位置ごとのクリックなど) | 配信カード ID + 案 + 部品 ID(+ 枠 ID) |

- 1 本の文字列が要る所(URL・計測のパラメーター)は、`カードID:案:部品ID` のように組み立てる。新しい表・採番は要らない。
- 分析は、見る範囲で鍵を使い分ける: 「テンプレート ID + 部品 ID」で全配信の S1、「配信カード ID + 部品 ID」でその配信の S1。

## 3. データの持ち方

### 3.1 テンプレート(表 `layout_templates`・`layout_template_versions`)

列を足す(`server/schema.json` と型を一緒に直す):

| 列 | 中身 |
|---|---|
| `scope` | `global` / `country` |
| `country` | 作った国(グローバルは空) |
| `copied_from` | 複製の元のテンプレート ID(と版)。分析では別のものとして扱い、経緯だけを残す |

- 標準の 10 種(コードに持つもの)は、グローバルとして扱う。
- 版の中身(セクションの JSON)は、新しい形(3.2)で持つ。

### 3.2 版の中身(新しい形)

```jsonc
{
  "schema": 2,                       // 新しい形の印(印がなければ、いまの形として読む)
  "hero": { "id": "sec_hero", "text": "below", "link": "campaign", "topBar": false },
  "sections": [
    {
      "id": "sec_k3f9",
      "heading": true,               // 見出しを付ける(AI が文言を作る)
      "copy": true,                  // コピーを置く
      "parts": [
        { "type": "box", "id": "box_2m8q", "cols": 3, "view": "card",
          "cells": [ { "id": "cell_x7", "c": 0, "r": 0, "w": 1, "h": 2 }, … ] },
        { "type": "buttons", "id": "btn_7d2a", "buttons": [ { "id": "b1", "label": "", "style": "outline", "link": "campaign" } ] },
        { "type": "text", "id": "txt_q1w2", "text": "…" }
      ]
    }
  ]
}
```

- 商品の載る順は、セクションの順 → セクションの中の箱の順 → 箱の中の枠の順。いまと同じく、全体を通した番号でも数えられる(`sectionsOf` などは、この順で数える)。
- 以前の種類(grid・mosaic など)は、箱の見本として表せる(grid 2 列 4 点 = 2 × 2 の箱、mosaic = 枠をまとめた箱 など)。新しい形では、すべて箱にする。

## 4. 移し方

**いまのデータは消さず、読むときに新しい形に直す。** 保存するときに、新しい形で書く。

### 4.1 テンプレート

- 読むとき(`layoutTemplates.ts` の読み込み): 印 `schema: 2` がなければ、いまの形から作る。
  - いまのセクション 1 つ → セクション 1 つ + その中に箱 1 つ。以前の種類は、同じ見た目の箱に直す。
  - 独立したボタンの部品(`buttonBlocks`。`at` = その前のセクションの数)→ その前のセクションの、箱の後ろに入れる。`at` が 0(ヒーローの直後)なら、ヒーローのセクションに入れる。
  - **ID は、順番から決めて付ける**(例 セクション 2 の箱の枠 3 → `cell_2_1_3`)。版は固定なので、毎回同じ ID になり、ピン・コメント・中身の鍵がずれない。
  - 一度保存したら、以後はその ID を持ち続ける(順番から作った ID も、そのまま使い続ける)。
- 標準の 10 種は、コードの定義に ID を書き足す(版 0。構成は変えない)。

### 4.2 配信カード

- いまの中身(`section_titles`・`section_copies` は、セクションの番号の並び)は、**使った版のテンプレートで、番号 → セクション ID に読み替える**。版が決まっているので、読み替えは一意。
- 新しく保存するときは、セクション ID を鍵にした形で書く(列の中身の形を変える。`section_texts` のような新しい列にするかは、作るときに決める)。
- 載せた商品(`delivery_products.section`・`sort_order`)は、枠の番号から `cell_id` を求めて書き足す(列 `cell_id` を足す)。番号の列は、互換のために残す。
- ピン(`card_notes.anchor`。`section:N`・`button:<id>` など)は、そのまま読める。新しく置くピンは `part:<部品 ID>` で持つ。古い目印は、使った版のテンプレートで部品 ID に読み替えて表示する。

### 4.3 プレビューの目印

- `Preview.tsx` の `data-part` に、部品 ID を足す(例 `data-part-id="cell_x7"`)。いまの `data-part`(`sectionTitle:N` など)と `data-anchor` は残す(シンプルな配信カードとピンが使っている)。
- `src/simple/parts.ts` の `PartRef` に、部品 ID を持つ種類を足す(`{ kind: 'part'; id: string; cell?: string }`)。番号で見分けていた所は、順に部品 ID に置き換える。

### 4.4 以前の版のアプリ・Workbench 版

- 新しい形(`schema: 2`)は、以前の版のアプリでは読めない。**テンプレートを新しい形で保存するのは、新しい版のアプリが行き渡ってから**にする(読み込みを先に出し、書き込みはあとの版で出す)。
- Workbench 版は、引っ越し用のパックで本番のデータを持ち込むので、同じ版のアプリで読む。

## 5. 画面

### 5.1 テンプレートの一覧

```
[すべて] [グローバル] [この国] [ほかの国]           ヘッダーの国: JP
┌──────────┐┌──────────┐┌──────────┐
│ 絵         ││ 絵         ││ 絵         │
│ 新作まとめ  ││ 冬のギフト  ││ Holiday    │
│ グローバル  ││ JP          ││ US          │
│ 4 か国・32 本││ 1 か国・5 本 ││ 2 か国・6 本 │
└──────────┘└──────────┘└──────────┘
選んだテンプレート: [使う] [複製して、この国のテンプレートにする] [編集](作った国・本部だけ)
```

- 絞り込みの「この国」は、ヘッダーの国。「ほかの国」は、作った国ごとにまとめる。
- カードに、作った国と、使っている国の数・配信の本数を出す(選ぶときの目安)。
- 配信カードのテンプレートの選択肢も、同じ絞り込み(この国のもの・グローバルを上に、ほかの国のものは下にまとめる)。

### 5.2 テンプレートの編集

- いまの「一覧 | 部品 | キャンバス | 設定」のまま。
- キャンバスで、セクションを枠で囲み(S1, S2…)、その中に箱・ボタン・コメントが並ぶ形にする。部品は、セクションの中・間に落とせる(セクションの外に落とすと、新しいセクションになる)。
- 右の設定に、選んだ部品の「コメント」を足す(スレッド。いまの `CommentsPanel` を、部品 ID の鍵で使う)。
- 作った国・本部でない人が開いたときは、見るだけ(「複製して、この国のテンプレートにする」を出す)。

### 5.3 配信カード(シンプルな配信カード)

- プレビューで部品を押すと、その部品(部品 ID)が選ばれ、右のペインで直す・コメントする(SIMPLE_CARD.md の 5・6 章)。コメントは、配信カード ID + 案 + 部品 ID で持つ。

## 6. 進める順番

| 段階 | 中身 | 主なファイル |
|---|---|---|
| 1 | **部品 ID**: テンプレートの読み込みで、すべての部品に ID を付ける(4.1 の順番から決める)。編集画面で足した部品には新しい ID。プレビューに `data-part-id` を出す | `templates.ts`・`layoutTemplates.ts`・`TemplateManager.tsx`・`Preview.tsx` |
| 2 | **ピン・コメントを部品 ID で**: 新しいピンは `part:<ID>`。古い目印の読み替え。テンプレートの編集画面の部品コメント | `pinStore.ts`・`PreviewPins.tsx`・`CommentsPanel.tsx`・`simple/parts.ts` |
| 3 | **グローバル / 国のテンプレート**: 列 `scope`・`country`・`copied_from`、一覧の絞り込みと 3 つの操作、編集できる人の判定 | `server/schema.json`・`layoutTemplates.ts`・`TemplateManager.tsx`・`ContentPane.tsx` |
| 4 | **セクションを入れ物に**: 版の中身を新しい形(3.2)で読み書き。キャンバスでセクションを囲む。ボタン・コメントをセクションの中へ | `templates.ts`・`layoutTemplates.ts`・`TemplateThumb.tsx`・`Preview.tsx`・`aiSelect.ts` |
| 5 | **コメントの部品**(文だけの部品。まずテンプレートで決める固定の文) | 段階 4 の形で作る |
| 6 | **配信カードの中身を部品 ID で**: 見出し・コピーをセクション ID で、載せた商品に `cell_id` | `CardDetail.tsx`・`simple/editor.ts`・`server/schema.json` |
| 7 | **分析を部品 ID で**: テンプレート ID + 部品 ID の集計(BACKLOG の T4) | 結果・効果の画面 |

- 段階 1・2 は、いまのデータの形を変えずにできる(シンプルな配信カードの土台になるので、先に)。
- 段階 4 は、データの形を変える一番大きい所。4.4 のとおり、読み込みを先に出す。
- 段階 3 は、段階 1・2 と別に進められる(列を足すだけで、いまのテンプレートはグローバルとして扱う)。

## 7. まだ決めていないこと

- グローバルを編集できる人: 本部の役割をどう決めるか(いまの利用者の表 `users` の `role` に足すか、承認のグループを使うか)。
- 文言の言語: グローバルのテンプレートの固定の文(ボタン・コメント)を、言語ごとに持つか(配信カードで上書きできるなら、1 つの言語で足りる)。
- 配信カードの中身を部品 ID で持つ列の形(段階 6)。
