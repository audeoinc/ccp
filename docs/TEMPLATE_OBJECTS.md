# テンプレートの部品を ID で持つ(テンプレートのオブジェクト管理)の設計

2026-10-22 に利用者と決めた方針と、それを作るための設計(何を、どの順で、いまのデータをどう移すか)。
画面の形は、触れる試作で利用者と何度も確かめて決めた(5 章。試作では「表で結合・分割する」案 B を採った)。
シンプルな配信カード([SIMPLE_CARD.md](SIMPLE_CARD.md)。プレビューの部品を押して直す)と合わせて進める。

---

## 1. ねらい

- テンプレートの**部品ごとに ID を持たせ**、コメント・ピン・直し・制作への指示・あとの分析を、部品にひも付ける。
  いまは、ボタンだけが ID を持ち、セクション・箱の枠・ヒーローは「上から何番目か」で区別している。並べ替えると、コメントや成績が別の部品に移ってしまう。
- テンプレートは、**本部が作るグローバル**と、**各国が作るもの**の 2 種類にする。どの国のテンプレートも、ほかの国がそのまま使える。
- 「同じテンプレート ID・同じ部品 ID」なら同じものとして、国・配信をまたいで比べられるようにする。

## 2. 決めたこと

### 2.1 テンプレートは 2 種類

| 種類 | 作る・直す人 | 使える人 |
|---|---|---|
| グローバル | 本部 | すべての国 |
| 国のテンプレート | 作った国(と本部) | すべての国(ほかの国が作ったものも、そのまま使える) |

- **国ごとのアレンジ(グローバルを元に、親とつながったまま国で直したもの)は持たない。** 変えた時点で別のものになり、分析で比べにくくなるため(利用者の判断)。
- ほかの国のテンプレートは、**写さずに、同じテンプレート ID のまま使う**。国をまたいで同じものとして比べられる。
- 自分の国に合わせて変えたいときは「**複製して、自分の国のテンプレートにする**」。新しいテンプレート(別の ID)で、分析も別。どれを元にしたかだけ残す(`copied_from`)。
- 直せるのは、作った国と本部だけ。ほかの国は「使う」か「複製」だけ。
- 作った国が新しい版にしても、使っている配信は、使った版のまま(いまの版の仕組み。[ARCHITECTURE.md](ARCHITECTURE.md) の 5 章)。

### 2.2 ID の組み立て

```
テンプレート(テンプレート ID)
 └ 版(版の番号)
    └ セクション(sec_…)  … 表(列 1〜4 × 行 1〜8)。見出し・コピー・AI の切り口のメモは、セクションに持たせる
        └ 部品(マス。box_… / btn_… / txt_… / emp_…)… 表のマスを敷き詰める。結合したマスも 1 つの部品
            種類: 箱(商品 1 点)・ボタン・テキスト・空き
    ヒーローも「ヒーローのセクション」(sec_hero)として、同じ形で持つ
```

- **単位はセクションと部品だけ**(「2 × 2 の箱の塊」のような単位は持たない。利用者の判断)。**箱 1 つ = 商品 1 点**。
- セクションは**表**: 部品は {列 c, 行 r, 幅 w, 高さ h} を持ち、表をすき間なく敷き詰める(空いた所は「空き」の部品)。左に縦長 1 + 右に 2、のような形は、マスの結合で作る。
- 部品 ID は、**動かしても、中身の設定(見せ方・文言・リンク先など)を変えても、版が変わっても同じ**。
- **形が変わったら新しい ID**(結合・分割・種類の変更・複製)。比べるときに、条件の違う部品を同じものとして扱わないため。使わなくなった ID のコメント・成績は、その ID を使っていた版の記録として残る(結合なら、元の ID を `merged_from` に残すと追える)。
- 部品 ID は、テンプレートの中で一意(比べるときは、いつも「テンプレート ID + 部品 ID」で見る)。
- 形: 種類の頭 + 短いランダムな文字(例 `sec_k3f9`・`box_2m8q`)。画面にはふだん出さず、S1・箱 3 のような呼び名を出す(オブジェクトのタブの詳しい欄にだけ出す)。
- 商品の載る順(箱の番号)は、セクションの順 → 上の行から → 同じ行は左から。

### 2.3 配信カードの側は、新しい ID を作らない

配信カードは、1 つのテンプレートの 1 つの版を使い、構成は変えない(T2 で決めた)。そのため、1 枚のカードの中に同じ部品 ID が 2 回出ることはない。
**配信カード ID + 案(AB の A / B)+ 部品 ID** の組み合わせで、配信の中の部品が 1 つに決まる。

| ひも付けるもの | 鍵 |
|---|---|
| コメント・ピン・制作への指示 | 配信カード ID + 案 + 部品 ID |
| 見出し・コピーなどの中身 | 配信カード ID + 案 + セクション ID |
| 箱に載せた商品(`delivery_products` の行) | 行の ID はいまのまま。どの箱かを `part_id` で持つ |
| 結果(位置ごとのクリックなど) | 配信カード ID + 案 + 部品 ID |

- 1 本の文字列が要る所(URL・計測のパラメーター)は、`カードID:案:部品ID` のように組み立てる。新しい表・採番は要らない。
- 分析は、見る範囲で鍵を使い分ける: 「テンプレート ID + 部品 ID」で全配信の S1、「配信カード ID + 部品 ID」でその配信の S1。

## 3. データの持ち方

### 3.1 テンプレート(表 `layout_templates`・`layout_template_versions`)

列を足す(`server/schema.json` と型を一緒に直す):

| 列 | 中身 |
|---|---|
| `scope` | `global` / `country` |
| `country` | 作った国(グローバルは空) |
| `copied_from` | 複製の元のテンプレート ID(と版)。分析では別のものとして扱い、経緯だけを残す |

- 標準の 10 種(コードに持つもの)は、グローバルとして扱う。
- 版の中身(セクションの JSON)は、新しい形(3.2)で持つ。

### 3.2 版の中身(新しい形)

**作ったときに形を変えた(2026-10-22)**: 版の中身は、いままでと同じ配列のまま、表のセクションを `{ "kind": "table", "slots": 箱の数, … }` として入れる(ヒーローの見せ方・アプリの通知は、いままでどおり配列の中の別の要素)。以前の版のアプリは、知らない種類をグリッドとして `slots` で読むので、`schema: 2` の印を使わなくても壊れない(4.4)。ヒーローは表にしない(ヒーローの直後のボタンは、いちばん上のボタンだけのセクションにする)。

```jsonc
[
    {
      "kind": "table", "slots": 1,
      "id": "sec_k3f9",
      "name": "新作",                 // 画面の呼び名(任意)
      "heading": true,               // 見出し・コピーを置く(AI が配信ごとに書く)
      "aiNote": "今季の新作を先に",   // AI の切り口のメモ(商品を選ぶ・見出しを書くときに渡す)
      "cols": 2, "rows": 2,
      "parts": [
        { "id": "txt_q1w2", "type": "text",   "c": 0, "r": 0, "w": 1, "h": 1, "text": "…", "overridable": true },
        { "id": "btn_7d2a", "type": "button", "c": 0, "r": 1, "w": 1, "h": 1, "label": "", "style": "fill", "link": "campaign", "track": "new_more" },
        { "id": "box_2m8q", "type": "box",    "c": 1, "r": 0, "w": 1, "h": 2, "view": "card", "aiNote": "主役の新作" },
        { "id": "emp_x7",   "type": "empty",  "c": 2, "r": 0, "w": 1, "h": 1 }
      ]
    }
]
```

- 見せ方 `view`: card(写真 + 名前・価格)/ photo(写真だけ)/ detail(写真の横に説明)/ story(左右交互)。
- 画像・動画の部品(2026-10-23 利用者と決めた。`type: "media"`): 画像 `src`(部品の画像のライブラリから選ぶとその URL と `imageId`)、動画 `video`(メールでは再生できないので、画像をサムネイルにして ▶ を重ね、押すと動画へ)、代わりの文 `alt`、形 `ratio`(省略は横に広い 2:1)、リンク先の種類・計測用の名前(実際の URL は配信ごと。ボタンと同じリンク先の一覧に入る)、`swap`(配信ごとに差し替える。キャンペーンのバナーなど)。バナー・タイル・アイコン・地図(地図の画像 + 地図のページへのリンク)は、この部品で作る。フッター(SNS・会社情報)の共通化は保留。
- ボタン: 見た目に「文字のリンク」(`style: "text"`。WOMEN / MEN のような枠のない文字)、色 `color`(黒・赤・紺・緑・グレーから選ぶ。ブランドの見た目をそろえるため、自由な色は持たない。テンプレートで決め、配信ごとには変えない)。テキスト・ボタンの揃え `align`。
- 箱の写真の形 `ratio`(正方形・縦長・横長・横に広い。省略は縦長、写真だけの箱はマスの形)。
- セクションの見た目: スマホでの並び方 `mobile: "stack"`(縦に積む。省略は列のまま)、背景の色 `bg`(グレー・ベージュ・ブルー・ピンク)、上下の余白 `space`(狭い・広い)、区切り線 `divider`。
- 箱の見せ方をそろえる(2026-10-23 利用者と決めた。案 A と B): いくつかの箱を選ぶと、右のタブと ⚙ でまとめて直せる(箱ごとに違う値は「ばらばら」)。1 つの箱の設定の「この見せ方を、ほかの箱にも当てる」で、同じ行 / このセクション / すべての箱にそろえる。そろえるのは見本・見せ方・出すもの・価格の見せ方・バッジ・写真の形で、AI への一言はそろえない。右の「セクションと部品」のカードは、選んでいても、もう一度押す・矢印で閉じられる。
- 編集の便利: 行の「…」の「この行を複製」、Ctrl+C / Ctrl+V(右クリックにも)で部品を写して空きのマスに貼る(写した部品は新しい ID)。均等の行は、キャンバスでもメールと同じに同じ幅で描き、右端の + で空きのマスに部品を置く。
- 均等に並べる行(2026-10-23 利用者と決めた): セクションの `evenRows`(行の番号)。その行は、列に合わせず、中身のある部品(空きは除く)を同じ幅で並べる(例: 3 列の表の下に、ボタン 2 つを半分ずつ)。行の帯の「…」から付け外しし、帯に「＝」の印。編集の画面ではマスのまま。縦に結合した部品がかかる行には付けない。行を差し込む・消す・動かす・分ける・まとめるときは、番号を合わせてずらす。よく使う行に「ボタン × 2(均等)」。
- 箱の見せ方(2026-10-22 利用者と決めた。案 A と D): 出すもの `fields`(name・price・badge・desc・button。省略は見せ方の既定)、価格の見せ方 `priceStyle`(省略はふつう / sale: 商品の `regular_price` に取り消し線 + 赤い価格 / from: 「〜から」)、バッジの文言 `badge`(空は NEW)。名前・価格の文言は商品のデータから出し、テンプレートでは打たない(値段の食い違いを防ぐ)。よく使う組み合わせは見本(標準・価格だけ・写真だけ・セール・新作・詳しく)で入れる。キャンバスで選んだ箱の ⚙(ダブルクリック)で、その場で直せる。配信ごとの文言の上書き(案 C)は、段階 6 と一緒に作る。
- 以前の種類(grid・mosaic・cells など)は、この形の表で表せる(grid 2 列 4 点 = 2 × 2 の箱、mosaic = 左の縦 2 マスを結合した箱 など)。新しい形では、すべて表にする。
- メールに出すときは、表の行ごとに出し、スマホでは上の行から・左から縦に並べる(箱の番号と同じ順)。

## 4. 移し方

**いまのデータは消さず、読むときに新しい形に直す。** 保存するときに、新しい形で書く。

### 4.1 テンプレート

- 読むとき(`layoutTemplates.ts` の読み込み): 印 `schema: 2` がなければ、いまの形から作る。
  - いまのセクション 1 つ → セクション 1 つ(表)。以前の種類は、同じ見た目の表に直す(グリッド 2 列 4 点 → 2 × 2、モザイク → 縦 2 マスを結合 など)。
  - 独立したボタンの部品(`buttonBlocks`。`at` = その前のセクションの数)→ その前のセクションの表の下に、ボタンの行(行いっぱいの 1 マス)として足す。`at` が 0(ヒーローの直後)なら、ヒーローのセクションに入れる。
  - **ID は、順番から決めて付ける**(例 セクション 2 の 3 番目の部品 → `box_2_3`)。版は固定なので、毎回同じ ID になり、ピン・コメント・中身の鍵がずれない。
  - 一度保存したら、以後はその ID を持ち続ける(順番から作った ID も、そのまま使い続ける)。
- 標準の 10 種は、コードの定義に ID を書き足す(版 0。構成は変えない)。

### 4.2 配信カード

- いまの中身(`section_titles`・`section_copies` は、セクションの番号の並び)は、**使った版のテンプレートで、番号 → セクション ID に読み替える**。版が決まっているので、読み替えは一意。
- 新しく保存するときは、セクション ID を鍵にした形で書く(列の中身の形を変える。`section_texts` のような新しい列にするかは、作るときに決める)。
- 載せた商品(`delivery_products.section`・`sort_order`)は、箱の番号から部品 ID を求めて書き足す(列 `part_id` を足す)。番号の列は、互換のために残す。
- ピン(`card_notes.anchor`。`section:N`・`button:<id>` など)は、そのまま読める。新しく置くピンは `part:<部品 ID>` で持つ。古い目印は、使った版のテンプレートで部品 ID に読み替えて表示する。

### 4.3 プレビューの目印

- `Preview.tsx` の `data-part` に、部品 ID を足す(例 `data-part-id="box_2m8q"`)。いまの `data-part`(`sectionTitle:N` など)と `data-anchor` は残す(シンプルな配信カードとピンが使っている)。
- `src/simple/parts.ts` の `PartRef` に、部品 ID を持つ種類を足す(`{ kind: 'part'; id: string }`)。番号で見分けていた所は、順に部品 ID に置き換える。

### 4.4 以前の版のアプリ・Workbench 版

- 新しい形(`schema: 2`)は、以前の版のアプリでは読めない。**テンプレートを新しい形で保存するのは、新しい版のアプリが行き渡ってから**にする(読み込みを先に出し、書き込みはあとの版で出す)。
- Workbench 版は、引っ越し用のパックで本番のデータを持ち込むので、同じ版のアプリで読む。

## 5. 画面

### 5.1 テンプレートの一覧

```
[すべて] [グローバル] [この国] [ほかの国]           ヘッダーの国: JP
┌──────────┐┌──────────┐┌──────────┐
│ 絵         ││ 絵         ││ 絵         │
│ 新作まとめ  ││ 冬のギフト  ││ Holiday    │
│ グローバル  ││ JP          ││ US          │
│ 4 か国・32 本││ 1 か国・5 本 ││ 2 か国・6 本 │
└──────────┘└──────────┘└──────────┘
選んだテンプレート: [使う] [複製して、この国のテンプレートにする] [編集] (作った国・本部だけ)
```

- 絞り込みの「この国」は、ヘッダーの国。「ほかの国」は、作った国ごとにまとめる。
- カードに、作った国と、使っている国の数・配信の本数を出す(選ぶときの目安)。
- 配信カードのテンプレートの選択肢も、同じ絞り込み(この国のもの・グローバルを上に、ほかの国のものは下にまとめる)。

### 5.2 テンプレートの編集(試作で決めた形)

```
[テンプレート › 名前(押して直す)]                     [↶ 元に戻す][見本の写真][保存…]
┌─┬────────────┬───────────────────────────┬──────────────────┐
│テ│パーツ        │ キャンバス(メールの見た目)      │ [テンプレート|オブジェクト] │
│ン│ 箱・ボタン・  │  ⠿ S1 · 新作                │  テンプレート: 基本・全体の │
│プ│ テキスト      │   列・行の帯(…)と境目の +     │  見た目・状況・構成         │
│レ│ よく使う行    │   マス(箱・ボタン・テキスト・空き)│  オブジェクト: セクションの   │
│一│ 空のセクション │   + 行を足す / + 列              │  カードと部品の行(位置の絵)│
│覧│              │  ─── + セクション ───           │                  │
└─┴────────────┴───────────────────────────┴──────────────────┘
  ↑ たたんだ帯(押すと一覧)  各ペインの境目はスプリッターで幅を変える
```

- **テンプレートの一覧**: ~~左端に、たたんだ細い帯で置く(押すと開く)~~ → 2026-10-28 にやめた(押しても見取り図が大きく出るだけで、何もできなかった)。ほかのテンプレートとの比べは、右のタブ「テンプレート」の「似ているテンプレート」(10 章)。ほかのテンプレートを開くのは、編集をやめてから。
- **パーツ**(いつも開いておく): 箱(商品 1 点)・ボタン・テキストと、**よく使う行**(箱 × 2・箱 × 3・大 1 + 小 2・文 + 箱・ボタンの行。1 行まとめて置ける)、空のセクション。
  - **足すだけ**(中身のあるマスを置き換えない): 空きのマスに落とすとそこに入る。中身のあるマスの**端に落とすと、その側に行(上下)・列(左右)を差し込んで置く**(メールの編集画面・Notion と同じ考え)。表の下・右の + に落とすと、そのパーツの行・列が増える。押すと、選んでいるセクションのいちばん下に 1 行足す。
- **キャンバス**(操作の帯は置かない。操作は、キャンバスの上・右クリック・右のタブで。見出しの横に大きさの変更 − / つまみ / + / 全体。利用者の指示で足した):
  - マスを押す・なぞる(Shift+押す)で選ぶ。結合したマスにかかると、範囲が丸ごとに広がる。
  - **右クリック**: 結合・分割・空きにする・上下左右に行と列を挿入。**Ctrl+M** で結合、**Delete** で空きにする。
  - 行・列の帯の「…」: 挿入・移動・削除・「この行から下を、新しいセクションに」。帯の**境目の +** で、その位置に挿入。表の右と下の **+** で足す。**挿入した行・列は空き**。
  - 空きのマスの「**＋ 置く**」: 箱・ボタン・テキストを選んで入れる。
  - ボタン・テキストは、ダブルクリックでその場で文字を直す。
  - **セクション**: 間の + で空のセクション(見出しだけ。最初の行は列の数を選んで作る)を足す。**札(⠿ S1)をつかんで動かす**(間に青い線)。オブジェクトのカードの ↑↓、選んで Alt+↑↓ でも動かす。分ける(行の「…」から)・上とまとめる(列の数は多いほうに合わせる)。

  - **テンプレート**: 基本(名前・種類・説明)・全体の見た目(ヒーロー・ヘッドラインの置き方)・状況(商品の枠の数・版・使っている配信・同じ構成のテンプレート)・構成(セクションの一覧。押すとそこへ)。

- 選んだ部品の「コメント」(スレッド)は、オブジェクトのカードに足す(段階 2)。
- 作った国・本部でない人が開いたときは、見るだけ(「複製して、この国のテンプレートにする」を出す)。
- やめたこと(試作で試して外した): 部品を自由な位置に描く・押し下げる形(操作が難しい)、行ごとに型を選ぶだけの形(自由度が足りない)、左をタブにして右に選んだものだけを出す並び、操作の帯、スマホで見る、中身の入れ替え(⠿)、パーツで中身を置き換える。

### 8.4 要素(部品の中の、名前・価格・バッジなど)を ID で持つ

- **要素の ID は「部品 ID ＋ 要素の名前」**(例 `box_2m8q.image`・`box_2m8q.price`・`btn_7d2a.label`・`sec_hero.headline`)。新しい乱数の ID は作らない。部品の中に足した要素は `box_2m8q.txt_a1` のように足した分だけ。部品の形が変わる(結合・分割・種類の変更)と、部品 ID と一緒に要素の ID も新しくなる。見せ方・置き場所・文言を変えても、ID は変わらない。
- 要素ごとに持つもの:
  - **説明(Description)**: 人が読むための説明。任意で、空なら自動(例「S1 箱 1 の写真」)。分析の画面・UTM の対応表・制作への指示・コメントに出す。書き直しても ID は変わらない。部品にも説明を持つ。
  - **種類**: 文字 / 画像(例: バッジを文字の SALE にするか、画像のバッジにするか)。
  - **置き場所**: 上・下・左・右・写真の全体に重ねる(上 / 中央 / 下)。
  - **向き**(文字の要素): 横 / 縦書き(上から下)/ 90 度回す(8.8)。
  - **押せる**(メールの中でリンクになる)か。既定は、写真・名前・ボタンは押せる、価格・バッジ・説明・カラーチップ・レビューは押せない。要素ごとに切り替えられる。

- **箱の要素**: 写真・名前・価格・バッジ・説明・ボタン・カラーチップ(8.5)・レビュー(8.5)。いまの「出すもの」(`fields`)は、要素の一覧に置き換える(以前の形は、読むときに直す)。

### 8.5 箱の要素の追加

- **カラーチップ**(`box_xxx.swatches`): その商品の色の展開を、SKU のデータから自動で並べる。形(四角 / 丸)・大きさ・並べる数の上限(超えた分は「+3」)。**確かめること**: SKU のデータに色の値(#c8b29a のような色の番号)やチップの画像があるか。なければ、名前から色を引く対応表 / チップの画像を上げる / 当面は色の名前の札、から選ぶ。
- **レビュー**(`box_xxx.rating`): 星・平均点・件数(商品の `rating`・`review_count`)。それぞれ出す / 出さない。星は文字(★)で、満ちた星と空の星だけ(メールで崩れにくい)。出さない条件(件数が少ない(既定 3 件未満)・点が低い)。星の色は決まった色から。
- **作った(2026-10-23)**: 箱の「出すもの」に `swatches`(カラーチップ)と `rating`(レビュー)。カラーチップは `src/swatches.ts` が、載せた商品の SKU の色を SKU の順に重ならないように並べる(本物の SKU があれば見本は使わない)。色は SKU の新しい列 `color_hex`(任意。BigQuery の SKU の出力に、あれば使う列として足した)を使い、なければ色の名前(ブラック / Navy など)から引き、引けない色は名前の札。形(丸 / 四角)・並べる数の上限(既定 5、超えた分は「+3」)。レビューは 見せ方(★ 4.2 (128) / ★ (128) / ★ だけ)・出す件数の下限(既定 3)・出す点の下限(既定なし)。カラーチップを出す箱がないテンプレートでは、SKU を読まない。撮影用のデータの商品に、レビューの件数を足した

### 8.10 UTM(どこが押されたか)
