# 設計メモ: マーケティングポリシーを考慮した推論

マーケティングポリシー(販売の方針と、表現・配信の決まり)を CCP に取り込み、AI の推論(テーマ・商品・見出し・コピー・制作指示)で参照し、守れているかを確かめるための設計。

- 状態: **設計(2026-10-17 に利用者と合意)。M2(商品ごとの MD 方針を AI に渡す)だけ作った。** 作る順番は [BACKLOG.md](BACKLOG.md) の 10 章(M1〜M8)
- 取り込むファイルの形(変換する人・Claude 向け): [POLICY_FORMAT.md](POLICY_FORMAT.md)
- 関係する文書: [BIGQUERY.md](BIGQUERY.md)(本番のデータ。同じ「受け渡しの形に変換して入れる」考え方)、[PRINCIPLES.md](PRINCIPLES.md) の 6 章(判断は人、AI は補助)
- 利用先の名前・ポリシーの文書の名前・置き場所は、ここにも、コードにも書かない

---

## 1. 前提(利用者に確かめたこと。M1 の答え)

| 項目 | 内容 |
|---|---|
| 種類 | **4 つともある**。① 商品ごとの方針(主力 / 在庫処分、販促の期間)② 期間の方針(今月・この四半期の重点、重点の顧客)③ 表現の決まり(ブランドの口調、使ってはいけない言葉、価格表示)④ 配信の決まり(週の露出の上限、メールとプッシュの頻度)。ファイルは分かれていることがある |
| 置き場所と形 | 文書。**販売系の方針(①②)は Excel で週ごとに管理**(1 つのファイルに週が並ぶ)。**ルール系(③④)は Confluence・文書・人の頭の中** |
| 取り込む前の形 | Gemini がそのままでは読みにくいので、変換してから入れる。**この段階では、ある程度構造化されたものがある前提でよい**(販売系は構造化されたデータ、ルール系は決まった書き方の Markdown) |
| 更新の頻度 | 販売系は週ごと。ルール系は、まれ |
| 守らせ方の強さ | **物による**。商品の選定とコピーの生成で、効く決まりも、守らせる強さも違う |

## 2. 方針(結論)

1. **クライアントの形のまま入れない。CCP が決めた「受け渡しの形」に変換して入れる**(Excel・Confluence の形は、クライアントごとに違う。変換は、クライアント環境の Claude が [POLICY_FORMAT.md](POLICY_FORMAT.md) を見て行う。BigQuery と同じ考え方)。
2. 受け渡しの形は 2 つ。
   - **販売系(①②)= 表**(CSV。1 行 = どの週・どの市場の・何についての方針か)
   - **ルール系(③④)= Markdown**(決まった見出しと箇条書き。人が手で直しやすい。CCP が取り込むときに読み分ける)
3. **決まりごとに「どの依頼に効くか」と「強さ」を持たせる。** 強さは `must`(必ず守る)/ `should`(なるべく)/ `info`(背景として知っておく)。
4. **依頼ごとに、関係する決まりだけを AI に渡す**(コピーの依頼に、商品の選定の決まりは渡さない。プロンプトを大きくせず、遅くしない)。
5. **必ず守る決まりのうち、機械で確かめられるものは、コードで確かめる。** 破っていたら 1 回だけ作り直させ、それでも破っていれば警告を出す。**保存は止めない**(判断は人。PRINCIPLES 6-1)。

## 3. 取り込むもの(受け渡しの形)

詳しい書き方は [POLICY_FORMAT.md](POLICY_FORMAT.md)。ここは要点。

### 3.1 販売系の方針(週ごと)= 表

| 列 | 中身 |
|---|---|
| `week_start` | 週の始まり(月曜) |
| `market` | 市場(`JP` / `US` など) |
| `scope` | 何についての方針か: `product`(商品)/ `category`(カテゴリ)/ `all`(その週・市場の全体。② 期間の方針) |
| `target` | `product` なら商品コード(SPU)、`category` ならカテゴリの名前、`all` なら空 |
| `stage` | 段階(主力 / 定番 / 在庫調整 / 新作 など) |
| `priority` | 優先度(1 が最も高い。空は普通) |
| `promo_period` | 販促の期間(開始 - 終了) |
| `focus` | その週の重点・重点の顧客(主に `all` の行) |
| `note` | 自由な文(方針・販促の予定) |

- 取り込みは、**ファイルに入っている週を、週ごとに置き換える**(1 つのファイルに週が並ぶため。ファイルにない週は、そのまま残す)。
- いまの商品ごとの MD 方針(表 `product_policies`。M2 で AI に渡している)は、この表の `scope = product` の行にあたる。新しい表に移すときに、配信日の週の行を選んで渡すようにする(M2 の仕組みは、そのまま使う)。

### 3.2 ルール系の決まり = Markdown

1 つの見出し(`##`)が、決まり 1 件。見出しの下に、決まった項目の箇条書きと、本文。

```markdown
## R-COPY-001 価格は税込みで書く
- 対象: copy, headline
- 強さ: must
- 市場: JP
- 確かめ方: 含めない /\d+円(?!\s*[(（]税込)/

価格を書くときは「1,980円(税込)」のように、税込みであることを添える。
```

| 項目 | 中身 |
|---|---|
| 見出しの最初の語 | 決まりの番号(ファイルをまたいで重ならないもの) |
| `対象` | どの依頼に効くか(4 章の表の名前。複数可) |
| `強さ` | `must` / `should` / `info` |
| `市場`・`チャネル`・`期間` | どこに効くか(書かなければ、すべて) |
| `確かめ方` | 機械で確かめられる決まりだけ(5 章)。書かなければ、AI に伝えるだけ |
| 本文 | 決まりの中身(自由な文。AI にそのまま渡す) |

- 取り込みは、**ファイルごとに置き換える**(同じファイル名で取り込み直すと、そのファイルの決まりが入れ替わる)。取り込んだ日時とファイル名を、版として残す。

## 4. どの依頼に、どの決まりを渡すか

| 対象(`対象` に書く名前) | CCP の依頼(`task`) | 渡すもの |
|---|---|---|
| `theme` | `suggest_themes` | 販売系の `all` の行(重点)、`theme` の決まり |
| `selection` | `select_section`・`select_section_products`・`suggest_replacements` | 販売系の `product` / `category` の行(商品の候補に付ける)、`selection` の決まり |
| `hero` | `select_hero` | `hero` の決まり |
| `headline` | `select_section_titles`・`select_section`(見出し)・`suggest_copies`(ヘッドライン) | `headline` の決まり |
| `copy` | `select_section_copies`・`select_section`(コピー)・`suggest_copies`・`suggest_push` | `copy` の決まり |
| `instructions` | `suggest_instructions` | `instructions` の決まり |
| `schedule` | (AI の依頼ではない) | 週の確認(確定の前に直すこと)で、コードが確かめる |

- 渡す決まりは、さらに配信カードの**市場・チャネル・配信日**で絞る。
- 指示文には、強さごとに分けて入れる: 「必ず守る(must)」「なるべく守る(should)」「背景(info)」。AI には、`must` に反する案を出さないこと、`should` に沿ったときは理由に書くことを伝える。
- `askAgent`(`src/aiSelect.ts`)が、依頼の `task` から対象を決めて、関係する決まりだけを足す(いまの「これまでの学び」・MD 方針と同じ仕組み)。

## 5. 守れているかの確かめ方

| 決まり | AI への渡し方 | できたものの確かめ方 |
|---|---|---|
| `must`、機械で確かめられる(`確かめ方` あり) | 「必ず守る」 | **コードで確かめる。** 破っていたら、どの決まりのどこが破れているかを添えて、1 回だけ作り直させる。それでも破っていれば、案のそばと配信カードに警告(決まりの番号と本文) |
| `must`、機械で確かめられない(口調 など) | 「必ず守る」 | 同じ返答の中で、AI に、守れているかと、気になる点を言わせる(追加の呼び出しはしない)。深く確かめたいときのために、配信カードに「方針で確かめる」ボタン(1 回の呼び出しで、配信全体を決まりに照らす) |
| `should` | 「なるべく」 | 確かめない。沿ったときは、理由に書かせる |
| `info` | 背景として | 確かめない |

`確かめ方` に書ける形(最初の版。足りなければ足す):

| 形 | 意味 | 使う例 |
|---|---|---|
| `含めない <言葉>, <言葉>, …` | その言葉を含めない | 使ってはいけない言葉、競合の名前 |
| `含めない /<正規表現>/` | その形の文字を含めない | 税込みの書き添えのない価格 |
| `含める /<正規表現>/` | その形の文字を必ず含める | 「送料無料」の注記 など |
| `除く 段階=<段階>` | 選定の候補から除く(選定の決まり) | 新作の配信に、在庫調整の商品を入れない(`期間`・`チャネル` と組み合わせる) |
| `上限 週 <数> 回` | 週に何回まで(配信の決まり・商品の露出) | 同じ商品は週 2 回まで(いまの週の確認の上限を、決まりから読む) |

- 確かめの結果は、保存を止めない(人が決める)。週の確認(確定の前に直すこと)にも、`must` を破っている配信を出す。

## 6. 画面

- ⚙ に「方針・決まりを取り込む」: ファイル(CSV / Markdown)を選ぶ → 中身の確かめ(件数、読めなかった行・項目と、その理由)を見せる → 取り込む。
- ⚙ に「方針・決まりの一覧」: 取り込んだ方針・決まりを、対象・強さ・市場で絞って見る(見るだけ。直すのは元のファイル)。版(ファイル名・取り込んだ日時)も出す。
- 配信カード: AI の案・選定の理由に、沿った方針(決まりの番号)を出す。`must` を破っている案に警告。「方針で確かめる」ボタン。

## 7. 保存の形(PostgreSQL。`server/schema.json` に足す)

| 表 | 中身 |
|---|---|
| `sales_policies` | 3.1 の列 + 取り込んだファイル名・日時 |
| `policy_rules` | 決まり 1 件 = 1 行(番号・題名・対象・強さ・市場・チャネル・期間・確かめ方・本文)+ ファイル名・取り込んだ日時 |

- どちらも、引っ越し用のパック(`server/ccp/pack.py`)の対象にする(Workbench にも持ち込めるように)。
- BigQuery に販売系の方針の表があるなら、8 章の取り込み(BIGQUERY.md)の 6 つめの出力にすることもできる(あとで決める)。
