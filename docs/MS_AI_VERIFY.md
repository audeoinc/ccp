# Microsoft の AI を CCP から呼ぶ検証の手順

2026-10-29 作成、2026-11-04 まとめ。CCP の AI を外の層に頼む作りは [AI_OUTLET_PLAN.md](AI_OUTLET_PLAN.md)、Gemini と Microsoft の候補の比較は [AI_PLATFORMS.md](AI_PLATFORMS.md)。

## 結論(2026-11-04 時点)

- **暫定の結論: CCP の使い方では、方式 1(Direct Line)が最も有力、方式 3(AI Builder を流れから)が次点。方式 2(Agents SDK)は外す。** 理由と比べた表は、下の「暫定の評価」。決める前に確かめることも、そこに書いた。
- **CCP から呼ぶなら、方式 1(Copilot Studio + Direct Line)が使える。** 人のサインインなしに、CCP のサーバー(層)が鍵だけで呼べる。CCP の頼み T1〜T10(文の頼み 5 つ・画像の頼み 5 つ)は、JSON がすべて ○、決まりもすべて ○。前置き・囲み・出典は 1 度も付かなかった。画像は、商品ページの写真 7 枚をまとめて送っても、アングルがすべて正しかった。
- **方式 2(Agents SDK)は、CCP の利用者一人ひとりに Microsoft のサインインが要る**(アプリだけで呼ぶ形が、まだない)。答えの形は方式 1 と同じだが、CCP には向かない。
- **方式 3(AI Builder のプロンプト)は、直接は呼べず、Power Automate の流れを窓口にすると呼べた。** 文の頼みも、画像の頼み(T6〜T10。写真 8 枚まで)も通った。画像は、流れの Image の欄に `base64ToBinary(…)` を式で入れて初めて通った。画像の入力は空にできないので、写真が足りないときは層が白い画像で埋める(8 枚で 8〜10 秒。15.8)。
- 速さ(方式 1): 文の頼みは本文まで 3.0〜4.6 秒 + 会話を始める 0.2〜0.7 秒。画像の頼みは 3.5〜11 秒(写真が大きいほど遅く、4MB で 16 秒)。CCP の「AI で下書き」(6〜9 回)を 4 本ずつ並べて呼べば、合わせて 10〜15 秒ほどの見込み(未確認)。
- 費用: Copilot のクレジット(方式 1 は 1 回あたり約 1)。環境にクレジットの用意が要る(管理者)。方式 3 はトークンの量で払い、本番では流れのプレミアムのライセンスも要る見込み。
- 利用者から見て差が出ないように、層で吸収することは 16 章(画像の組み替え・写真を縮める・エラーの文を見分ける・答えを JSON に整える・やり直しと時間切れ)。

| 方式 | 結果 | 人のサインイン | 文の頼み | 画像の頼み | 本文まで(文) |
|---|---|---|---|---|---|
| **1. Copilot Studio + Direct Line** | **使える** | **要らない**(鍵 → 短い期限のトークン) | JSON 6 / 6・決まり 6 / 6 | **○**(upload の入口。1 回 4MB まで) | 3.0〜4.6 秒 |
| 2. Copilot Studio + Agents SDK | 動くが CCP には向かない | **要る** | JSON 6 / 6・決まり 5 / 6 | ○(添付の `data:` の URL) | 3.3〜6.1 秒 |
| 3. AI Builder(プロンプト) | 流れを挟めば使える | 要らない(流れの URL の署名の鍵) | JSON 6 / 6・決まり 5 / 6(流れから) | ○(最大 8 枚。空いた欄は白い画像で埋める。JSON・決まりとも ○) | 2.4〜6.7 秒(流れを挟んで) |

Azure OpenAI は、いまは想定していない(2026-10-29 利用者)。

### 暫定の評価(2026-11-04)

ここまでの測った結果からの評価で、まだ決定ではない(下の「決める前に確かめること」のあとで決める)。

#### 画像の枚数の扱い

| 項目 | Direct Line | Agents SDK | AI Builder(流れ) |
|---|---|---|---|
| 枚数を毎回変えられるか | **そのまま変えられる**(送るたびに何枚でも添付できる) | そのまま変えられる | **そのままでは変えられない**。プロンプトの画像の入力は数が決まっている |
| 上限 | 1 回の送信が 4MB まで(枚数の上限はない) | 未確認 | プロンプトに作った欄の数(検証では 8) |
| 写真が足りないとき | 何もしなくてよい | 何もしなくてよい | **空の欄(null)は断られる**。層が小さな白い画像で埋め、頼みの文に「空の画像は無視する」と足す |
| 欄より多いとき | 何もしなくてよい | 何もしなくてよい | 層が 8 枚ずつに分けて呼び、答えをまとめる(試していない)。分けると、写真どうしを見比べる判断(T9 の picks)ができなくなる |
| 作るときの工夫 | なし | なし | 欄ごとに式 `if(empty(…), null, base64ToBinary(…))` を入れる。プロンプトの入力を変えたら、流れの箱でプロンプトを選び直す(前の欄が見えない形で残り、保存が断られた) |
| 答えの確かめ | 番号が渡した枚数の外なら、層が消す | 同じ | 同じ(白い画像で埋めた分、番号の取り違えが起きやすい。1 回あった) |
| 余分な費用 | なし | なし | 白い画像の分のトークン(少し) |

#### 全体の比較

| 項目 | Direct Line | Agents SDK | AI Builder(流れ) |
|---|---|---|---|
| 人のサインイン | 要らない | **要る**(CCP の利用者一人ひとり) | 要らない |
| 呼ぶ手順 | 4 段(トークン → 会話 → 送る → 取りに行く) | SDK が行う | 1 段 |
| 文の頼み | JSON・決まりとも すべて ○ | JSON ○、英語の文字数が少し長い | JSON ○、英語の文字数を大きく外れた(1 回の測定) |
| 速さ(文) | 3.2〜5.3 秒(会話を始める時間を含む) | 3.6〜7.9 秒(同じ) | 2.4〜6.7 秒 |
| 速さ(画像 7〜8 枚) | 11 秒(7 枚) | 試していない | 8〜10 秒(8 枚。1 回目だけ 89 秒) |
| 画像の枚数 | 自由 | 自由 | 8 枚まで。層が白い画像で埋める工夫が要る |
| 費用 | Copilot のクレジット(1 回あたり約 1) | 同じ | トークンの量(画像 1 枚でクレジット 3)+ 本番では流れのプレミアムのライセンス(見込み) |
| 作って保つもの | エージェント 1 つ | エージェント + Entra のアプリ | プロンプト + 流れ(+ 流れの接続) |
| 頼みの文を変えたとき | 層の頼みの文を変えるだけ(エージェントは中継) | 同じ | 層の頼みの文を変える。入力の欄を変えるなら、流れも直す |
| 壊れやすい所 | 会話の手順(層で持つ) | サインインの期限・承諾 | 流れの接続は作った人のサインインで動く。その人のアカウントが止まると流れも止まる(見込み) |
| 利用者から見た差 | ほぼなし | **Microsoft のサインインが増える** | ほぼなし |

#### CCP の使い方に照らした評価

CCP が AI に頼むことは、主に次の 4 つ: (1)「AI で下書き」で文の頼みを 6〜9 回並べて呼ぶ。(2) 写真の頼み(商品写真・メイン画像・部品の画像は 1 枚、商品ページの画像は 1〜8 枚で、商品ごとに枚数が変わる)。(3)「？ 聞く」で長い資料を付けて頼む。(4) 頼みの文は、機能を足すたびに増え、変わる。

| 観点(CCP での重み) | Direct Line | Agents SDK | AI Builder(流れ) |
|---|---|---|---|
| サインインなしでサーバーから呼べる(必須) | ◎ | ×(利用者ごとのサインイン) | ◎ |
| 写真の枚数が商品ごとに変わる(高) | ◎ そのまま | ◎ | △ 白い画像で埋める工夫が要る。8 枚を超えると見比べられない |
| 頼みの文が増え、変わる(高) | ◎ 層だけ直せばよい | ◎ | ○ 文だけなら層で済む。画像の入力を変えると流れも直す |
| 速さ(中) | ○ | ○ | ○(1 回目の遅さは要確認) |
| 答えの決まりを守る(中) | ◎ | ○ | △(英語の文字数) |
| 費用・ライセンス(中) | ○ クレジットのみ | ○ | △ プレミアムのライセンスも要る見込み |
| 作ったものを保つ手間(中) | ○ エージェント 1 つ | △ | △ プロンプト + 流れ + 接続 |
| 呼ぶ手順の手軽さ(低。層が持つ) | △ 4 段 | ○ | ◎ 1 段 |
| **総合** | **最も有力** | 外す | **次点** |

**Direct Line が最も有力な理由**

1. **写真の枚数をそのまま扱える。** 商品ページの画像は商品ごとに枚数が違う。白い画像で埋める工夫も 8 枚の上限もなく、見比べる判断もそのまま使える。
2. **頼みの文が増えても、直すのは層だけ。** エージェントは中継に徹するので、CCP に機能を足しても Microsoft の側を直さずに済む。
3. **決まりを守る力が高かった。** 英語の文字数まで含めて、すべての頼みが ○。
4. **費用がクレジットだけ。** 流れのプレミアムのライセンスが要らない。
5. 手間は会話の 4 段の手順だが、層に一度作れば済む。

**AI Builder(流れ)が次点の理由**

- 呼ぶ手順は最も手軽で、速さも答えの形もほぼ同じ。
- ただし CCP では、写真の枚数が変わること(白い画像で埋める)、頼みの形が変わること(流れを直す)、流れの接続とライセンス(作った人のアカウント・プレミアム)の 3 つが、続けて手間になる。
- 組織が Power Platform で管理したい(流れの実行の記録を残す・ソリューションで持ち運ぶ)なら、選ぶ値打ちがある。

**Agents SDK を外す理由**: CCP の利用者一人ひとりに Microsoft のサインインが要り、アプリだけで呼ぶ形がない(確か)。

#### 決める前に確かめること(どちらにも共通)

| こと | なぜ |
|---|---|
| 同時に呼んだとき | 「AI で下書き」は 6〜9 回を並べて呼ぶ。混み合いで断られないか |
| 長い頼みの文の上限 | 「？ 聞く」は長い資料を渡す |
| 会話・実行の記録が、どこにどれだけ残るか | 中身の扱いの決まりに合うか(13 章) |
| データの地域 | GPT Chat Latest は日本の外で処理されることがある(14 章) |
| 流れのライセンス(AI Builder を選ぶなら) | 本番の環境で、プレミアムが要るか |

### できなかったことと原因

「確か」は試して確かめたこと、「推測」は確かめていないこと。

| できなかったこと | 原因 | 確か / 推測 | 次の手 |
|---|---|---|---|
| Direct Line に 12MB の写真を送る | Direct Line の upload は、1 回の送信が 4,194,304 バイト(4MB)まで(400「MessageSizeTooBig」) | **確か**(答えの文に上限が出た) | 層で写真を縮める(長い辺 1024〜2048 の JPEG。512 まで素材を読めた) |
| Agents SDK を、人のサインインなしで呼ぶ | Copilot Studio の Agents SDK は、アプリだけの認証に対応していない | **確か**(Microsoft のサンプルの説明に「S2S is not currently supported」) | Direct Line を使う。アプリだけの認証が出たら見直す |
| GitHub Copilot ハーネスのエージェントを Agents SDK から呼ぶ | そのハーネスは、Agents SDK のつなぎに対応していない | **確か**(エージェントの答えに書かれていた) | 標準のハーネスで作る。**Direct Line からなら、GitHub Copilot ハーネスのエージェントも呼べた**(2026-11-04。ただし標準の 2 倍ほど遅い。12.6) |
| AI Builder の `Predict` を、アプリだけの認証で直接呼ぶ | 「Source is null」。プロンプトの `Predict` は、Power Apps・Power Automate の中から呼ばれる前提で、外のプログラムからは呼べない作り | **推測**(外の作者の報告と同じ症状。Microsoft の文書では確かめていない。人のサインインで直接呼ぶ形は試していない) | 流れを窓口にする(文の頼みは通った) |
| AI Builder の流れで、画像をプロンプトに渡す(**2026-11-04 に解決**) | Image の欄は、受けた中身を自分で base64 にする。HTTP で受けた base64 の文をそのまま入れると、2 重に包まれてプロンプトが画像として読めない。`base64ToBinary(…)` を**式として**入れる(前は文字のまま入っていた)と通った | **ほぼ確か**(式を正しく入れたら通った。失敗した実行の値の頭(2 重なら `LzlqLzRB…`)は見ていない) | 済み。流れの作り方は 15.8 |
| AI Builder の流れで、写真の枚数を毎回変える(T9) | プロンプトの画像の入力は数が決まっていて、空(null)にすると「入力パラメーターがモデルに対して無効です」で断られる | **確か**(8 つすべてを埋めると通った) | 入力を 8 つ持つプロンプトにし、層が空いた欄を白い画像で埋める(2 枚・4 枚で通った。15.8) |
| 流れから呼んだ AI Builder で、英語のコピーを 25〜35 文字に収める(T5) | プロンプトのモデル(GPT-5 chat・温度 0)が、文字数の決まりを守りにくい | **推測**(Direct Line のエージェント(GPT Chat Latest)では収まった。1 回しか測っていない) | 何回か測る。ほかのモデルで比べる |

### まだのこと

| こと | なぜ |
|---|---|
| AI Builder の流れで写真を 9 枚以上渡す | いまの流れは 8 枚まで。層が 8 枚ずつに分けて呼ぶ形は試していない |
| 頼みの文の長さの上限 | 「？ 聞く」は長い資料を渡す。Direct Line で、どこまで長い文を送れるか測っていない |
| 同時に呼ぶ | 「AI で下書き」は 6〜9 回を並べて呼ぶ。混み合いで断られないか |
| Gemini と同じ頼みで、秒数を比べる | 利用者から見て、待ち時間が変わるか |
| 同じ頼みを何回も送ったときのばらつき | 多くは 1 回ずつしか測っていない |
| データの扱い | 会話の記録がどこに・どれだけ残るか(13 章)。GPT Chat Latest は、日本では「cross-geo」(日本の外で処理されることがある)の扱い(14 章) |
| 方式 2 で、権限のない人が断られるか | 試したのは作った本人だけ(12.1) |
| CCP の層を作る | [AI_OUTLET_PLAN.md](AI_OUTLET_PLAN.md) の出口と、Direct Line を呼ぶ層(9 章)。作るかは利用者が決める |

## 読む前に

- 比べる項目: 認証の形・人のサインインが要るか・データの地域・会話の記録が残るか・待ち時間・JSON の形・画像・費用の形・用意の手間(10 章)。
- Copilot Studio の画面の名前は、画面の版で変わることがある。**「(未確認)」の印がある所は、実際の画面でまだ確かめていない。**確かめたら印を消す。
- この文書には、テナント・環境の名前、環境の ID・URL、メールアドレス、鍵を書かない。`<環境の ID>` のように置き換えて書く。

## 0. 守ること

- **サインインは人が行う。** Claude はパスワードを入れない。`pac auth create` でブラウザが開いたら、人に頼む。
- **環境にものを作るのは、人の指示があってから。** どの環境に何を作るかを、先に人に確かめる。
- **消すのは人。** Claude は、エージェントや環境を消さない。消し方を伝えて、人に消してもらう。
- 調べるだけのコマンド(`pac env list` など)は、確かめなしで行ってよい。
- **鍵(Direct Line のシークレット)・トークン・環境の ID・URL は、リポジトリの外に置く。** サーバーの設定(環境変数)か、リポジトリの外のファイル(`%USERPROFILE%\.ccp\ms-verify.env`)。コミット・チャット・文書に書かない。画面に出すときは、値を出さずに「入っている・長さ」だけを出す。

## 1. 用意するもの

| もの | 中身 |
|---|---|
| Microsoft のアカウント | Copilot Studio を使えるもの。サインインは人が行う |
| Power Platform の Developer の環境 | 個人の検証用の環境。会社全体の既定の環境(Default)は使わない |
| 環境の Copilot のクレジット | 環境に、Copilot のクレジットの割り当てか、従量課金の課金プラン(Azure のサブスクリプション)のつなぎが要る。**Developer の環境でも要る。テストの欄で試すだけでもクレジットを使う。** Power Platform の管理者が管理センターで行う(方式 1・2。方式 3 も同じになる見込み) |
| Windows の PC | winget と Node(22 以上)が使えるもの |
| Entra のアプリの登録 | 方式 2 だけ。12.3 |

### つまずき: 「This environment is out of credits」

テストの欄で頼みを送ると「This environment is out of credits. Contact your admin to add more credits. Error code: EnforcementUsageCredits.」と出て止まる(2026-10-29。保存しただけの下書きのエージェントでも出た)。環境に使えるクレジットがない。Power Platform の管理者に、次のどれかを頼む(未確認。管理センターのメニューの名前は版で変わる)。

1. 従量課金の課金プランを作り、環境につなぐ(Azure のサブスクリプションに請求される)。
2. 組織が買った Copilot のクレジット(容量)を、環境に割り当てる。
3. Copilot Studio の個人の試用が組織で許されていれば、それを使う。

環境にクレジットが付いたら、同じ下書きのエージェントのまま、テストの欄で答えが返るようになった(2026-10-30。公開は要らない)。テストの欄の頼みも 1 回ごとにクレジットを使う(T1 で 1 回あたり約 1 クレジット。10.1)。

## 2. Power Platform CLI(pac)を入れる

```powershell
winget install --id Microsoft.PowerAppsCLI -e
```

- winget で入るのは起動用の部分だけ。続けて本体を入れる。

```powershell
$env:Path = [System.Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [System.Environment]::GetEnvironmentVariable('Path','User')
pac install latest
pac help
```

- `pac help` に `Version: 2.x` が出れば済み。
- 入れた直後のターミナルでは `pac` が見えないことがある。ターミナルを開き直すか、上の 1 行目で Path を読み直す(Git Bash からは見えないことが多いので、PowerShell で使う)。
- `dotnet tool install --global Microsoft.PowerApps.CLI.Tool` は、.NET 8 の SDK で「DotnetToolSettings.xml がパッケージで見つかりませんでした」で止まった。winget を使う。

## 3. サインインする(人が行う)

```powershell
pac auth list      # すでにサインインしていれば、ここに出る
pac auth create    # ブラウザが開くので、人がサインインする
```

- 「authenticated successfully」と出れば済み。

## 4. 環境を選ぶ(読むだけ)

```powershell
pac env list
pac admin list     # Type の列: Default = 会社全体 / Developer = 個人
pac copilot list --environment <環境の ID>   # その環境のエージェントの一覧
```

- 検証は、自分の **Developer** の環境で行う。ほかの人の Developer の環境・Default の環境は使わない。
- 環境の ID を設定のファイルに書くときは、画面に出さずに取り出す(PowerShell で `pac env list` の表示名の行から取り出して、そのまま `ms-verify.env` に書く)。
- `pac copilot list` には、エージェントの名前・ID・状態が出る。**スキーマ名は出ない**ので、エージェントの「設定 → 詳細 → メタデータ」で見る。
- **`pac copilot list` の `Component State` の `Published` は、画面の「公開」とは別のもの。** 画面で保存しただけ(下書き)のエージェントでも `Published` と出た(2026-10-29)。**公開したかは、Copilot Studio の画面で確かめる。** pac 2.14.1 には、公開の日時を読むコマンドはない(`list` は環境の指定だけ、`status` は `componentstate_Property` のエラーで止まる)。公開の日時は Dataverse の表 `bot` の列 `publishedon` にあるはず(未確認)。
- `pac copilot extract-template` は、指定したファイルのほかに、**いま居るフォルダにも** `kickStartTemplate-1.0.0.json` を作る。リポジトリの中で流さない。中身にスキーマ名・モデルは入っていなかった。

## 5. 検証用のエージェントを作る(人が画面で行う)

方式ごとに、エージェントを分けて作る(方式 1 は認証を変えるので、方式 2 と同じエージェントは使えない)。

| エージェント | 方式 | 認証 |
|---|---|---|
| `CCP AI 出口の検証 標準` | 2(Agents SDK) | Microsoft で認証する(既定のまま) |
| `CCP AI 出口の検証 DL` | 1(Direct Line) | 認証なし + 鍵を必須(8 章) |

1. Copilot Studio を開き、サインインする。
2. 右上の環境の切り替えで、4 章で選んだ Developer の環境を選ぶ。
3. **標準(standard)のハーネスで作る。** 作る種類を選ぶ画面で、「Other ways to build」の下の **「エージェント [標準]」**(事前に定義したトピックとフローを使う、ルールベースの会話エージェント)を選ぶ(2026-10-30 確かめた)。いちばん上の「エージェント [GitHub Copilot]」で作ると、CCP から呼べない(12.6)。「エージェント [会話型 AI]」は、チャット・音声の顧客対応向けの別の種類なので選ばない。
4. 名前: 上の表のとおり。
5. 指示の欄を押してから、次をそのまま貼る。

```text
あなたは、メールやアプリのお知らせの配信を企画する担当者を助ける AI です(CCP という配信の企画ツールから呼ばれる検証用)。
- 頼まれた文(見出し・コピー・制作指示・テーマの案など)を、日本語の指示どおりに作ります。
- 指示に「JSON で返す」とあれば、説明や前置きを付けず、指示された形の JSON だけを返します。
- 分からないことは作らず、分からないと答えます。
- 個人情報や社外秘の内容は出しません。
```

6. 右上の「作成」。エージェントの「概要」の画面になる。
7. **モデルを、既定に任せずにはっきり選ぶ**(「概要」→「モデル」)。標準のハーネスでは **GPT Chat Latest** を選ぶ(12.6)。既定のモデルは環境や時期で変わり、Claude になっていることもある(2026-10-29 の検証の環境では、GitHub Copilot ハーネスの既定が Claude Opus 5.5 だった)。Anthropic のモデルを選ぶ前に 14 章を確かめる。**選んだモデルの名前を記録に書く**(測るプログラムは設定の `MODEL_LABEL`)。
8. 6 章の設定にして、右上の「保存」。
9. テストの欄で T1 を 1 回試す(7 章)。JSON が返れば OK。
10. 右上の「公開」→「公開する」(「最新バージョンを強制する」のチェックは入れない。Teams などで続いている会話を新しい版に切り替えるためのもので、検証では要らない)。
11. 「設定」→「詳細」→「メタデータ」の **スキーマ名** を、`ms-verify.env` の `COPILOT_AGENT_SCHEMA_NAME` に書く(方式 2 のエージェント)。

## 6. エージェントの設定(標準のハーネス)

2026-10-30 に画面で確かめた設定。

| 所 | 設定 | 理由 |
|---|---|---|
| 生成 AI → オーケストレーション | **はい**(生成 AI オーケストレーション) | 「いいえ(クラシック)」だと、決めたトピックにしか答えない。CCP の頼みは毎回違う文 |
| ナレッジ → 根拠のない応答を許可する | **オン** | オフにすると、ナレッジ・ツールを使わない答えが止められる。CCP の頼みは、指示と入力だけで答えを作る |
| ナレッジ → Web の情報を使用する | **オフ** | 頼みの中身が Bing の検索に使われない。出典が付かない |
| ナレッジ・ツール | 何も足さない | 頼みと関係のない内容が混ざらないように |
| ファイルの処理能力 → ファイルをアップロードする | **オン** | T6(画像)に要る。画像は png・webp・jpeg・gif、15MB まで |
| ファイルの処理能力 → コード インタープリター | **オフ** | CCP の頼みには要らない。プレミアム(追加の費用) |
| セキュリティ → 認証 | 方式 2: Microsoft で認証する(既定のまま)/ 方式 1: 認証なし(8 章) | |

GitHub Copilot ハーネスのエージェントには、最初から「ツール: Work IQ」と「ナレッジ: すべての Web サイトを検索」が入っていた(外す)。

### T9 商品ページの画像の提案(画像 1〜8 枚)

CCP のサーバー(Gemini)は、画像と「画像 0」などの文を交互に並べて渡す。Direct Line・Agents SDK では画像は添付にまとまるので、**番号と添付の順の対応を文で伝える**(下の「画像は、添付の順に…」の行)。最後の「判断済み」の画像は、画像を渡さず文字で渡す形(CCP で、前にアングルを見分けた画像)。下は 3 枚を添付したとき。

```text
あなたは、EC のメール・アプリの配信で、商品の見せ方を決める担当です。
下に、ある商品の商品ページに載っている画像を、番号つきで並べます(写真のほか、SVG のソースで渡す絵もあります。SVG はソースから絵を思い浮かべて判断してください)。
1. それぞれの画像のアングルを、次から 1 つ選ぶ: front(正面)・back(後ろ)・side(横)・worn(着用・人が身に着けている)・detail(ディテールの寄り: ボタン・縫い目・ポケットなど)・texture(素材の寄り)・scene(使っている場面・背景つき)・flat(平置き)・package(箱・付属品)・other
2. この配信で伝えたいこと(下の「配信」。テーマ・見出し・コピー)と、商品の強み(下の「商品」)から、この配信の商品画像に合う画像を、よい順に最大 3 つ選び、理由を 1 文で書く。
   強みが素材なら素材の寄り、着たときの形ならシルエットが分かる着用、のように、伝えたいことが見て分かる画像を選ぶ。
「判断済み」と書いた画像は、前にアングルを見分けた画像なので、画像は渡さず、アングルと写っているものを文字で渡します。それも選ぶ候補に入れる。
```

## 8. 方式 1: Direct Line を開く(人が画面で行う)

方式 1 用のエージェント `CCP AI 出口の検証 DL` で行う(5 章の手順で作り、6 章の設定にしたもの)。2026-10-30 に確かめた手順。

1. **「設定」→「セキュリティ」→「認証」で「認証なし」を選ぶ。** Direct Line の鍵だけで呼ぶため。
2. **すぐに「設定」→「セキュリティ」→「Web チャネルのセキュリティ」で「セキュリティで保護されたアクセスを要求する」をオンにする。** 認証なしのままだと、トークン エンドポイントの URL を知っている人なら、鍵なしで話しかけられる(試して確かめた。下の囲み)。
3. 同じ画面の **シークレット 1** をコピーし、`ms-verify.env` に `DIRECT_LINE_SECRET=<シークレット>` の行を足す。チャットには貼らない。
4. **右上の「公開」→「公開する」。** 2 の設定は、**公開して初めて効く**。
5. 鍵なしの入口で断られることを確かめる(12.4 の `check-token-endpoint.mjs`)。

Direct Line の窓口は、既定の `https://directline.botframework.com` でつながった(地域ごとの窓口は要らなかった)。窓口を変えるときは、`ms-verify.env` に `DIRECT_LINE_ENDPOINT=<窓口の URL の /v3/directline の手前まで>` を書く。

> **鍵を必須にした効き目(2026-10-30 に確かめた)**
> Direct Line のトークン エンドポイント(`https://<環境のホスト>/powervirtualagents/botsbyschema/<スキーマ名>/directline/token?api-version=2022-03-01-preview`)に、鍵なしでトークンを頼んだ。
>
> | 「セキュリティで保護されたアクセスを要求する」 | 公開 | 鍵なしの頼み |

> | オン | 済み | **403・トークンは出ない**(「ErrorCode 4011: The bot isn't available at this time」) |
> | オフ | 済み | **200・トークンが出る**(だれでも話しかけられる) |

> | オン | 済み | 403 に戻った |
>

> - チャネルの画面(「Web アプリ」「ネイティブ アプリ」)に出る `…/copilotstudio/dataverse-backed/authenticated/bots/<スキーマ名>/conversations` は **Agents SDK 用の接続先**で、トークン エンドポイントではない(人のトークンを付けて使う。鍵なしの GET は 404)。

## 9. 方式 1 で呼ぶ形(CCP の層が行うこと)

測るプログラム(12.4 の `--via dl`)で確かめた形。CCP の層([AI_OUTLET_PLAN.md](AI_OUTLET_PLAN.md))も、この形にする。

1. **鍵を短い期限のトークンに取り替える**: `POST https://directline.botframework.com/v3/directline/tokens/generate`(`Authorization: Bearer <鍵>`)→ `{"token": …}`。鍵は、ここでしか使わない。
2. **会話を始める**: `POST …/v3/directline/conversations`(`Authorization: Bearer <トークン>`)→ `{"conversationId": …}`。CCP の呼び出しは 1 回ずつ独立しているので、**頼みごとに新しい会話**にする(前の答えが混ざらないように)。1 と 2 で 0.2〜0.7 秒。
3. **頼みを送る**:
   - 文だけ: `POST …/conversations/<会話の ID>/activities` に `{"type":"message","from":{"id":"<層の名前>"},"locale":"ja-JP","text":"…"}`。答えの `id` を控える。
   - **画像あり**: `POST …/conversations/<会話の ID>/upload?userId=<層の名前>` に multipart で、`activity`(`Content-Type: application/vnd.microsoft.activity`。上と同じ JSON)と `file`(画像)を一緒に送る。**添付の `data:` の URL は、エージェントに「InvalidUri」で断られる。**
4. **答えを取りに行く**: `GET …/conversations/<会話の ID>/activities?watermark=<前の続き>` を、間を置いて繰り返す(測るプログラムは 0.25 秒ごと)。**答えの終わりを知らせる合図はない。** 自分以外から届いた `message` で、`replyToId` が 3 で控えた `id` のものを答えとみなす。答えは 1 通でまとめて届いた。
5. 答えの `text` を、層との約束(版 1)の `{"text": …}` にして CCP に返す。決まった時間(例: 120 秒)待っても届かなければ失敗として返す。

- 鍵は CCP のサーバーの設定(環境変数)に置く。漏れたら、画面でシークレットを作り直す。
- この形では、**どの利用者が頼んだかは、Copilot Studio の側には残らない**(すべて層の名前になる)。残すなら CCP の側で残す。
- **だれがエージェントを使えるかは、CCP に入れる人で決まる。** エージェントを呼べるのは鍵を持つ CCP のサーバーだけなので、CCP の画面に入れる人が、CCP を通してエージェントを使える。組織の人だけに絞るなら、**CCP の入口で組織のサインイン(Microsoft の Entra ID など)を通す**。方式 2 と違い、利用者一人ひとりに Copilot Studio の権限は要らない(Copilot Studio が利用者を確かめるのではなく、CCP が確かめる)。

## 12. 方式 2: Copilot Studio + Microsoft 365 Agents SDK

### 12.1 下調べと、試して分かったこと

| 調べたこと | 分かったこと |
|---|---|
| 人のサインインなしに、サーバーがアプリの名前で呼べるか | **できない。** サンプルの説明に「S2S is not currently supported for Copilot Studio」とある。クライアントは人のトークンが要る。アプリだけの認証は「予定にある」とされるが、時期は書かれていない |
| Entra のアプリの登録 | 公開クライアント(ネイティブ)のアプリ。リダイレクト URI は `http://localhost`。クライアントのシークレットは持たない(1 回ごとの合言葉 PKCE で、同じプログラムかを示す) |
| API の権限 | Power Platform API の**委任された権限** `CopilotStudio.Copilots.Invoke` と、Microsoft Graph の `User.Read`。承諾の画面には「Allows Invoking Copilots」「Sign you in and read your profile」と出た。承諾は承諾した人の分だけ |
| 呼べるかの確かめ | (未確認)サインインのときではなく、**エージェントを呼ぶときに**、その人がそのエージェントを使えるかが確かめられる見込み。試したのは、エージェントを作った本人のアカウントだけ。権限のない人が断られるか・共有すると呼べるかは、組織の別の人に協力してもらって確かめる |
| エージェントの側の設定 | 公開したエージェントが要る。認証は「Microsoft で認証する」のままでよい。つなぐ値は「設定 → 詳細 → メタデータ」の環境の ID とスキーマ名 |
| 言語 | .NET・JavaScript・Python のサンプルがある |
| 答えを届いた分から受け取れるか | 届いた順に読む仕組みはある。ただし試したときは、入力中の印のあと、本文は 1 通でまとめて届いた |
| 画像を渡せるか | **渡せた**。「ファイルをアップロードする」をオンにし、メッセージの添付に `{contentType: "image/png", contentUrl: "data:image/png;base64,…"}` を付けて送る。文書には書かれていなかった |
| エージェントを作り直したとき | テナント ID・アプリ ID・サインインはそのまま使えた(アプリの権限は特定のエージェントに結びついていない)。変えるのはスキーマ名だけ |

出典: Microsoft Learn「Integrate web or native apps with Microsoft 365 Agents SDK」、GitHub `microsoft/Agents` の `samples/*/copilotstudio-client` の説明、Copilot Studio のチームのブログ「Every Path to Integrating Your Copilot Studio Agent」。

### 12.2 人のサインインが要るときの形(案)

**CCP の利用者ごとにこの形で呼ぶなら、利用者の一人ひとりに Microsoft のアカウントと、エージェントを使える権限が要る。**

| 形 | 中身 | 問題 |
|---|---|---|
| A. 利用者ごとのサインイン | CCP の利用者が、Microsoft にサインインする。層は、その人のトークンでエージェントを呼ぶ | CCP の画面にサインインの流れを足す必要がある(CCP の作りが大きく変わる)。利用者全員に Microsoft のアカウントと Copilot Studio を使う権限が要る |
| B. 共用のアカウント | 層が、AI 用の 1 つのアカウントでサインインしたトークンを持ち、それで呼ぶ | 人のアカウントを機械に使わせる形で、組織の決まりに触れやすい。多要素認証・パスワードの期限でトークンが切れ、人がサインインし直す必要がある。だれが使ったかが残らない |
| C. 方式 1 を使う | Direct Line で、鍵だけで呼ぶ(8・9 章) | エージェントを「認証なし + 鍵を必須」にする。鍵の管理が要る |

### 12.3 試すときの段取り

1. Entra に、公開クライアントのアプリを登録する(12.1 の権限)。テナント ID・アプリ ID はリポジトリの外のファイルに置く。
2. エージェントを公開する(5 章)。
3. 測るプログラム(12.4。`tools/ms-verify/`)に設定を入れて動かす。最初の 1 回だけブラウザが開くので、人がサインインして承諾する。
4. 表(`results/<日時>_<方式>_<モデル>.md`)を 10.1 に写す。

### 12.4 測るプログラム(`tools/ms-verify/`)

Node(22 以上)のプログラム。7 章の T1〜T6 を送り、秒数と答えの形を表に書き出す。方式 1(Direct Line)と方式 2(Agents SDK)の両方で送れる。方式 2 の部分は、Microsoft のサンプル `microsoft/Agents` の `samples/nodejs/copilotstudio-client` を元にした。**検証の道具で、CCP の画面・サーバーには入れない**(Workbench 版の ZIP にも入らない)。

| ファイル | 中身 |
|---|---|
| `tools/ms-verify/measure.mjs` | 送って測る本体 |
| `tools/ms-verify/tests.mjs` | T1〜T6 の頼みと、決まりの確かめ(7 章と同じ中身。直すときは両方) |
| `tools/ms-verify/check-token-endpoint.mjs` | 鍵を必須にしたエージェントが、鍵なしの入口を断るかを確かめる(8 章)。Agents SDK 用の接続先の URL を入れたときは、Direct Line のトークン エンドポイントを組み立てて試す。別のエージェントは `--schema-name <設定の名前>` でスキーマ名を差し替える |
| `tools/ms-verify/package.json` | 使う部品(`@microsoft/agents-copilotstudio-client`・`@microsoft/agents-activity`・`@azure/msal-node`・`open`) |
| `scripts/pack-ms-verify.mjs` | 道具を ZIP に固める(下) |

**リポジトリの外に置くもの**(Git にも ZIP にも入れない):

| ファイル | 中身 |
|---|---|
| `%USERPROFILE%\.ccp\ms-verify.env` | 設定(下)。鍵・環境の ID などを書く |
| `tools/ms-verify/.token-cache.json` | 方式 2 のサインインのトークン(プログラムが作る。.gitignore で外す)。消すと、次はサインインし直し |
| `tools/ms-verify/images/` | T6 の写真(各自で用意する。.gitignore で外す) |
| `tools/ms-verify/results/` | 測った表(`<日時>_<方式>_<モデル>.md`)と、答えの全文(同じ名前の `.json`)。.gitignore で外す |

設定(`ms-verify.env`):

```text
COPILOT_ENVIRONMENT_ID=<環境の ID>          # 方式 2。エージェントの「設定 → 詳細 → メタデータ」
COPILOT_AGENT_SCHEMA_NAME=<スキーマ名>       # 方式 2。同じ所
TENANT_ID=<テナント ID>                     # 方式 2。Entra のアプリの登録の「概要」
APP_CLIENT_ID=<アプリ(クライアント)ID>     # 方式 2。同じ所
MODEL_LABEL=<モデルの名前>                  # エージェントの「概要」→「モデル」で選んだもの(記録に書く)
DIRECT_LINE_SECRET=<シークレット 1>          # 方式 1。「Web チャネルのセキュリティ」
DIRECT_LINE_ENDPOINT=<窓口>                 # 方式 1。なくてよい(既定の窓口)
COPILOT_TOKEN_ENDPOINT=<URL>                # 鍵なしの入口の確かめ。同じ環境のホストとスキーマ名が入った URL
FORBIDDEN_WORDS=<言葉>,<言葉>               # なくてよい。ZIP の検査で、入っていないことを確かめる言葉(テナント・環境の名前など)
```

動かし方:

```powershell
cd tools\ms-verify
npm install
node measure.mjs --self-test                 # つながずに、確かめの仕組みだけを試す
node measure.mjs --runs 1                    # 方式 2 で T1〜T5 を 1 回ずつ。最初の 1 回だけブラウザが開く
node measure.mjs --via dl --runs 1           # 方式 1(Direct Line)で T1〜T5 を 1 回ずつ。サインインしない
node measure.mjs --via dl --only T6 --image images\<写真>.jpg   # T6 を、画像を付けて送る(写真は各自で用意する。下)
node measure.mjs --via dl --only T7 --image images<写真>.jpg   # T7(メイン画像の説明)。T8 も同じ形
node measure.mjs --via dl --only T9 --image imagesa.jpg --image images.jpg   # T9 は --image を並べる(最大 8 枚)。写真に合わせて --theme・--product・--strengths で配信と商品を変えられる
node measure.mjs --only T3 --runs 5          # T3 だけ 5 回
node measure.mjs --model "<別のモデルの名前>"   # エージェントのモデルを替えたあと。MODEL_LABEL より優先
node check-token-endpoint.mjs                # 鍵なしの入口で断られるか(8 章)
```

- 画像を何枚も付けるとき、Direct Line では upload の入口に `file` の部分を並べる(並べた順が添付の順。T9 の番号はこの順)。Agents SDK では添付の `data:` の URL を並べる。
- 頼みごとに新しい会話を始める(CCP の呼び出しは 1 回ずつ独立しているため)。会話を始める秒数は、別の列に書く。
- 秒数は 4 つ: 会話を始めるまで・最初に何かが届くまで(入力中の印など)・本文が届くまで・終わりまで。
- モデルの名前は、つなぎ方からは分からないので、設定か `--model` で渡す。渡さないと止まる。
- 鍵・トークン・ID・URL は画面に出さない(つまずきの理由も 200 文字までにし、ID は伏せる)。
- **T6 の写真は、各自で用意する**(リポジトリ・ZIP には入れない)。服の写真を 1 枚、`tools/ms-verify/images/` に置いて `--image` で渡す(このフォルダは .gitignore で Git に入らない)。人の顔・社外秘の写る写真は使わない。形は png・jpeg・webp。方式やモデルを比べるときは同じ写真を使い、どの写真で試したか(何が写っているか・大きさ)を記録に書く。

#### ZIP にして渡す・受け取る

手で 1 つずつ落とさずに済むように、道具を 1 つの ZIP に固める。

```powershell
npm run pack:ms-verify                  # リポジトリの最上位で。release-out\ccp-ms-verify-<日付>-<コミット>.zip
```

- 入るもの: コミット済みの `tools/ms-verify/` と、この手順書の写し(`docs/MS_AI_VERIFY.md`)。コミットしていない変更は入らない。
- 必ず外すもの: `node_modules/`・`*.env`・`.token-cache.json`・`results/`・`images/`(コミットされていなくても、名前で外す)。
- 検査: 作った ZIP を読み直し、中身の一覧を出して、環境の ID(GUID の形)・メール・テナントのドメイン・環境のホスト・開発元の名前と、手元の `ms-verify.env` の値(と `FORBIDDEN_WORDS`)が入っていないかを確かめる。見つかったら止まる(値は出さない)。
- GitHub の Releases への公開: `npm run pack:ms-verify -- --publish`(タグ `ms-verify-<日付>-<コミット>`)。**公開は利用者の承認のあとだけ**(連絡係が流す)。
- 受け取った人: ZIP を展開し、中の `README.md` のとおり `npm install` から始める。設定は、各自の `%USERPROFILE%\.ccp\ms-verify.env` に書く(ZIP には入っていない)。

### 12.6 つまずき: 「GitHub Copilot harness」のエージェントは SDK から呼べない

2026-10-30、T1 を送ると、サインイン・つなぎは通ったが、エージェントから「This action doesn't support agents built with the GitHub Copilot harness.」とだけ返った(0.4 秒。頼みは処理されていない)。

- Copilot Studio のエージェントには「ハーネス」(エージェントを動かす仕組み)がある。**新しい画面のいちばん上の「エージェント [GitHub Copilot]」で作ると、GitHub Copilot ハーネスになる**。もう 1 つは、以前からある **標準(standard)のハーネス**(「Other ways to build」の「エージェント [標準]」)。
  - GitHub Copilot ハーネス: 目標を受けて手順を組み、ツールを使い分ける、重い仕事向け。名前に GitHub Copilot とあるが、GitHub Copilot のサービスにデータは行かない。
  - 標準のハーネス: 決まった話題・頼みに、決まった形で答える向け。チャネル・つなぎ方は、こちらのほうが揃っている。
- Microsoft Learn に書かれているのは、Power Automate の Copilot Studio のつなぎが GitHub Copilot ハーネスに対応していないこと。**Agents SDK も、試したとおり対応していない。**
- **標準のハーネスで作り直したエージェントは、Agents SDK からも Direct Line からも呼べた。** ハーネスを後から切り替える方法は、文書では見つからなかった(Microsoft は「移すのは作り直し」としている)。
- **Direct Line からは、GitHub Copilot ハーネスのエージェントも呼べた**(2026-11-04)。最初の「CCP AI 出口の検証」(モデル GPT 6.1 Sol)を、認証なし・「セキュリティで保護されたアクセスを要求する」オンにして公開した(どちらの設定も、このハーネスの画面にあった)。T1〜T5・T7 は JSON・決まりともすべて ○ で、答えの形は標準のハーネスと同じ。
  - **遅い**: 文の頼みは本文まで 5.3〜10.9 秒(標準のハーネスは 3.0〜4.6 秒)、画像 1 枚(T7)は 9.9 秒(標準は 6.0 秒)。目標を受けて手順を組む作りの分と、モデルの違いと推測する(1 回ずつの測定)。
  - 鍵なしの入口(トークン エンドポイント)は、403 ではなく **404「4100 ObjectNotFound」**(トークンは出なかった)。同じ環境の標準のハーネスのエージェント(DL)は、続けて試して 403。スキーマ名の形も標準と違ったので、このハーネスのエージェントはこの入口に載っていないと推測する(鍵なしで話しかけられないことは同じ)。
  - **それでも標準のハーネスを勧める**: 速い(CCP の「AI で下書き」は 6〜9 回呼ぶので、1 回の遅さが積もる)。Agents SDK・Power Automate からも呼べ、つなぎ方を後から替えられる。CCP の頼みは決まった形の答えを返すだけで、手順を組む重い仕事は要らない。選べるモデルが文書に揃っている。

### 15.8 流れで画像を渡す試し(2026-11-02 は通らず、2026-11-04 に通った)

画像の入力(`image`)を持つプロンプト(`CCP AI 出口の検証 画像`。モデルは GPT-5 chat)を作り、画像用の流れ(「HTTP 要求の受信時」→「プロンプトを実行する」→「応答」)から呼んだ。

- プロンプトの画面の「テスト」で写真を付けると、答えは返った(透かし編みのカーディガンを「カーディガン・レース編み」)。**プロンプトそのものは画像を読める。**
- 流れには、画像を `{"request": …, "image": {"$content-type": "image/jpeg", "$content": "<base64>"}}` の形で送り、「プロンプトを実行する」の Image の欄に入れる値を 6 通り試した。**どれも流れの中で失敗し、答えが返らなかった**(流れからの答えは 502「NoResponse」)。

| # | Image の欄 | 流れの中のエラー |
|---|---|---|
| 1 | `$content`(base64 の文字のまま) | 「Image url cannot be accessed」「unsupported image」(対応していない画像の形式) |
| 2 | `json(concat(…))`(`$content-type` と `$content` のファイルの形) | 「入力パラメーターがモデルに対して無効です」 |
| 3 | `dataUriToBinary(concat('data:', …))`(バイナリ) | 同上 |
| 4 | `concat('data:', …)`(データ URL の文字) | 失敗(エラーの文は控えていない) |
| 5 | `json(concat(…))`(`base64Encoded` と `mimeType` の組) | 失敗(エラーの文は控えていない) |
| 6 | `base64ToBinary(triggerBody()?['image']?['$content'])`(バイナリ) | 失敗(保存はできた) |

- プロンプトの画像の入力は「ドキュメント入力」という種類で、受け付ける形式は **PNG・JPG・JPEG・PDF だけ(WebP は受け付けない)**(プロンプトの画面の説明)。CCP は WebP の写真も受け付け、Direct Line も WebP を読めたので、AI Builder を使うなら、層で WebP を JPEG に変えてから渡す。今回の流れの試しは JPEG で行った。
- 流れの外(HTTP)から受けた画像を、プロンプトの画像の入力に渡す形は、文書にも見当たらず、見つけられなかった。流れの中で、ファイルの置き場(OneDrive・SharePoint など)から読んだ画像なら渡せる見込みはあるが、CCP の層から使うには、画像をいったんそこに置く段が増える(試していない)。
- プロンプトの画像の入力は 1 つの入力に 1 枚なので、T9(最大 8 枚)は、この形では入力を 8 つ持つプロンプトが要る。
- 2026-11-02 の時点の結果: 文の頼みは使えたが、画像は 6 通りでは渡せなかった。

#### 2026-11-04: 通った

1. **対照の試し**: 手動で動かす流れを作り、流れの中で OneDrive から読んだ写真(「ファイル コンテンツの取得」)を Image の欄に入れた。**答えが返った**。流れとプロンプトの組み合わせは、画像を扱える。
2. そのときの「プロンプトを実行する」の生の入力では、画像は `item/requestv2/image/base64Encoded` に **base64 の文 1 つ**だった(種類や `$content-type` の欄はない)。値の頭は `UklGR…`(WebP)。
3. **原因(ほぼ確か)**: Image の欄は「ファイルの中身」を受け取り、自分で base64 にする。HTTP で受けた base64 の文をそのまま入れると、その文がもう一度 base64 にされ、**2 重に包まれる**(JPEG なら頭が `/9j/4A…` ではなく `LzlqLzRB…` になる)ので、プロンプトは画像として読めない。上の 6 番(`base64ToBinary`)は、式が**文字のまま**欄に入っていて(T の印)、式として動いていなかった。
4. **直し方**: 流れの「HTTP 要求の受信時」の JSON に `imageBase64`(base64 の文)を足し、Image の欄で **fx(式)** を押して `base64ToBinary(triggerBody()?['imageBase64'])` を入れる。欄に紫の部品として入れば、式として動く。測るプログラムは `imageBase64` も送る。
5. 結果: T6・T7・T8・T10 は JSON・決まりともすべて ○、本文まで 3.9〜6.6 秒(10.1)。**WebP も読めた**(上の「WebP は受け付けない」は、プロンプトの画面のテストで写真を付けるときの話。流れから渡すなら変えなくてよい)。
6. 費用: 画像 1 枚の頼み(T10 の短い形)で、入力 1,727 トークン・Copilot のクレジット 3(流れの実行の答えの `costAsCopilotCredits`)。AI Builder のクレジットは 0。

#### 2026-11-04: 写真を何枚も渡す(T9)

   - プロンプトの入力の名前を変えたあと、流れの「プロンプトを実行する」に前の欄(`image`)の値が見えない形で残り、保存が「WorkflowOperationParametersExtraParameter」で断られた。箱でプロンプトを選び直すと直った。
2. **写真 2 枚(残りの 6 つの欄は `null`)は、「入力パラメーターがモデルに対して無効です」で断られた。** プロンプトの画像の入力は、空にできない(**確か**: 8 つすべてを埋めると通った)。
3. **写真 8 枚(すべての欄を埋める)は通った。** 8 枚ともアングルが写真のとおり。1 回目は 89 秒かかったが、続けて送ると 8.1・9.7 秒だった(1 回目は流れが温まっていなかったと推測)。picks に、渡していない番号(判断済みの画像)を `index: 8` と書く誤りが 1 回あった。
4. **枚数が足りないときは、層が空いた欄を小さな白い画像(64×64 の PNG)で埋め、頼みの文に「画像 N 以降は空の白い画像。無視する」と足すと通った**(測るプログラムの `--pad`)。2 枚で 6.7 秒、4 枚で 7.2 秒。白い画像は、答えの images にも picks にも出てこなかった。

- **ここまでの結果: AI Builder(方式 3)は、流れを窓口にすれば、文の頼みも画像の頼み(最大 8 枚)も使える。** 枚数の違いは、層が白い画像で埋めて吸収する(CCP の側は変えない)。8 枚を超えるときは、層が 8 枚ずつに分けて呼ぶ(試していない)。答えの `index` が渡した枚数の外を指していたら、層が消す。

## 16. 利用者から見て差が出ないために、層(と出口)で気をつけること

CCP の AI を Gemini から Copilot Studio(方式 1・Direct Line)に替えても、**CCP の画面を使う人から見て、何も変わらない**ようにするための注意。画面は変えず、違いは層(と CCP の出口)で吸収する。数字は 10.1 の記録から。Gemini の秒数は、まだ同じ頼みで測っていない(未確認)。

| 観点 | Gemini のとき(いまの CCP) | Copilot Studio(Direct Line)で分かったこと | 利用者から見た差 | 層(と出口)で気をつけること |

| 画像の渡し方 | 文の中の好きな所に画像を置ける(商品ページの画像の提案は「画像 0」の文と画像を交互に並べる) | 文 + 添付。添付の `data:` の URL は「InvalidUri」で断られ、upload の入口なら通る。複数枚は `file` を並べ、「添付の順が番号」と文で伝えると、3 枚で ○(T9) | なし(層が変換すれば) | 層が、CCP から受けた `parts`(文と画像)を「文 + 添付」に組み替える。画像の番号は添付の順にそろえ、文で伝える。画面は変えない |
