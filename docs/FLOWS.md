# 導線の棚卸し: 週のサイクルと、画面の入り口・移り方

業務の流れ(週のサイクル)の段階ごとに、**どこから入り、何をして、次にどこへ移るか**を、いまの画面とコードから書き出したもの。
メニュー・ツールバーを整理するときに、**プロセスに合わせた導線を壊さない**ための土台にする(2026-10-17、利用者の要望)。

- 最終更新: 2026-10-17(`main` の時点の画面とコード。英語の撮影用の画面と、`src/` を読んで確かめた。本番の画面では確かめていない)
- 週のサイクルと登場人物は [USER_STORIES.md](USER_STORIES.md) の 0 章、デザインの方針は [PRINCIPLES.md](PRINCIPLES.md)、ファイルの場所は [SOURCE_MAP.md](SOURCE_MAP.md)
- **この文書は、変える候補を挙げるだけで、画面はまだ変えていない。** 変えるかどうかは、利用者と 1 つずつ決める(6 章)

---

## 1. 整理するときの決まり(PRINCIPLES.md から)

導線を崩しやすい整理と、その理由。メニューを動かす前に、ここに照らす。

| 決まり | PRINCIPLES.md | 整理で気をつけること |
|---|---|---|
| 作業の拠点から動かずに作業する。上に重ねて、閉じれば元に戻る | 1-1・1-3 | 画面を移らせる形(別のページ・ハンバーガーの先の画面)にしない |
| 見ていた条件を引き継ぐ | 1-4 | 絞り込みの条件を、隠さない・切り替えで外さない |
| 使えないものは、消さずに選べないだけにする | 2-2 | 状態によって、ボタンを出したり消したりしない(位置がずれる) |
| 切り替え・操作・中身を見分けられるようにする | 2-3 | 切り替えは枠のかたまり、操作はメニューか区切りの右 |
| 毎日の作業と、管理・設定を分ける | 2-4 | 毎日の作業は表に出し、たまに使うものだけを ⚙ に入れる |
| 次の作業に、移りやすくする | 4-1 | 終えたら、次の候補が目の前にある状態にする |
| 手順を意識しなくても、手順どおりに進む | 4-2 | いまの段階でやることだけを目立たせる |

**ハンバーガーメニューにまとめない理由**: ハンバーガーは「機能の種類」で仕分ける形。CCP の画面は、週のサイクルの段階に合わせて置いているので、機能の種類で仕分け直すと、段階の間の移り方が 1 段奥に隠れる。いまのヘッダー(計画 / 結果・アラート・新規作成・⚙)は、2-4 のとおり、毎日の作業と管理・設定がすでに分かれている。

## 2. 画面の全体(いまの形)

```
ヘッダー: [計画 | 結果]  ……  アラート(件数)  新規作成  ⚙(テンプレートの管理・データと画像の書き出し・言語・自動の下書き)
絞り込み: 国・チャネル・種別・ステータス(計画と結果で共通)                         ◯ / ◯ 件
ツールバー: ‹ 期間(ミニカレンダー) › [月 | 週 | 一覧 | 比べる]  週の見方[商品 | 進み具合]  (計画)CSV で書き出す / (結果)データ ▾  凡例
中身: 計画の面 = 月のカレンダー / 週の表示(週の状態の帯・確認の一覧) / 一覧
      結果の面 = 月・週・一覧・比べる
      アラートの面 = 左に一覧、右に中身

上に重ねて開くもの:
  配信カード(全画面のフロート) = 左: 配信情報・すべてAIで下書き / 中: [コンテンツ生成 | やり取り] / プレビュー / 右: 商品情報(参照専用)
  詳しい結果(全画面のフロート)
```

## 3. 段階ごとの導線

段階の番号は、USER_STORIES.md の 0 章の週のサイクル(7. 配信する は CCP の外)。

### 段階 1. 前週の配信を振り返る

| | いまの形 |
|---|---|
| だれが | マーケティング担当者 |
| 入り口 | ヘッダーの「結果」→ 結果の面(月・週・一覧)。計画の面でも、配信カードに結果を重ねて見られる(`ResultPeek`) |
| すること | 開封率・クリック率・売上・前週比・前年比を見る。配信を押すと詳しい結果(リンクごとのクリックをプレビューに重ねる)。「比べる」で、条件で絞った配信を並べ、AI に見比べさせる |
| 次への移り方 | 詳しい結果の「制作の詳細」→ その配信カード。結果の面から「計画」に戻ると、見ていた期間・絞り込みのまま(1-4) |
| 気になる点 | 振り返りで気づいたことを、次の計画に残す場所が、配信ごとのメモ(学び)だけ。「前週」を開く近道はなく、期間を 1 つ戻して探す |

### 段階 2. 当週・翌週の配信を計画する

| | いまの形 |
|---|---|
| だれが | マーケティング担当者(国ごとのチーム) |
| 入り口 | 計画の面の月のカレンダー / 週の表示 / 一覧。ヘッダーの「新規作成」、カレンダーの日の「この日に新規作成」 |
| すること | 日・チャネル・種別の割り振りを見る。絞り込み(国・チャネル・種別・ステータス)で、自分のチームの分に絞る。締め切りが近いのに未着手の配信と、アラートのある配信に印 |
| 次への移り方 | 配信を押す → 配信カード(上に重ねる)。月 → 週は、ツールバーの [週] か、ミニカレンダーの週の印 |
| 気になる点 | 月のカレンダーから、その週の週表示へ直接移る近道がない(週の行を押しても移らない)。ミニカレンダーのボタンが、押せると分かりにくい(W13 で直す予定) |

### 段階 3. 配信ごとに、内容の下書きを作る

| | いまの形 |
|---|---|
| だれが | マーケティング担当者 |
| 入り口 | 配信カードを開く(新規なら、設定がオンのとき、開いたときに自動で下書き)。週の帯の「まとめて AI で下書き」(W14) |
| すること | 左の「すべてAIで下書き」、または中ペインの「コンテンツ生成」で ①テーマ → ②テンプレート → ③ヒーロー → ④セクション → ⑤制作指示、リンク先。AI チャットで、開いているタブの案を直す。上に「これまでの学び」、右に商品情報、プレビュー |
| 次への移り方 | 「保存」→ **配信カードが閉じて、カレンダーに戻る** |
| 気になる点 | 保存すると閉じるので、同じ週の次の配信を、カレンダーで探し直す(4-1 に照らすと弱い)。工程の番号(①〜⑤)と、左の「工程」の欄の両方で進み具合を見せている。中ペインのタブは、狭い幅では横にスクロールする |

### 段階 4. 週の計画を、関係者でレビューする

| | いまの形 |
|---|---|
| だれが | マーケティング担当者・レビュー参加者・MD |
| 入り口 | 計画の面の週の表示 → 週の状態の帯の「レビューに出す」。帯の下の「確認の一覧」(上限超えの商品・主力の漏れ・連続・未対応のコメント など) |
| すること | 確認の項目を押すと、該当する配信・商品が目立つ。週の見方「商品 / 進み具合」で見る観点を変える。配信カードを開き、「やり取り」→ コメントに指摘を残す。帯の「PDF」で週の資料 |
| 次への移り方 | 確認の項目 → 目立った配信を押す → 配信カード → 閉じると週の表示に戻る |
| 気になる点 | 確認の項目から、該当する配信を順に開いていく近道がない(1 本ずつ押して開き、閉じて、次を押す) |

### 段階 5. 修正して、確定する

| | いまの形 |
|---|---|
| だれが | マーケティング担当者・承認者 |
| 入り口 | 配信カードの下の「保存して承認」「差し戻す」。週の状態の帯の「まとめて承認」「週を確定」「確定を取り消す」 |
| すること | 1 本ずつ、または週まとめて承認する。差し戻しは理由が必須(コメントにも残る)。確定した週を変えるときは理由を残し、週をレビューに戻す(W3) |
| 次への移り方 | 承認・差し戻しの保存 → 配信カードが閉じて、週の表示に戻る。帯の「履歴」で、承認の履歴 |
| 気になる点 | 承認の対象の配信(検討中)だけを、順に見ていく近道がない(段階 4 と同じ)。承認者が「自分が見るべき週・配信」を知る入り口がない(通知はしない、と決めている) |

### 段階 6. 制作担当に引き継ぐ

| | いまの形 |
|---|---|
| だれが | マーケティング担当者 → 制作担当 |
| 入り口 | 配信カードの「やり取り」→ 引き継ぎ(制作の担当・「制作に知らせる」)、制作からの質問と返信、タスク。左の配信情報にも、制作の担当・締め切り・引き継ぎ済み |
| すること | 引き継ぐ。制作からの質問に答える。質問から AI でタスクの案を出し、採用したものを管理する |
| 次への移り方 | 「やり取り」の数(未対応の合計)で、残りに気づく。週の表示の「進み具合」で、引き継ぎ・タスクの状態を一覧で見る |
| 気になる点 | **制作担当の入り口がない**: 自分が担当の配信・未回答の質問・未完了のタスクを、配信をまたいで一覧にする画面がない。絞り込みに「担当」がない(アラートの条件にはある)。制作の担当・締め切り・引き継ぎ済みを、左と「やり取り」の 2 か所で入力できる |

### 段階 8. 結果を振り返り、次の計画に生かす

| | いまの形 |
|---|---|
| だれが | マーケティング担当者 |
| 入り口 | 結果の面。配信カードの「結果を見る」(配信日が過ぎたもの) |
| すること | 詳しい結果・比べる・AI の振り返り。学びのメモを残す |
| 次への移り方 | 同じテンプレート・同じテーマの種類の配信カードを開くと、「これまでの学び」として出る。AI の下書きにも渡る |
| 気になる点 | 段階 1 と同じ(気づきを、配信ごと以外に残す場所がない) |

### 段階をまたぐもの: アラート

| | いまの形 |
|---|---|
| 入り口 | ヘッダーの「アラート(件数)」。カレンダー・週の配信の印。配信カードの上の帯 |
| すること | 在庫切れ・在庫僅少・MD 方針の変更・日程の変更。差し替え・延期・取りやめ、対応済みにする |
| 次への移り方 | アラートの画面で「配信カードを開く」→ 問題の商品を選んだ状態で開く → 閉じるとアラートの画面に戻る。対応済みにすると、残りのいちばん上が選ばれる(4-1 のお手本) |
| 気になる点 | 大きな問題はない |

## 4. 面・ツールバーの部品と、使う段階

| 部品 | 場所 | 使う段階 | メモ |
|---|---|---|---|
| [計画 \| 結果] | ヘッダー | 計画 2〜6 / 結果 1・8 | 段階の大きな切り替え。いまのままがよい |
| アラート | ヘッダー | すべて | 件数つき。いまのままがよい |
| 新規作成 | ヘッダー | 2 | いまのままがよい |
| ⚙ | ヘッダー | 管理・設定 | テンプレートの管理・データの書き出し・言語・自動の下書き(2-4) |
| 絞り込み(国・チャネル・種別・ステータス) | 2 行目 | すべて | 計画と結果で共通、切り替えても引き継ぐ。**「担当」がない** |
| ‹ 期間 › ・ミニカレンダー | ツールバー | すべて | W13 で、押せると分かるように直す予定 |
| [月 \| 週 \| 一覧 \| 比べる] | ツールバー | 月・一覧 = 2 / 週 = 2・4・5・6 / 比べる = 1・8 | 「比べる」は計画の面で薄く出す(2-2) |
| 週の見方 [商品 \| 進み具合] | ツールバー | 4(商品)・6(進み具合) | 週の表示以外で薄く出す(2-2) |
| CSV で書き出す / データ ▾ | ツールバー | 計画 = 共有 / 結果 = 取り込み・書き出し | **計画はボタン、結果はメニューで、形がそろっていない**(2-3・8-3) |
| 凡例(状態の色) | ツールバーの右 | 2・4・5 | 毎回見るものではないが、場所を取っている |
| 週の状態の帯・確認の一覧 | 週の表示 | 4・5 | レビュー・確定の拠点 |

## 6. 変える候補(未決定。利用者と 1 つずつ決める)

導線を壊さない(画面を移らせない・ボタンを消さない・位置を変えない)ものだけを挙げた。

| 候補 | 気になる点 | 内容 | 導線への影響 |
|---|---|---|---|
| C-1 ✅ | F1・F2 | (2026-10-17 に入れた。X9)配信カードに「保存して次へ」(同じ週の、次の配信を開く)。週の表示で確認の項目を選んでいるときは、その項目に該当する次の配信へ | 段階 3〜5 の移り方が短くなる。いまの「保存」(閉じる)は残す |

| C-3 | F4 | 制作の担当・締め切り・引き継ぎ済みの入力を、1 か所にする(左は表示だけ、など) | 入力の場所が 1 つになる |

| C-5 | F6 | 計画の「CSV で書き出す」を、結果と同じ「データ ▾」のメニューにする | ツールバーの同じ位置に、同じ形の部品 |
| C-6 | F7 | 凡例を小さくする(色の点だけにして、マウスを重ねると名前) | 場所が空く。位置は変えない |
| C-7 | F8 | 週ごとの振り返りのメモ(週の状態の帯に置く)。結果の面に「前週」の近道 | 機能の追加。バックログの振り返り(6 章)と合わせて決める |
