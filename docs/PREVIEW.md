# 見本の画面(作りかけのブランチを URL で開く)

画面の見た目・動きを変えたら、`main` に入れる前に、**作業のブランチを push するだけで、そのブランチの見本の画面が URL で開ける**。
写真の代わりに、利用者やチームのメンバーに実際に触ってもらい、OK をもらってから `main` に入れる(2026-10-27 から、この進め方)。
仕組みの細かい所(サービス・置き場所・権限)は [GCP.md](GCP.md) の「見本の画面」。

## 1. 見本を出す手順

1. **`main` から作業のブランチを切る。** 見本の仕組みが入った後の `main` から切ること。それより古いブランチは、見本を作れない。迷ったら `git pull --rebase origin main` で、今の `main` に載せ直す。
   ```bash
   git switch -c claude/ui9-sample-change
   ```
2. **変更をコミットして、ブランチを push する。**
   ```bash
   git push -u origin claude/ui9-sample-change
   ```
   ブランチの名前は自由。`main` に入れる必要はない。
3. **2 分ほど待つ。** push をきっかけに、見本のビルドが自動で動く。デモのビルドを作って置くだけで、本番には何もしない。
4. **URL を開く。** 見本のサービスの URL の後ろに、`/b/<ブランチ名を URL の形にしたもの>/` を付ける。
   ```
   https://<見本のサービスの URL>/b/claude-ui9-sample-change/
   ```
   - 見本のサービスの URL は、このリポジトリには書かない(公開のリポジトリのため)。チームの Google Chat で共有しているもの、または連絡係に聞く。
   - パスワードは、本番の画面と同じ(ユーザー名は何でもよい)。ブラウザが一度覚えれば、次からは聞かれない。
   - 見本のサービスの URL だけを開くと、見本のあるブランチの一覧が出る(押すと開く)。

### ブランチ名を URL の形にする決まり

英大文字は小文字に、英小文字・数字以外(`/`・`_`・`.` など)は `-` に置き換わる。`-` が続けば 1 つにまとまり、最大 60 文字。

| ブランチ | 見本のパス |
|---|---|
| `main` | `/b/main/` |
| `claude/ui2-x81-9` | `/b/claude-ui2-x81-9/` |
| `ui3-ai-draft-on-click` | `/b/ui3-ai-draft-on-click/` |
| `Feature/New_Header` | `/b/feature-new-header/` |

### 開いたら「not found」と出たとき

- **まだできていないことが多い。** push から 2 分ほどかかる。少し待って、開き直す。
- できたかどうかは、見本のサービスの URL(ブランチの一覧)を開いて、自分のブランチが並んでいるかで分かる。GCP を見られる人は、次でも確かめられる。
  ```bash
  gcloud builds list --limit=5 --format="value(status,substitutions.BRANCH_NAME)"
  ```
  `SUCCESS` なら、できている。`FAILURE` なら、ビルドで止まっている(手元で `npm run verify` を通してから push し直す)。
- パスの形(上の表)が合っているか確かめる。

## 2. 見本で分かること・分からないこと

- **データは、すべてデモのもの**(`src/mock`。撮影・デモ用のビルド `vite.mock.config.ts` と同じ)。本物のデータ・鍵は入っていない。
- **AI は作り物の答え。** 案の中身・文の出来は、見本では確かめられない。
- **保存しても、サーバーには残らない。** 画面の中だけで動く。開き直すと元に戻る。
- **見本で確かめるもの**: 見た目、並び、ボタンの場所、押したときの動き。
- **本番で確かめるもの**: データの保存、AI の中身、サーバーの動き(こちらは `main` に入れて反映してから確かめる)。

## 3. 進め方の決まり(2026-10-27 利用者と決めた)

| 変えたもの | 進め方 |
|---|---|
| 見た目・画面の動き | 作業のブランチを push → 見本の URL を利用者に送る → OK をもらってから `main` に入れる |
| データ・保存・AI・サーバー | `main` に入れて反映し、本番で確かめる |
| 崩れの直し | そのまま `main` に入れてよい |

- 見本の URL を送るときは、Chrome に貼れるよう、コードの枠(```)に 1 行ずつ入れる。
- 送る前に、見本ができたこと(上の一覧か `gcloud builds list` で `SUCCESS`)を確かめる。開いたら not found、をなくすため。
- OK をもらって `main` に入れたら、作業のブランチは消してよい。

## 4. 片付け

- `main` 以外のブランチの見本は、**最後の push から 14 日で自動で消える**。ブランチを消しても、見本は 14 日は残る。
- 同じブランチに push し直すと、見本は新しい中身に置き換わる(開き直すと新しくなる)。
