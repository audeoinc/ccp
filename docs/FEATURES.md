# 機能説明

「Campaign Contents Planner(CCP)」の機能の説明。
画面の用語は、実際の画面の表記(日本語 / English)に合わせてある。**「未実装・制限」の章に書いたことは、できないこと。**
機能ごとの「なぜその機能があるか」は、[FEATURE_REASONS.md](FEATURE_REASONS.md)(機能の理由の台帳)を参照。

---

## 1. 一言で

メール・アプリの**配信コンテンツ**(テーマ、メイン画像、ヘッドライン・コピー、セクションごとの商品、制作指示)を、**AI の提案を選びながら**企画し、**週ごとにレビュー・承認**し、送ったあとの**結果を振り返る**アプリ。
配信前には、在庫切れや方針の変更などの**アラート**で、事故を防ぐ。US チームと JP チームが、日本語・英語のどちらでも使える。

## 2. 解決する課題と、価値

| 課題 | このアプリでの解決 |
|---|---|
| 企画の素案づくりに時間がかかる | 「すべてAIで下書き」で、テーマから制作指示まで一度に下書きを作る。週の表示で、週の枠を作って配信名と種類を入れ、まとめて AI で中身を作ることもできる |
| 商品の選定が属人的 | 在庫・売上トレンド・評価・季節・天候などを踏まえた AI の選定と、**その理由**を表示する |
| 国ごとに、商品・言語が違う | 配信カードの「国」(US / JP)に合わせて、商品・画像・コピーの言語を使い分ける |
| デザイナーが、商品情報を探し回る | 配信カードの右の商品の一覧と商品のフロートで、掲載商品の情報を見て、売上・在庫の推移や MD の方針も見られる |
| メールの構成を、毎回、作り直す | テンプレート(構成の型)を選ぶ。自分でも作って、チームで共有できる |
| AI の案が、気に入らない | 部品ごとに「AI に頼む」「指示して直す」で条件を足して、案を出し直す(「この商品を必ず入れて」など)。押して試し、確定で入れ替える |
| 週の計画のレビューが、資料づくりと確認で重い | 週の表示で 1 週間をまとめて見て、確認の一覧(同じ商品の回数・主力の漏れなど)・コメント・承認までを同じ画面で行う。資料は PDF で書き出す |
| 配信のあとで、在庫切れや方針の変更に気づく | 配信前の在庫の見込みと、方針・日程の変更を**アラート**で知らせ、差し替え・延期・取りやめまでその場で対応する |
| 振り返りが、次の企画に生きない | 結果をカレンダー・一覧・ヒートマップで振り返り、「次に生かすメモ」を、次の配信カードと AI の案に渡す |

**人が決める、AI は提案する**、という立場。AI の案は、**採用するまで反映されない**(一部は、反映して「元に戻す」で戻せる)。

## 3. 想定する利用者

- **企画担当(販促・CRM・EC)**: 配信を企画し、AI の案を選んで、内容を決める。週の計画をレビューに出す。
- **レビュー・承認する人**: 週の計画を見て、コメントを残し、承認・差し戻し・週の確定をする。
- **デザイナー・制作担当**: 決まった内容(ヘッドライン、コピー、商品、制作指示、リンク先)と商品情報を見て、制作する。質問を返す。
- **MD(商品担当)**: 商品の販売方針・販促計画を、AI の選定と制作の判断に使えるようにする(データとして登録されている)。
- 国: **US チーム / JP チーム**。

## 4. 画面の流れ

### 4.1 ヘッダーと、共通のツールバー

- **いまどの面にいるか**: 面ごとの色(計画 = 藍、制作 = 橙、結果 = 緑。メールとアプリの札の青・ベリーとは重ねない)。ヘッダーのすぐ下に、面の色の細い帯と、ロゴ風の面の名前(PLAN / PRODUCTION / RESULTS)と一言の説明。面の切り替えで選んでいる側も、面の色。配信カード・制作のページ・詳しい結果の題名の左に、同じ色の面の札。

- **リンクで画面を伝える**: 面・見せ方・期間・国と、開いているフロート(配信カード・詳しい結果・アラートの商品・制作のページ)を、URL に持たせる。フロートの右上の「**リンクをコピー**」で写して送ると、相手も同じ画面で開ける。ブラウザの「戻る」でフロートが閉じ、再読み込みしても開いたまま。リンクの国は、そのときだけ合わせる(ふだんの国の設定は変えない)。リンクの配信が見つからなければ、知らせていつもの画面で開く。

- ヘッダー: アプリ名、**国**(「すべての国 / US / JP」。どの国の仕事をしているか。画面のすべて(計画・結果・週の帯・アラート・依頼の件数・新規作成の既定の国。「すべての国」のときは、その人が新規作成・一括作成で最後に選んだ国)に効き、人ごと(ブラウザごと)に覚える。全体を見る人は「すべての国」)、「**アラート**」(未対応の件数。在庫切れがあれば赤)、「**依頼**」(自分宛ての承認の依頼)、「**＋ 新規作成 ▾**」(本体は「**新しいキャンペーン**」の窓で、キャンペーンと最初の配信カード 1 枚を作る(4.3.2)。▾ から「**まとめて作る**」(作業画面。5.1.1)と「**この週の枠を作る**」(週の表示の上で作る、これまでの形。5.1.2))、「**リクエスト**」(開発へのリクエストの一覧。5.18。横の目の印でピンを出す / 隠す)、「**聞く**」(？ の印。使い方を AI に聞く。5.19)、「**あなた**」(履歴・依頼・承認に残す人。ユーザーが登録されていれば選んで切り替え(デモ)、「**ログアウト**」で最初の「だれでログインしますか?」に戻る。1 人も登録されていなければ名前の入力)、**⚙**(**設定**の画面を開く。自分の設定・国・全社・開発へのリクエスト・開発・管理。5.17)。
- ツールバー(計画・制作・結果で共通。切り替えても、期間・見せ方・絞り込みはそのまま):
  - 作業の段: ヘッダー(システム全体)のすぐ下の段の左端に **[計画 | 制作 | 結果]** の切り替え、その右に絞り込み。
  - 絞り込み: 作業の段に、**チャネル / 種類 / ステータス / 担当** の札を横に並べる(ステータスは計画の面だけ。国はヘッダーの国)。選んでいない札は名前だけ(「チャネル ▾」)、選ぶと「チャネル: メール ▾」と中身を出して色が付く。絞っているときだけ「クリア」。**種類**はテーマの種類(値下げ / 期間限定価格 / セール / 新作 / コラボ / 会員向け / 季節の特集 / 再入荷 / その他。決まっていない配信は、言葉から推し量った種類で見る)。担当のいちばん上は「**自分**」(右上でログインしている人。切り替えると追いかける)。担当は、企画・制作の担当か、質問・タスクの宛先。
  - 期間: ‹ › で移動。期間の文字(例: 2026年10月。カレンダーのアイコンと ▾ の付いたボタン)を押すと**ミニカレンダー**が開き、月・週・日へ移れる。
  - 見せ方: **[月 | 週 | 一覧 | 商品別]**。結果の面では、さらに **比べる / 効果 / 学び**(計画・制作の面では出さない。結果の面からほかの面へ移ると、月に戻る)。商品別は 4.5.1。計画の面の週のときは、「週」のボタンの下に「週の見方」の小さなタブ(**商品 / 進み具合 / 時刻 / 前週と比べる**。結果の面では出さない)。「**前週と比べる**」は 4.2。「**時刻**」は、横 = 曜日・縦 = 時刻の格子に配信を配信時刻の位置で置き、違う日で同じ時刻の配信に点線を引き、左の時刻の列に「10:00 ×4」の札を出す(マウスを重ねると「10:00 の配信が 4 日あります」)。カードにマウスを重ねるとプレビュー。カードをつかんで別の日・時刻へ動かせる(15 分きざみ。「元に戻す」あり。承認済み・確定した週・取りやめの配信は鍵の印で、配信カードで変える)。キャンペーン(4.3.2)に入った配信は「キャンペーン名 › メール」の札で、同じキャンペーンは左の線が同じ色(乗せると、きょうだいの配信も光る)。
  - ツールバーの右端に「**この画面 ▾**」: いま見ているものへの操作をまとめたメニュー(どの面・見せ方でも同じ位置)。計画: この週の枠を作る(週の表示)・この月の空いている週から、枠を作る(月・一覧。配信がいちばん少ない確定前の週に移って始める)・配信を CSV で書き出す(表示中の月・週)・週の資料を PDF で書き出す・この週の承認の履歴(週の表示のとき)・表示する列(一覧のとき)。結果: 結果の CSV の書き出し・結果の取り込み・取り込みの見本・AI でテーマの種類を分ける。
- 国: US / JP。チャネル: **メール / アプリ**。種類: テーマの種類(上の絞り込みと同じ)。
- ステータス(4段階・色分け): **未起案 → 検討中 → 承認済み → 確定**。

- **表示の大きさ**(右上の「あなた」のメニュー): とても小さめ(70%)/ 小さめ(80%)/ やや小さめ(90%)/ 標準 / 大きめ(110%)。文字も部品もまとめて縮める・広げる(ノート PC など、画面が狭いときに作業の領域を広げる)。このブラウザで覚える。
- **どの画面にも共通の操作**:
  - **フロート**(配信カード・制作のページ・商品のフロート・設定など)は、端・角をつかんで大きさを変えられ(種類ごとに覚える)、題の行をつかんで動かせる(位置は覚えず、開くたびにいつもの場所。題の行を 2 回押すと戻る)。小さい確かめの窓(複製・削除など)は固定。
  - **ペイン**の境目をつかんで幅を変えられる(覚える)。**複数行の入力欄**は、下の端をつかんで高さを変えられる(欄の種類ごとに覚える)。
  - **右クリックのメニュー**: プレビューの部品(この部品を直す・AI に頼む)・商品の枠(入れ替える・商品ページを開く・外す)・メイン画像・ピン・週 / 月 / 一覧の配信(開く・複製…・制作のページを開く・結果を見る)・素材の行などに、その場の操作を出す。どのメニューにも、最後に「**ここについて聞く**」(5.19)と「**開発に伝える**」(5.18)。ブラウザのいつものメニューは、Shift + 右クリック・入力欄の上・文字を選んでいるとき。
  - **項目の説明**は、見出し・ラベルの横の **ⓘ** を押すと出る。慣れたら邪魔な案内(ヒント)は × で閉じると次から出ない(設定の「自分の設定」の「ヒントをもう一度出す」で戻せる)。
  - 値に付くラベル(「テーマ」「配信日時」など)は小さく薄く、値を目立たせる。空の値(未設定・—)は薄く出す。
  - **検索の欄**は、虫眼鏡の付いた欄と、右に当たった件数。絞り込みの札は「絞り込み」の見出しを付けて、検索の欄と分ける。
### 4.2 計画の面

- **月**: カレンダーに配信が並ぶ。1 行目はチャネルの印と名前、2 行目は時刻と国。**ステータスの色**(左の線と薄い色)で状態が分かる。メールとアプリは、名前の前の**塗りつぶしの印**(メール = 青の地に白い封筒、アプリ = ベリー色の地に白いスマートフォン)で見分ける。
  - **キャンペーン**(4.3.2)に入った配信は、マスに**キャンペーン 1 つ**としてまとめて出す(中に、子の配信のチャネルの印と状態の点、AB テストのある配信には小さく「AB」。箱の色は、子のいちばん遅れている状態)。押すと、いちばん早い子の配信カードが開く。
  - 印: アラートのある配信、配信日が近いのに未着手の配信、取りやめた配信(取り消し線で薄く)。
  - 各週の先頭(日曜日)の「**週 ›**」を押すと、その週の週表示に移る(結果の面でも同じ)。
  - 上に「**月の要約の帯**」(見るだけ): この月の配信の状態ごとの件数(未起案 › 承認待ち › 承認済み n / 全体)と「確定した週 n / n」。「確定した週」を押すと、確定していない最初の週の週表示へ。一覧の表示にも同じ帯。
  - **日付のマスを押すと、その日の 10:00 を配信日時にして、新規作成**が開く(マウスを乗せると「＋」が出る)。絞り込み中の国・チャネル・種類も最初から入る。
- **週**: 1 週間の配信を、日ごとに、縮小プレビューつきで並べる(箱の上の帯が、メール = 青、アプリ = ベリー色の塗りつぶしに白抜きの文字・アイコン)。上に、週の状態(と状態ごとの件数)とレビュー・確定の操作を並べた**週の帯**(5.12)。
  - 週の見方「**商品**」は、載せた商品の画像(マウスを重ねると、同じ商品が光る。その週に 2 本以上の配信に載せている商品には、右上に「×2」「×3」の**掲載回数**。数えるのは絞り込みに関係なく、その週のすべての配信(B・C 案も数え、取りやめは除く)。色は、週の上限より下 = 灰・ちょうど上限 = 黄・超え = 赤)、「**進み具合**」は、工程の進み具合、「**時刻**」は曜日 × 時刻の格子(4.1)を出す。
  - 週の見方「**前週と比べる**」: 当週と比べる週(既定は前週。‹ › でずらす)を、日〜土の 7 列で上下に、縮小のプレビューで並べる。下の「重なり」に、両方の週に出た商品・メイン画像と、テーマの種類ごとの数。欄に重ねると、使っている配信が上下で光り、押すと配信カードが開く(差し替えは、そこから)。
- **一覧**: 配信を表で並べる。左にサムネイル(マウスを重ねるとプレビュー)。列見出しで並べ替え、表示する列を選べる。**CSV で書き出す**。
- **週・月は、地の部分をつかんで横に引くと、前後の週・月に移る**(トラックパッドの横スワイプでも。右に引くと前、左に引くと次。配信の箱やボタンの上から始めたときは動かない。結果の面の週・月も同じ)。
- どの見せ方でも、配信を押すと、**配信カード**が開く。

### 4.3 配信カードの編集画面(フロート)

配信カードは、1 つの形だけ(2026-10-28 に、以前の「詳しい配信カード」(5 つのペインと 6 つの工程のタブ・AI チャット)と、「シンプル | 詳しい」の切り替えをなくした。以前のリンクで開いても、いまの形で開く)。**プレビューの部品を押して直す**形で、並びは「**左のバー + 開くパネル | プレビュー | 選んだ部品のペイン | 商品の一覧**」(くわしくは 4.3.1)。ペインの境目は、つかんで幅を変えられる(覚える)。

- **題の行**(2026-10-28 から 1 行に詰めた。プレビューを広く見せるため): **チャネルの札**(メール = 青の封筒、アプリ = ベリー色のスマートフォン。週の表示の配信の帯と同じ色。開いた瞬間に、どちらの配信かが分かる)・配信名・日時・**承認の札**と保存の様子・**PLAN | PRODUCTION | RESULTS** のタブ。題の行の印で、この配信カードを開く**リンクをコピー**できる。キャンペーンに入った配信は、その上にキャンペーンの帯(4.3.2)。
- **「⋯」のメニュー**: **すべて AI で下書き**(5.1)・**保存して次へ**・**結果を見る**(送ったあとの配信)・**複製…**・**変更の履歴…**・取りやめ・削除(5.16)。**変更の履歴**は、配信カードの中身の項目(配信名・件名・プリヘッダー・テーマ・見出し・コピー・セクションの見出しとコピー・制作指示・メイン画像・テンプレート・国・チャネル・通知・リンク・制作の担当と締め切り など)が、いつ・だれに・何から何に変わったかを、1 回の保存ごとにまとめて新しい順に出す(ステータスの変化・差し替えの理由も同じ並び。長い文は「全文を見る」)。どこから保存しても残る。左のバーの「変更」でも開く。複製は、配信名と配信日時(初めの値は 1 週間あとの同じ曜日・時刻。確定した週は飛ばす)を決めて、中身・テンプレートの版・載せた商品・AB テストの案を写した新しい配信カードを作り、そのまま開く。承認・制作への引き継ぎ・素材は写さず、確定した週には作れない(週をレビューに戻してから)。
- **種類(Type)**(配信の情報): テーマの種類(値下げ / 期間限定価格 / セール / 新作 / コラボ / 会員向け / 季節の特集 / 再入荷 / その他)。これまでの種別(販促 / CRM / EC)はやめた(データは残す)。「この配信に使う学び」の種類は見るだけ。種類が決まっていない配信は、設定の「開発・管理」→「取り込み・書き出し」の「種類が未設定の配信を、AI で分ける」でまとめて分けられる。
- **AB テスト**(題の行の下の「**AB テストの案を足す**」。キャンペーンの配信は、キャンペーンの帯の ＋ のメニュー): 1 つの配信の中に、**A・B・C の 3 案まで**を持つ。A はいまの配信そのもの、B・C は A の写しから始め、**比べる要素だけ**を案ごとに変える(それ以外のテーマ・リンク先・時刻などは全案で共通)。**案を切り替える**(案のタブ)と、プレビュー・部品のペイン・商品の一覧がその案になる。案の段の「⋯」の「**テストの設定**」で、**使い方**(AB テスト(全案を送る)/ 案から選ぶ(1 案だけ送る))・**判定の指標**(クリック率・受信者あたりの売上・注文率・開封率。既定はクリック率)・**送り方**(一部に送り、勝った案を残りに / 全員を均等に分ける。テストに回す割合と、勝ち負けを決めるまでの時間)・**仮説**を決める。案を足すときに「AI で別の案を作る」で、A 案と違う切り口のメイン画像・商品を AI が選ぶ(仮説があれば、それを確かめられる案に)。「**並べて比べる**」で、案のプレビューを横に並べて見られる。AB テストの配信には、月・週・一覧・時刻の格子で「**A/B**」「**A/B/C**」の印が付く。週の上限(同じ商品を週に何回載せたか)は、B・C 案の商品も数える。承認は全案まとめて 1 回。制作の依頼には、全案の中身とテストの設定がそのまま渡る(制作のページの左の「AB テスト」)。実際に受信者を分けて送るのは、配信システム。案の段の細かい操作は 4.3.1。
- **案から選ぶ**(テストの設定の使い方で「案から選ぶ(1 案だけ送る)」): AB テストと同じく A・B・C の 3 案までを作るが、**配信するのは決めた 1 案だけ**。案ごとに、メイン画像・商品・文言(ヘッドライン・コピー・セクションの見出しとコピー・通知の文)のすべてを変えられる。「**B 案に決める**」で、誰でも決められる(保存で確定)。決めると、その案が配信の中身になり、ほかの案は「**配信しなかった案**」として中身ごと残る(「B 案に決めた · 並べて見る」で見返せる。配信のメモにも残る)。月・週・一覧の印は、決める前は「A/B?」、決めたあとは「B 案」。

- **この配信のアラート**・**この配信に使う学び**は、左のバーの「アラート」「学び」(4.3.1)。アラートの問題の商品を押すと、プレビューで目立ち、そのまま「このアラートへの対応」が開く。
- **保存**: 自動で保存する(4.3.1)。「⋯」の「保存して次へ」は、保存したあと、閉じずに次の配信を開く。週の表示で確認の一覧の項目を選んでいれば、その項目の配信の中で、それ以外は同じ週の中で、配信日時の順。次がないときは、押せないだけ。続けて開くとき(同じキャンペーンのきょうだいの配信カードへの切り替え・保存して次へ)は、窓の出てくる動きを付けない(画面がちらつかないように。2026-10-28)。
- **ほかの人が先に保存していたら**: 保存の前に、開いたあとにほかの人が同じ配信を保存していないかを確かめ、保存されていれば黙って上書きせず「**上書きする**」「**閉じて読み直す**」を聞く(上の帯)。

### 4.3.2 キャンペーン(配信カードの親)

- **キャンペーン › 配信カード › AB の案** の 3 段。1 つのキャンペーンの中に、同じ国・同じ配信日の、メールとアプリの配信カードを入れる(時刻はカードごと。同じチャネルが 2 枚でもよい。カード 1 枚だけのキャンペーンもある)。キャンペーンは名前・国・テーマ(と種類)・目的を持ち、期間・状態は持たない(状態は、子のいちばん遅れているもの)。
- **作る**: ヘッダーの「新規作成」→「**新しいキャンペーン**」の窓(キャンペーン名・国・配信日時・チャネル・目的)→「作って開く」で、キャンペーンと最初の配信カード 1 枚を作って開く。確定した週の日には作れない。
- **配信カードの名前**は「キャンペーン名 + チャネル」(例「秋の新作 メール」)で、表示のたびに作る(画面の言語に合わせる)。
- **キャンペーンの帯**(配信カードのいちばん上。2026-10-28 から 1 行): キャンペーン(名前・配信日・国)と、配信カードのタブ(チャネル・時刻・状態。押すと切り替わる)、＋ のメニュー(「配信カードを足す」と、AB テストをしていなければ「AB テストの案を足す」)、右の端に「**まとめて承認**」。テーマ・目的は、名前にマウスを乗せるか、左の ∨ で開くと出る。AB テストをしているときだけ、下に案の段が出る。キャンペーンは一度読んだものを覚えて先に出すので、きょうだいの配信カードへ切り替えても、帯が消えて上の高さが変わることはない。
- **まとめて承認**: 子の配信の承認をまとめて依頼する(「承認を依頼する(n)」)・自分の番の分をまとめて承認する(「承認する(n)」)。送る前の確かめに通らないカードがあれば名前を示す(警告のまま依頼したものは「警告あり」)。既定の承認者がいない配信は飛ばし、カードから依頼する。カードごとの承認も、これまでどおり。
- **配信カードを足す**: 帯の「＋ 配信カードを足す」→ チャネルと時刻を選ぶ(国・配信日・テーマはキャンペーンと同じ)。「『○○ アプリ』の中身を写す」(2 枚以上なら「同じキャンペーンの配信カードの中身を写す」と写す元)で、きょうだいのテーマ・コピー・商品・AB の案を写せる(チャネルが違えばテンプレートは写さない)。メールとアプリのどちらからでも足せる。
- 月のカレンダーはキャンペーンの単位(4.2)、週の「時刻」の格子はカードの単位で、同じキャンペーンを同じ色の線でつなぐ(4.1)。

### 4.4 結果の面

- 計画の面と同じ見せ方(**月 / 週 / 一覧 / 商品別**)と、結果の面だけの **比べる**で、送った配信の結果を見る(5.14。商品別は 4.5.1)。見せ方「**効果**」で、配信が売上をどれだけ増やしたかと、AI に渡した学びが効いているかを見る(5.14.1)。見せ方「**学び**」で、学びをカードで並べる(5.14.2)。
- 配信を押すと、**詳しい結果**が上に重なって開く。
- 月・一覧の上に「**この月**」の要約の帯(配信の数と結果のある数・売上・前月比・前年比・開封率・クリック率。国が混ざるときは、金額と増減を通貨ごとに)。チャネルは、計画の面と同じ塗りつぶしの札(週の箱・一覧の列・詳しい結果の題名の左・比べるの列)。

### 4.5 アラートのフロート

- ヘッダーの「アラート」から、いまの画面の上に重ねて開く。左にアラートの一覧、右に影響を受ける配信と対応の操作(5.15)。

### 4.5.1 商品別(見せ方)

- 見せ方の「**商品別**」。商品を軸に、**自由な期間**(開始〜終了。直近 4 週・直近 12 週・前後 4 週・これから 4 週の近道)の中で、どの配信に何回載せたかと、その結果・売上・外部広告を並べる。計画の面・結果の面のどちらからも使える。
- 粒度は **商品(SPU)/ カテゴリ**(カテゴリの階層の上 2 段。国ごと)。
- 列: 掲載の回数・メール / アプリ・うち予定・最後の掲載・クリック・CTR・**配信経由の売上**(配信の結果)・**期間の売上(全体)**(週ごとの実績)・**外部広告**の日数・費用・費用対効果。
- 印: 週の上限超え、外部広告と重複(7 日以上出稿していて、配信でも 3 回以上)、外部で好調・未掲載(費用対効果 3 倍以上なのに、配信に載せていない)、CTR が低い(2 回以上載せて 1% 未満)。外部に出稿している商品を、配信でも推すべきかを決める材料にする。
- 行を押すと、期間の中の並び(点 = 配信、帯 = 外部広告の出稿)と、載せた配信の一覧(押すと開く)。
- 外部広告のデータは、いまは見本(設定の「開発・管理」→「見本のデータ」の「外部広告の見本を作る」で作り直せる)。本物は、あとで取り込む。

### 4.6 制作の面と、制作のページ

- 面の切り替え **[計画 | 制作 | 結果]** の「制作」。計画・結果と同じカレンダー(配信日)の月・週・一覧で、箱の色は制作の状態、2 行目に状態と締め切り(近い・過ぎたものに印)。週の「時刻」の見方はない。
- **当面、承認の前でも制作に進める**: いまは、承認を受ける前の配信でも、段階の帯の PRODUCTION から制作のページを開き、「この内容で依頼する」で依頼できる(画面を見せて回る段階で、承認の手順が先にあると見せにくいため)。実際の運用で使い始めるときに、承認済みからだけに戻すかもしれない(戻すと、承認の前の配信は制作の面で薄く出て、制作のページは開けない)。案から選ぶ配信は、これまでどおり 1 案に決めるまで依頼できない。
- **制作のシンプルな画面**(X86。2026-10-28 から、箱・PRODUCTION のタブから開くと、まずこちら): 配信カードのシンプルと同じ形。左に企画の見本のプレビュー(部品を押せる。スマホ / PC・AB テストの案の切り替え)、右のペインは、何も選んでいないときは **渡されたもの**(制作の担当・締め切り・制作指示・テキストと商品とリンク先のまとめてコピー・計測の対応表・企画の見本の HTML のコピー / .html で保存・参考の素材)、部品を押すと **その部品の材料**(文・画像の URL・商品の名前 / コード / 価格 / 商品ページの URL・リンク先と utm_content。どれも 1 押しでコピー)。いまは開く・読む・コピーまで(直す・工程のボタン・やり取り・ピンは、下の詳しい制作のページで)。… のメニューの「詳しい制作のページで開く」と、詳しいほうの「シンプルで開く」で切り替える(人ごとに覚える)。配信カードの「制作に渡す」から開くときは、詳しいほうが開いて渡す
- 詳しい **制作のページ**(フロート)。左から **要素の情報 | HTML のエディタ | プレビュー | やり取り**(右のペインは、制作のやり取り・**素材**・タスクのタブ)。フロートの大きさとペインの幅は変えられ、覚える。
- 中身は、配信カードの**写し**(承認で下書き、「この内容で依頼する」で固める。当面は、承認の前に依頼したときも、その時点の内容で固める)。あとで配信カードを変えても、黙って変わらない。企画が変わって承認がやり直しになると「企画が変わりました」と知らせる。
- 要素の情報(文言・メイン画像・商品・リンク先)は項目ごとにコピーでき、**直せる**(承認のやり直しは要らない)。直した行には「企画から変更」の印と元の値を出し、行ごとに戻せる。配信カードと承認された写しは書き換えない。
- HTML は 2 つ: **企画の見本**(配信カードのプレビューと同じ見た目の HTML。見るだけ)と、**制作した HTML**(はじめは企画の見本から始まり、エディタで直すか、制作ツールで作ったものを「**貼り付けて置き換える**」で入れて、版ごとに保存)。エディタの上で切り替える。プレビューは「制作した HTML / 企画の見本 / **並べて比べる**」(2 つを横に並べる)。縮小・拡大と「全体」。
- **AI チャット(制作物の手直し)**(エディタの下): 「見出しをもっと短く」「背景を明るく」のように頼むと、AI が直し方を返す。入力欄の近くに**よく使う頼み方**が出て、押すと入力欄に足される(いくつか選んでから送れる)。
  - **見た目**(色・余白・並びなど、HTML だけの直し): プレビューが「いま / **AI の案**」の並べて比べるになり、よければ「**採用**」、要らなければ「やめる」。採用のあとも「元に戻す」で戻せる(確定は HTML の「保存」)。
  - **文言・リンク先・メイン画像・商品**: AI の返事のボタンから、左の要素の情報の**その 1 行だけのフロート**が開く(文言・リンク先は「いま / 企画で承認された値 / 直したあと」を見て、直してから入れられる。画像・商品は「いま / 替えたあと」を見て、ほかから選び直すこともできる。画像は上げることもできる)。「この内容で入れる」で、左の行に「企画から変更」の印が付き、HTML の同じ場所も書き換える(見つからない所は知らせる)。確定は左のペインの「保存」。HTML だけを直して左とずれることがないように、こうしている。
  - AI が選ぶ画像・商品は、配信の国に合う市場の候補の中からだけ。リンク・画像の URL や価格が変わる直しには注意を出す。会話は保存しない。
- **プレビューの場所への書き込み(ピン)**: プレビューの見出しの「**コメントを置く**」→ 場所を押すと、右の「制作のやり取り」に場所(「HTML の中(制作した HTML)」など)が入り、書き込むとプレビューに番号のピンが出る(倍率によらず同じ大きさ)。ピンを押すとそのスレッドへ、スレッドの札を押すとプレビューのその場所へ。配信カードのプレビューのピンと同じしくみ(5.13)。並べて比べている間は置けない。
- 「**仕上がりを見る**」(工程の帯の ④ と、配信カードの「制作」の札): 制作した HTML のプレビュー、「制作が終わった」のひとこととできたもののリンク、直してほしいと伝えたこと、制作指示、素材を 1 つのフロートで見る(素材へのコメントもできる)。
- 題名の下の **工程の帯**: ① 制作に依頼する(企画)→ ② 受け取る(制作)→ ③ 制作する(制作。「制作が終わった」に、ひとことと、できたもののリンクを添えられる)→ ④ 仕上がりの確認(企画。「**これで OK**」か「**直してほしい**」。直してほしいことを書くと ③ に戻る)→ ⑤ 配信のしくみに送る(企画)。いまの段のボタンだけを出し、いちばん新しく終えた段は「やり直す」(依頼の段は「依頼を取り下げる」)。制作を通さずに送る近道は「…」のメニュー。
- やり取りは、計画(企画の段階)と制作(制作の段階)で分ける。書き込みに軽いリアクション(👍 了解 / 👀 見ています / ✅ 対応します / 🙏 ありがとう / ❓ 確認したい)。
- 配信カード・制作のページ・詳しい結果の題名の左に **段階の帯**(PLAN → PRODUCTION → RESULTS)。押すと、同じ配信の隣のフロートに切り替える。配信カードでは、承認済みで渡す前なら、題の行の右の青いボタンが「制作に渡す」(4.3.1)。制作のページの「**企画を見る**」で、配信カードを上に重ねて開く(閉じると、制作のページに戻る)。

## 5. 機能の詳細

### 5.1 すべてAIで下書き
- 何も選んでいないときのペインの「AI で全体を下書きする」と、「⋯」の「すべて AI で下書き」。**テーマ → テンプレート + メイン画像 → ヘッドライン・コピー → 各セクション(見出し・コピー・商品)→ 制作指示 → 件名・プリヘッダー**の順に、AI の第1候補で、下書きを作る(アプリの配信は、通知・メッセージの文言)。いまの中身は上書きする(中身があれば、先に確かめる)。
- 進み具合が、全画面の「AIが下書きを作っています」で表示される(「スキップして開く」で中断できる)。セクションの段は、名札と同じ呼び名で出す(例「グリッド2 を選んでいます(2 / 5)」)。
- 押したことを採用とみなし、でき上がったら**保存する**(ふだんの保存と同じ。気に入らなければ「元に戻す」か、下書きし直す)。
- 1回で、AI を **7〜10回**呼ぶ(セクションの数による。所要時間は、数十秒程度)。
- 前提: 配信日時が入っていること。
- **AI の下書き(空のカード)**: 中身が空のカードを開くと、配信カードの窓の真ん中に重ねて「この配信カードは、まだ中身がありません」と大きめの「AI で下書きする」のボタン・「やめる」を出し、**押したときだけ**下書きし、でき上がったら保存する(押したことを採用とみなす。気に入らなければ、元に戻すか下書きし直す。一括作成の「保存して次へ」で次のカードを開いても、自動では始めない。2026-10-27)。設定の「自分の設定」の「テンプレートが見つからない配信カードを開いたとき、自動で下書きし直す」がオンのときは、テンプレートが見つからないカードだけ、開いたときに下書きし直す(同じカードで1回だけ)。
- 下書きには、「この配信に使う学び」(過去の配信の、次に生かすメモ)も渡す。

### 5.1.1 まとめて作る(作業画面)
- ヘッダーの「**新規作成 ▾**」→「**まとめて作る**」。全画面の作業画面で、1 週間分の配信をまとめて作る。
- 手順は 2 つ。① **計画する**: 週(‹ ›)を選び(国は、画面の上のヘッダーの国。「すべての国」のときだけ、ここで選ぶ)、「作る日と、配信の方向」の表のすぐ上の「**作るチャネル**」でメール / アプリを選び(空いている日の判定が変わるため、表の上に置く。② に進むと、見出しに印だけ出す)、表で、日ごとの**種類**(プルダウン)と**配信名**(社内で配信を見分けるための名前。メールには出ない)を入れる。空けておけば AI が入れる。「種類と配信名を AI でまとめて入れる」、行ごとの「この行に配信名の案」、要らない日は「作らない」。国に**配信の型**(5.17。曜日・時刻・チャネル・種類・テンプレートの組)があれば、型の 1 本 = 1 行で、時刻・種類・テンプレートが入った行になる(「型」の印。型のテンプレートがあれば AI に選ばせない。型のない国・チャネルは 1 日 1 本)。作れない行(過ぎた日・型のない曜日・もうある日・確定した週)は詰めて出す。右に「**この週の配信**」(選んだ国の、すでにある配信と、作る予定の行)→ ② **作って決める**: AI が中身を作り(同時に 3 本まで。「作るのをやめる」で止められる)、できた案のカードごとに、メイン画像・ヘッドライン(アプリは通知のタイトル)・テンプレートを出し、「**プレビュー**」(大きさを変えられるフロートで、配信カードと同じ描き方のメール / アプリのプレビュー。← → と ‹ › で隣の案へ。スマホ / PC)・「開いて編集」(まだ保存していない案も、配信カードで開ける。4.3.1)・「保存」・「破棄」(✕。「破棄を取り消す」)・「作り直す」(その 1 本だけ。前の案のテーマは避ける)。保存した案は「削除」。右の「この週の配信」は ② にも出し、保存していない案は「未保存の案」。カードには、週の中での重なり(週の上限を超える商品・同じテーマ・同じメイン画像・同じ日の配信)も出し、「開いて直す」で直す。説明は、見出しの横の ⓘ。「ほかの保存のしかた」で、中身は作らずに配信名だけで下書きとして保存することもできる。
- AI の案は、保存するまで画面だけに持つ。保存したものは、ふつうの下書き(未起案)になる。閉じるときは「まとめて保存して閉じる」か「破棄して閉じる」。「終えて、週の表示で見る」で、その週の週表示へ。

### 5.1.2 週の枠と、まとめて AI で中身を作る
- ヘッダーの「**新規作成 ▾**」の ▾ から「**この週の枠を作る**」(週の表示のときだけ選べる。確定した週では選べない)。「新規作成」の本体は、1 本作るだけ。
- まず、この週に作る配信の、**国とチャネル**を 1 回だけ選ぶ(既定は、画面の絞り込み)。この週の、その国・チャネルの配信がない日(今日以降)が出て、その日に、中身のない配信カード(**枠**。未起案)を 1 本ずつ作る。いらない枠は消せる。
- 枠は、週の表示で、破線の枠と「枠」の印で出る。その場で、**配信名**と**種類**(値下げ・期間限定価格・セール・新作・コラボ・会員向け・季節の特集・再入荷・その他)を入れる(すぐ保存)。配信名は、AI の案を 1 枠ずつ、または帯の「名前のない N 本に、配信名の案を入れる」で、まとめて出せる。
- 配信名と種類が入った枠は、中身を作れる。帯の「**そろった N 本の中身を作る**」「**選んだ N 本の中身を作る**」(枠のチェック)、または枠ごとの「作る」。AI は、配信名と種類に沿って、テーマ・テンプレート・メイン画像・見出し・コピー・商品・制作指示を作る(同時に 3 本まで。すでにある配信とテーマ・商品が重ならないように)。
- 作った中身は保存され、ふつうの配信として並ぶ。人の確認は承認で担う(2026-10-24 に「AI 下書き・未確認」の印はやめた)。承認の履歴に「AI でまとめて作成した」が残る。
- 週の帯の「まとめて依頼」は、中身のない枠を依頼しない。

### 5.2 テーマ(配信全体の前提。メールには出ない)
- 配信の情報(プレビューの上の 1 行の帯を押す。部品のペインの「ねらい」の「変える」からも)の「**AI でテーマの案を出す**」で、テーマの案を **3つ**出す(各案に、理由つき)。ほかの配信と重ならないテーマを出す。
- 案を押すと試し、「確定」で採用する。採用中の案の**理由**(「AIの理由」)は、保存され、あとで見られる。
- 手で書き換えると、理由は消える(文と理由が食い違わないように)。
- **切り口**(見出し・コピーをどの方向で書くか): テーマの下の 1 行の欄。AI の案を採用すると入り、手でも直せる(2026-10-28)。AI の案にも渡す。

### 5.3 テンプレート(メールの構成の型)
- プレビューのテンプレートの札から、見取り図つきの一覧で選ぶ(乗せると、この配信の中身のままプレビューに写る。押すと替わり、元に戻すで戻せる)。選ぶと、セクションの構成が変わる。選べるのは、配信の国で使うテンプレートだけ(設定の「国」→「使うテンプレート」。5.17)。すでにその国で使っている配信は、使わないにしても、そのまま描き、「この国では使わない」と出す。
- **標準のテンプレート 10種**:
  | 名前 | 構成 |
  |---|---|
  | 自由に並べる(カテゴリごとに見出し) | 商品の数に決まりがない(点数が毎回変わる配信・カテゴリごとに見せたい配信に) |
  | Standard Hero + 4 Grid Items | メイン画像 + 2×2 の商品 4点 |
  | Collaboration Hero + 2 Features + 2 Grid | コラボ用ヒーロー + 特集 2点 + グリッド 2点 |
  | Price: Limited Offer & Value Hero | 赤基調のヒーロー + 価格を強調した 4点 |
  | Standard Hero + 2 Category | カテゴリ 2つ(各 2点)。カテゴリごとに見出し |
  | Standard Hero + 3 Category | カテゴリ 3つ(各 2点)。カテゴリごとに見出し |
  | セール(大きく 1 点 + グリッド) | お知らせ帯 + 文字を大きく重ねたヒーロー。大きく 1 点とグリッドを交互に、最後に写真だけのタイル(12点) |
  | 特集(モザイク + グリッド) | 大 1 点 + 小 2 点のモザイク + 見出し付きグリッド(7点) |
  | ストーリー(写真 + 文) | 写真と商品の説明を左右交互 + 見出し付きグリッド(7点) |
  | コレクション(大きな写真中心) | 大きな写真・モザイク・3 列グリッド(11点) |
- **アプリのテンプレート**(標準 4 つ: お知らせ / 特集 / 商品の紹介 / セール): 「通知の形(テキスト / 画像 / 商品 1 点 + ボタン)」と「メッセージの本文(メールと同じ部品)」の組。
- **セクションは表**(テンプレートを作るとき。2026-10-22〜23): 列 1〜4 × 行 1〜8 のマスに、**箱(商品 1 点)・ボタン・テキスト・画像 / 動画・空き**の部品を敷き詰める。マスを結合して大きな箱(左に縦長 1 + 右に 2 など)を作る。部品ごとに ID を持つ(コメント・成績を部品にひも付けるため)。どのセクションにも、見出し(AI が作る)とコピーの有無・スマホでの並び方・背景・余白・区切り線を決められる。以前の種類(グリッド・写真だけ・大きく・モザイク・ストーリー・特集・独立したボタン)は、編集で開くと同じ見た目の表に直る。ヒーローは、ヘッドラインの見せ方(帯で重ねる / 大きく重ねる / 写真の下)、画像のリンク先の種類、お知らせ帯を選べる。
- 構成のプレビューは、メールに近い縦長の見取り図で表示する。
- AI も、テーマや時期から、**テンプレートを選べる**(「すべてAIで下書き」のとき)。
- **テンプレートの部品の書き換え**: テンプレートで「配信ごとに書き換えてよい」にした文・ボタンの文言・画像は、配信ごとに書き換え・差し替えができる(部品のペイン)。空にすると、テンプレートのまま。AI の下書きは、部品の文を書かない。
- 選ぶとき、テンプレートごとに**最近の使用回数**を出す: この配信日の前 4 週間に同じ国で使った本数、同じ週に使っている本数、最後に使った配信日(取りやめた配信は数えない)。続けて同じ型にならないように選べる。テンプレートの管理画面には、使っている配信の数を出す。

### 5.4 メイン画像 / ヘッドライン・コピー / 件名
- **メイン画像**(プレビューのメイン画像を押す →「入れ替える」): 登録済みの画像から、AI がテーマ・季節・用途・タグに合う画像を選ぶ(「AI に頼む」。選定理由つき)。押すと試し、「確定」で入れ替わる。「すべての画像」から手で選ぶ、ドラッグ&ドロップでプレビューに置く、もできる。画像は、国(JP / US)に合うものだけが対象。
- **持っている画像を上げる**(メイン画像の入れ替えの「アップロード」。AI の案 → 頼み直す → ほかから選ぶ、で合わないとき): 画像(JPEG・PNG・WebP・AVIF、15MB まで。AVIF はブラウザの中で JPEG に変えて上げる。メールでは AVIF を出せない受信ソフトが多いため)を置くと、**AI が画像を見て**名前・用途・季節・タグ(テーマ・色・写っているもの)・説明を下書きする(人は確かめて直す)。画像を押して**焦点**(いちばん見せたい場所)を決めると、テンプレートの枠(帯 8:3・正方形・縦 4:5・横 2:1)に切り出したときの見え方が出て、プレビューでもその点を中心に切り出す。**拡大**(1〜3 倍)で、焦点を中心に寄って切り出せる(トリミング)。**出どころ**(自社で撮影 / 取引先から / 素材サイトで購入 / その他 と、ひとこと)と**使える期限**も入れる。上げた画像は配信ではなく**メイン画像のライブラリ**に入り、この配信のメイン画像になる。同じ国の次の配信からは、選ぶ候補にも AI の候補にも出る。期限を過ぎた画像は、候補から外れる(使っている配信からは消えない)。
- **画像のライブラリ**(設定の「全社」→「画像のライブラリ」。タブで「メイン画像」と「部品の画像」を切り替える)。**メイン画像**: すべてのメイン画像を一覧(画像・名前・コード・国・用途・季節・タグ・出どころ・使える期限(期限切れ・あと何日)・上げた人・使っている配信の数と今週・前週の数)。言葉・国・上げた画像だけ・期限切れも出す、で絞る。「画像を上げる」(入れる国を選ぶ)、「直す」(名前・用途・季節・タグ・説明・焦点・出どころ・期限)、使っていない画像は「消す」(上げた画像はファイルも)、使っている画像は消さずに「今日で期限を切る」(明日から候補に出ない)。「直す」の中の「AI で下書きし直す」で、いまの画像を AI に見せ直して名前・用途・季節・タグ・説明を作り直せる(焦点は変えない)。「空の項目を AI で埋める」で、名前(コードのまま)・タグ・説明が空の画像を、AI が 1 点ずつ埋める(入っている項目は変えない。いま絞り込んでいる画像だけ。途中でやめられる)。
- **部品の画像**(画像のライブラリの「部品の画像」のタブ): ボタン・バナー・ロゴ・アイコンなど、メールの中で使い回す画像。上げると AI が名前・種類・タグ・説明・**代替テキスト**(画像が出ないときに代わりに出る文)を下書きする。大きさ(px)を測って持つ。透明が分かるように市松模様の上に出す。AVIF は PNG に変えて上げる(透明を残す)。国・種類・言葉で絞る、直す、今日で期限を切る、消す。**制作のページ**の左の「部品の画像」に、配信の国の期限内のものが並び、画像の URL か `<img>` のタグ(代替テキストと、元の半分の幅つき)をコピーして、隣の HTML に貼れる。
- **制作のページからも画像を上げる**: 制作のページの左のメイン画像の「ほかの画像に替える」に「持っている画像を上げる」。上げた画像はライブラリにも入り、この版のメイン画像になる。
- **ヘッドライン・コピー**: 「ヘッドライン」(メイン画像の上に載る大見出し)と「コピー」(その下の導入文)。プレビューで押して直し、「AI で変える」で案を出す・指示して直す(4.3.1。試す → 確定)。言語は、配信の国に合わせる(US は英語、JP は日本語)。
- プレビューでは、ヘッドラインが**自動で縮小して、1行に収まる**。

- **件名・プリヘッダー**(メール。プレビューの上の「受信箱での見え方」を押す): 件名(空なら配信名)と、プリヘッダー(受信一覧で件名の横・下に出る短い文。文字数と目安 40〜90 文字を出す)。制作の写しの「テキスト」にも入る。「AI で変える」で案を出す(試す → 確定)。AB テストでは、比べる要素に「件名・プリヘッダー」を選べ(「メイン画像・商品・文言」にも件名が入る)、B・C 案では A 案と違う切り口の案を出す。全案を送る AB テストでは、制作のページで案(A・B・C)を切り替え、案ごとに HTML を作って保存できる。保存していない案があるうちは「制作が終わった」を押せない。仕上がりも案ごとに見られる。
### 5.5 セクション(見出し・コピー・商品)
- テンプレートのセクションごとに、見出し(見出しのあるセクションだけ)・コピー・商品の枠を持つ。プレビューで、見出し・コピー・商品の枠を押して直すか、名札でセクションの全体を選ぶ(4.3.1)。呼び名は「グリッド2」のように、種類の名前 + 番号。
- 見出し・コピーは「AI で変える」(試す → 確定)。商品は、セクションの全体のペインなどの「**グリッド1 の商品を AI で選ぶ**」で、見出し・コピーを踏まえてまとめて選ぶ(試す → 確定)。
- **商品の選定**: AI が、在庫(少ないものは避ける)、売上トレンド、評価、季節、天候、テーマ、メイン画像・ヘッドラインとの整合などから選び、**理由**を表示する。残りの案は、そのセクションの「残りの候補」になる(入れ替えの引き出しの「AI のおすすめ」)。1 つの配信の中で、同じ商品を複数のセクションに入れない。
- 商品の操作: 並べ替え(プレビューでつかんで動かす・Alt + 矢印)、外す(× か Delete。枠は空き枠になる)、入れ替える(入れ替えの引き出しの「AI のおすすめ / AI に頼む / すべての商品」。すべての商品は、検索語かカテゴリで探す)。4.3.1。
- 商品は、配信カードの**国に合う市場(JP / US)のものだけ**が、AI の対象と検索の対象になる。
- **空いた枠**: 前のセクションが空いたまま、後ろのセクションに商品を選んだ・置いたときも、前の枠に詰めない(空いた枠のまま残す)。外すと、そのセクションの中だけ詰め、ほかのセクションは動かさない。
- 確定したあとも、「**元に戻す**」(Ctrl + Z)で戻せる。

### 5.5.1 リンク先
- メール: メイン画像・ボタン・画像を押したときの部品のペインで、URL(空は既定)を直す。計測用のパラメーター(utm)の付いた、実際に送る URL は読むだけで出す(utm の決まった値は ⚙ の設定。5.17)。アプリ: 開くアプリの画面(5.6.1)。詳しくは 5.13。
- リンクの場所すべてに行き先が決まったら、完了(テンプレートの既定の行き先も含む)。「配信カードで指定」のボタンは、配信ごとに決めるまで未完了。

### 5.6 制作指示
- 左のバーの「**渡すもの**」の「渡す文章(制作指示)」。箇条書き・見出しつきの欄で書き(4.3.1)、AI に頼んで直せる(例「画像の指示を足して、箇条書きに」。試す → 確定)。AI で全体を下書きするときも作る。
- 部品のペインの「**制作へのメモ**」で、部品ごとのメモを制作指示に足せる。

### 5.6.1 アプリの配信(通知 / メッセージ / 開く画面)
- **通知**(プレビューの上の、スマホの通知の形を押す): 通知のタイトル・本文。「AI で変える」で案を出す(文字数と上限を表示)。
- **メッセージ**: アプリの中のメッセージボックスに届くメッセージ。メールと同じ部品(メイン画像・見出し・セクション)で、プレビューを押して作る。
- **開く画面**(通知の部品のペインの「押したときに開く画面」と、メッセージのメイン画像・ボタンのペイン): 通知は Firebase Cloud Messaging(FCM)で送る想定。開く画面は URL ではなく、通知の data に入れる **screen(画面の名前)と、画面に渡す値**で伝える。
  - 通知を押したときに開く画面: このメッセージ・配信のページ・紹介する商品・カテゴリ・アプリのホーム・画面の名前を指定。
  - メッセージのメイン画像・ボタンごとに開く画面: 既定は、テンプレートのリンク先の種類から決まる(配信のページ → 配信のページ、カテゴリのページ → カテゴリ、ショップのトップ → アプリのホーム)。変えるときは、配信のページ・カテゴリ・商品・ホーム・画面の名前から選ぶ。
  - 商品のリンクは、商品のページ(商品コード)を自動で開く。
  - 各欄の下に、data に入れる値(例: `{"screen":"product","product_code":"…","campaign":"…"}`)を出す。どの画面にも、配信を表す campaign を付ける。
- 送る日時と送る相手(全員・会員など)は、配信の情報で決める(送る相手は「配信の対象」の中。最初に決め、AI の下書きの前提にする)。

### 5.7 部品ごとに AI に頼む
- 配信カード全体で自由に頼む AI チャット(以前の中ペインの下半分)は、2026-10-28 に詳しい配信カードと一緒になくした。代わりに、部品ごとに AI に頼む。
- **文の部品**(件名・プリヘッダー・ヘッドライン・コピー・セクションの見出しとコピー・通知の文): 「AI で変える」の「案」と「指示して直す」(4.3.1)。
- **メイン画像・商品**: 入れ替えの引き出しの「**AI に頼む**」に、言葉で条件を書く(例「人物が入った、明るい屋外の写真」「2 万円以下のアウターで、在庫の多いもの」)。入力欄の近くに、**よく使う頼み方**の札が出る。
- **配信の全体**: 何も選んでいないときのペインの「AI で全体を下書きする」に、どう作るかを書ける(任意。空なら、いまのテーマから全体を作る)。
- **制作指示**: 渡すものの欄から AI に頼む(5.6)。
- どれも試す → 確定。会話は保存しない。
- 制作のページにも、制作物を手直しする AI チャットがある(4.6)。

### 5.8 プレビュー(メール / アプリ)
- **メール**: いちばん上の帯(左に差出人の名前、右に MEN / WOMEN の文字のリンク)、ヒーロー(メイン画像 + ヘッドライン + コピー)、セクションごとの見出し・コピー・商品タイル(画像、名前、価格、ボタン)。テンプレートの構成に従う。メイン画像・ボタンにマウスを重ねると、設定したリンク先が出る。
- **アプリ**: 通知の見た目(iOS / Android の切り替え)と、通知を押したあとのメッセージ。
- **部品を押して直す**: プレビューの部品を押すと、その部品のペインが出る(4.3.1)。商品はつかんで並べ替え、乗せると「⇄ 入れ替え」と「×」。
- **倍率**: 右下の「− 倍率 +」と Ctrl + ホイール、「全体」(全体が収まる倍率)と「100% にする」。
- 価格の表記: JP の商品は円(¥)、US の商品はドル($)。

- メールは「**スマホ / PC**」で幅を切り替えて見る(スマホ 375px・PC 640px。ブラウザごとに覚える)。
### 5.9 商品の一覧と、商品のフロート
- 右の**商品の一覧**(畳める)に、掲載商品を、**メールの並び順**に、セクションごとに一覧する。1行は、画像、名前、「コード・価格・在庫」、売上トレンドの矢印(↑ ↓ →)。**在庫が少ない商品には「残少」**の印。アラートのある商品には種類の札(押すと、そのアラートへの対応)。
- 行にマウスを置くと、プレビューの**該当商品が枠で光る**。
- 行を押すと、**商品のフロート**が開く(画面の真ん中に大きく出し、題名の行をつかんで動かせる。右上の × か Esc で閉じる)。**プレビューの商品の箱・部品のペインの商品を押しても、アラートの札を押しても、同じフロートが開く**。アラートから開いたときは、上にそのアラートと「配信日を変える」「アラートの画面で詳しく」が出る(7 章)。
- フロートは、はじめは**詳しい情報**(題は商品名)。題の行の「**入れ替える**」(商品ページの隣)で、同じフロートの中が**入れ替え**(題は「○○を入れ替える」)に切り替わり、「← 詳しい情報に戻る」で戻る。在庫・週の上限のアラートから開いたときは、入れ替えから始める。
  - 入れ替え: いちばん上に、いまの商品を 1 行。その下に、アラートから開いたときの **AI の差し替え案**、そのセクションの**残りの候補**(AI のおすすめの先頭)、**AI に頼む**、**すべての商品**(名前・コード・カテゴリで探す。「残少」・週の上限・アラートの札つき。もう載っている商品は「掲載済み」)。行には「在庫の持ち 約○週」。候補の小さな写真を押すと、その商品の詳しい情報。
  - 候補を押すと、**プレビューにだけ仮に当てはめ**(試す)、上の帯の「**確定**」で配信カードの中で入れ替わる(残りの候補を選んだときは、外した商品が候補に戻る)。やめれば元のまま。理由は聞かない。**保存で確定**し、候補の AI の理由は配信のメモに残る。
  - **この配信で使う画像**(詳しい情報の上)。いまの画像と「商品ページから画像を選ぶ…」。選ぶフロートは、商品の URL のページを開いた時点で読み、ページの画像を並べる(切らずに全体を見せる)。「**AI に選んでもらう**」で、画像ごとのアングル(正面・後ろ・着用・ディテール・素材の寄り・使う場面 など)と、配信のテーマ・見出し・コピーと商品の説明から、伝えたいことが見て分かる画像を 3 つまで、理由つきで勧める。ページを読めないときは、商品ページの画像を右クリック →「画像をコピー」して Ctrl+V、ファイルを落とす・選ぶ、画像の URL を入れる、でも選べる。「この画像にする」で、プレビュー・商品情報の行・制作のページの写しが、その画像になる(**保存で確定**。商品のマスタの画像は変えない。AB テストでは、案ごとに持てる。「商品のマスタの画像に戻す」で元に。画像だけを替えたときは、承認のやり直しにしない(変更の履歴には残る))。画像ごとのアングルは一度だけ見分けて残し、次からは読み直さない。本物のページの画像は CCP に写して持つ(あとで消えても困らないように)。**いまの商品ページの URL は仮のもの(shop.example.com)なので、その URL は、CCP が作る見本の EC サイトのページ(`/sample-shop/p/<商品コード>`。商品ごとの色の絵 6 枚)を読む**(外に出られない環境でも、流れを最後まで試せるように。「見本のページ」の印)。
- 詳しい情報のタブ:
  - **売上・在庫**: 指標3つ(直近4週の販売数と増減%、在庫が何週分か、12週の売上)、**週ごとの販売数の棒グラフ**、**在庫の推移の折れ線グラフ**(在庫が少ないラインつき)。グラフは12週分。マウスを乗せると、その週の値が出る。
  - **基本情報**: 価格、在庫、売上トレンド、評価、季節、天候適性、説明。
  - **SKU**(X63。商品別の見せ方の詳細と、アラートの画面でも、見出しの商品の画像か、その下の「SKU・詳しい情報」を押すと、同じ詳しい情報を SKU のタブで開ける): いまの在庫から計算した SKU 欠品率・欠品の SKU の数・在庫の合計と、色 × サイズの在庫の表(0 は赤、3 以下は黄)。本物の SKU は BigQuery から入る。設定の「開発・管理」→「見本のデータ」の「見本の SKU を作る」で、SKU がまだない商品に見本を作れる(在庫の合計は商品の在庫と同じ。表の見出しに「見本」の印。「見本の SKU を削除」で見本だけを消せる)。見本の行は `source = sample` の印を持ち、BigQuery の取り込みは見本を消さず、在庫の合計にも数えない。BigQuery の SKU が来た商品の見本は、取り込みのときに消える。
  - **指標**: この商品と、そのカテゴリの週の指標(値・順位・前週比・前月比・前年比)。SKU 欠品率は増えたら赤、在庫数の増減は色なし。まだ取り込んでいなければ、設定の「開発・管理」→「取り込み・書き出し」の「商品・カテゴリの指標を取り込む(CSV)」を案内する。
  - **販売方針・販促**: MD の販売方針、販促の期間、販促計画(週ごとの予定)。位置づけ(主力 / 定番 / 在庫調整 など)がバッジで出る。
- 一覧そのものには、操作する部品を置かない。右の一覧には「入れ替える」だけを置き、並べ替え・外すはプレビューと部品のペインで行う(4.3.1)。

### 5.10 テンプレートの管理(設定の「全社」→「テンプレート」)
- 設定の画面からも、配信カード(テンプレートの選び直し)からも、同じ**大きな作業のフロート**で開く(大きさを変えられ、題の行の右の切り替えで画面いっぱいまで広げられる。どちらも覚える)。
- 左に一覧(「作成したテンプレート」と「標準」。2 列で見比べられる。メールとアプリ。それぞれに使っている配信の数)、右に詳細・編集、構成の見取り図(プレビュー)。
- **テンプレートは版で持つ**: 標準のテンプレートも、作成したものも「編集」「複製」できる(標準はコードの定義が版 0)。**保存するたびに新しい版**になり(「変更のメモ」を残せる)、すでにある配信は、**使った版の形のまま**(テンプレートを直しても、作った配信の見出し・商品の位置は崩れない)。使っている配信があるときは、編集中に黄色の帯を出し、保存の前に「版 n+1 になる。これらの配信は使った版のまま」と確かめる。
  - 詳しい欄: 「いまの版: 版 n」、**版の履歴**(版ごとの日付・人・メモ・使っている配信の数。「見る」「この版に戻す」)、**使っている配信**(版ごとに、配信名・日付・状態。押すと配信カード。いまの版は開いたまま、過去の版は「版 k・n 本」を押すと開く)。標準は「最初の形に戻す」もできる(戻すのも、新しい版として保存)。
  - 使っている配信の数・一覧は、**ヘッダーの国**の配信だけ。ほかの国でも使っていれば「ほかの国でも n 本で使っています」と数だけ出す(削除・使わない・保存の前の確かめは、すべての国の分で決める)。
  - 配信カードのテンプレートの選び直し: 前の版を使っている配信には「このテンプレートは、この配信のあとに編集されました(この配信は版 k、いまは版 n)」と「いまの版(版 n)にする」。
- **AI で作る**(一覧の上の「AI で作る」。枠線の AI のボタン `AiButton`。メールのテンプレートだけ): 「AI でテンプレートを作る」のフロートで、目的(何のための配信か)・載せる商品の数(1〜24)・切り口・構成のメモ(任意)・雰囲気(標準 / セール・期間限定 / コラボ)を入れると、AI がセクションと部品(箱・ボタン・テキスト・画像・区切り線)の並びを組み立てて下書きにし、「この構成にした理由」を添える。作る前と作ったあとに、商品の数・雰囲気・構成が近いテンプレートを、似ている度と一緒に 3 つまで出し、「使う」「複製して直す」も選べる。「この下書きで編集を始める」で編集(新規)に入る。AI の下書きは保存しない(保存は、編集の画面で確かめて、いつもの「保存」)。
- **AI で直す**(編集画面のキャンバスの見出しの先頭。枠線の AI のボタン。メールのテンプレートだけ。2026-10-28): 今のテンプレートへの直しを言葉で頼む(例「2 列のグリッドを 3 列に」「全部の箱にセールのバッジ」)。AI の直した形をキャンバスに仮に当て、変わった・足した部品に点線の印。帯に何を変えたかと、変えた・足した・消した部品の数。「確定」で取り込み(Ctrl+Z で戻せる)、「やめる」で元に戻す、「頼み直す」。試しているあいだはキャンバス・保存・元に戻すを止める。残す部品の ID はそのまま(返答でも検査し、付け直された ID は元に戻す)。AI の案は保存しない(保存はいつもの「保存」)。TEMPLATE_OBJECTS.md の 11 章
- **使わない(無効)**: 「使わないにする」で、配信カードの選択肢から外す(使っている配信は、そのまま)。一覧の下の「使わないテンプレート(n)」から、また使える。**削除**できるのは、どの版もどの配信でも使っていない、作成したテンプレートだけ(標準は削除できない)。
- **編集画面**(T8。触れる試作で利用者と決めた形): 「**パーツ** | **キャンバス**(メールの見た目の表)| **右のタブ**(テンプレート / セクションと部品)」の 3 列(境目をつかんで幅を変えられ、覚える)。見出しは「テンプレート › 名前 を編集中」。
  - **パーツ**(足すだけ。中身のあるマスを置き換えない): 箱・ボタン・テキスト・画像 / 動画と、**よく使う行**(箱 × 2・箱 × 3・大 1 + 小 2・文 + 箱・ボタンの行・ボタン × 2(均等))、空のセクション。空きのマスに落とすとそこに入り、中身のあるマスの端に落とすと、その側に行・列を差し込む。押すと、選んでいるセクションのいちばん下に 1 行足す。
  - **キャンバス**: マスを押す・なぞる(Shift+押す)で選ぶ。**右クリック**で結合(Ctrl+M)・分割・空きにする・コピー(Ctrl+C)・貼り付け(Ctrl+V。空きのマスに)・行と列の挿入。行・列の帯の「…」で挿入・移動・削除・**この行を複製**・**この行を均等に並べる**(3 列の下にボタン 2 つを半分ずつ、など。帯に「＝」)・この行から下を新しいセクションに。空きのマスの「＋ 置く」。ボタン・テキストはダブルクリックでその場で直す。セクションは札(⠿ S1)をつかんで動かす・Alt+↑↓。キャンバスの大きさを変えられる(− / つまみ / + / 全体)。
  - **箱の ⚙**(選んだ箱の右上・ダブルクリック): その場で見せ方を直す。箱をいくつか選ぶと、まとめて直す。
  - **右のタブ**: **テンプレート**(基本・通知・全体の見た目・状況(商品の枠・版・使っている配信・同じ構成)・**似ているテンプレート**・構成)/ **セクションと部品**(セクションのカードと、位置の絵つきの部品の行。行に乗るとキャンバスのマスが光る。キャンバスで選ぶと、このタブに切り替わる。選んでいるカードも、もう一度押すと閉じる)。
  - **似ているテンプレート**(右のタブ「テンプレート」。2026-10-28): 編集中の構成と似ている順(同じ構成を先に)。いちばん上に、同じ構成(黄)・よく似たもの(似ている度 80% 以上)の知らせ(作り過ぎを避ける)。行ごとに「見比べる」(今の編集中と左右に並べるフロート `TemplateCompareFloat`。大きさを変えられる)・「セクションを取り込む」(相手のセクションを選んで、新しい ID で末尾に足す。Ctrl+Z で戻せる)・「…」の「開く」「複製して直す」。最初は似ているもの 4 つまで、残りは「もっと見る」。状況の「同じ構成のテンプレート」を押すと、この欄へ。
  - **元に戻す・やり直す**(Ctrl+Z / Ctrl+Shift+Z)。
- 作成・編集できる内容:
  - **テンプレート**: 名前、説明、ヒーロー(種類・ヘッドラインの見せ方・画像のリンク先・お知らせ帯)。
  - **セクション**: 名前、見出し・コピーの有無、AI の切り口のメモ、スマホでの並び方(列のまま / 縦に積む)、背景の色(白・グレー・ベージュ・ブルー・ピンク)、上下の余白、区切り線。複製・上とまとめる・削除。セクションは最大 8 つ。
  - **箱**: 見本(標準・価格だけ・写真だけ・セール・新作・詳しく)、見せ方(写真 + 名前・価格 / 写真だけ / 特集 / ストーリー)、写真の形(正方形・縦長・横長・横に広い)、出すもの(名前・価格・バッジ・説明・ボタン・**カラーチップ**(SKU の色を並べる。丸 / 四角・並べる数の上限)・**レビュー**(星・平均点・件数。出す件数の下限))、**置き場所**(名前・価格などを 写真の下 / 写真に重ねる(上・中央・下)/ 写真の横(左・右)。省略は見せ方から決まる場所)、要素(写真・名前・価格など)ごとの説明と「押せる」(メールの中でリンクになるか)、価格の見せ方(ふつう / セール(元の価格に取り消し線)/ 〜から)、バッジの文言、AI に伝える一言。「この見せ方を、ほかの箱にも当てる」(同じ行 / このセクション / すべて)。名前・価格は商品のデータから出す(テンプレートでは打たない)。
  - **ボタン**: 文言・見た目(塗り / 枠線 / 文字のリンク)・色(黒・赤・紺・緑・グレー)・形(丸・角丸・四角・下線だけ)・大きさ(小 / 中 / 大)・幅(文字に合わせる / マスいっぱい)・矢印(› を右 / 左に)・**画像のボタン**(画像だけ / 画像の上に文字。画像は配信ごとに差し替えてよい)・文言を配信ごとに書き換えてよいか・揃え・リンク先の種類・計測用の名前。
  - **テキスト**: 固定の文・配信ごとに書き換えてよいか・揃え・**向き**(横 / 縦書き / 90 度回す。縦・回転は多くのメールのソフトで出せないので、制作に渡す HTML に「この文字は画像にしてください」と書く)・枠で囲む(線 / 点線)。
  - **区切り線**(太さ・色・長さ(全幅 / 真ん中だけ)・上下の余白)と**余白**(高さ)。均等の行には、部品の間に縦の区切り線を引ける。よく使う行に、区切り線・文字のリンク × 3(縦線)・アイコンの行なども。
  - **ヒーローの見た目**(テンプレートのタブの全体の見た目): 写真の形・ヘッドラインの位置(上・中央・下 × 左・中央・右、写真の下)・文字の色・写真に重ねる暗さ・お知らせの帯の文言。メイン画像の下には、表の行(ボタン・テキストなど)を置ける。
  - **画像・動画**: 画像(部品の画像のライブラリから選ぶか URL)・動画の URL(メールでは再生できないので、画像をサムネイルにして ▶ を重ね、押すと動画へ)・代わりの文・形・リンク先の種類・計測用の名前・配信ごとに差し替えるか。バナー・タイル・アイコン・地図(画像 + 地図へのリンク)に使う。
- リンク先は、テンプレートでは**種類(配信のページ / カテゴリのページ / ショップのトップ / 配信カードで指定)**を決め、実際の URL は配信カードの部品のペイン(メイン画像・ボタン・画像)で決める(5.13)。
- 作ったテンプレートは、**組織の全員が選べる**(アプリのデータベースに保存)。他の人が作ったものも編集できる。どの国で使うかは、設定の「国」→「使うテンプレート」(見本の縮小を並べて選ぶ)。国で外しても、新しい版は作らない。
- 配信カードからは、テンプレートの構成を変えない(テンプレートごと・位置ごとの結果の比べを崩さないため)。構成を変えたいときは、テンプレートを編集する(新しい版)か、新しいテンプレートを作る。

### 5.11 日本語 / English
- 設定の「自分の設定」の言語の切り替えで、**画面全体**が、日本語・English になる(初期値は English。選んだ言語はブラウザごとに覚える)。
- **AI の出力**も、画面の言語に合わせる(理由・切り口・制作指示など)。コピー・ヘッドラインは、配信の国の言語で作る(US は英語、JP は日本語)。
- 日付・価格の表記も、言語に合わせる。

### 5.12 週のレビューと承認
- **週の状態**: 確定前 → 確定。状態は、週の帯の左端の印に出す(マウスを重ねると、確定した日時)。週の状態は**国とチャネルごと**に持つ(メールとアプリは、別の人・別のときに確定するため)。「週を確定」「まとめて依頼」・確定の鍵は、その国・チャネルの配信だけに効く。ヘッダーの国かチャネルの絞り込みが「すべて」のときは、週の帯に組(国 × チャネル)ごとの状態を並べ、押すとその組に絞る(承認・確定は、組を選んでから)。週・月の振り返りも、組・国を選んでいるときだけ書ける。
- **週の帯**(週の表示の上。その週のレビューと確定だけを置く): 左端に週の状態の印と、状態ごとの件数(未起案・承認待ち・承認済み。確定は承認済みに数える)。右に「**まとめて依頼**」「**自分宛てを承認**」「**確定の前に直すこと**」の印・「**週を確定**」「確定を取り消す」。
- **配信 1 本ずつの承認**: 配信カードの左のバーの「承認」(題の行の承認の札を押しても開く)で「**承認を依頼する**」(相手は承認グループか人)。承認者には「**承認する**」と、理由を付けて「**差し戻す**」が出る(理由はやり取りにも残る)。変更が保存されていないときは、先に「保存」する。「誰が」は右上の「あなた」の人。自分で依頼した配信も、自分で承認できる(確かめてから)。承認のルール(どのグループに回すか)は、設定の「全社」→「ユーザーと承認グループ」→「承認の決まり」で、国ごとに決められる(国の決まりがなければ共通)。承認グループには「承認する国」を付けられる(空はすべての国)。キャンペーンの配信は、キャンペーンの帯の「まとめて承認」で、まとめて依頼・承認もできる(4.3.2)。
- **確定後の変更の制限**: 確定した週の配信では、承認のパネルに説明が出る。確定した週の配信は自動では保存せず、内容を変えると上の帯の「理由を入力して保存」で理由を聞く。保存すると、配信は「検討中」、週は「確定前」に戻り、理由は記録に残る。承認済みの配信の内容を変えても、「検討中」に戻る。
- **確定の前に直すこと**(確認の一覧。「週を確定」の左の印): 週を確定する前に、0 にしておくことの一覧。同じ商品の週の回数(上限を超えたもの)、メールとアプリ、主力の商品の漏れ、テーマ・メイン画像の連続、未解決のやり取り、承認の数。
  - 印は、問題のある項目の数(⚠ と数)。なければ ✓。押すと、一覧が重なって開く(画面は移らない)。
  - 問題のある項目を、**何をするか**(例: 「ほかの商品に差し替える」「質問に返信して、解決にする」)と一緒に出す。問題のない項目は「OK の項目」にまとめ、押すと出る。
  - 項目を選ぶと、週の表示で、かかわる配信・商品が目立つ。帯の左に「選択中: …」の札が出る(× で外す)。「**最初の配信を開く**」から配信カードを開き、「保存して次へ」で、その項目の配信を順に直せる。
  - 残っているまま「週を確定」を押すと、確かめる。
- **承認の履歴**: 誰が・いつ・何から何にしたか(週の操作と、配信のステータスの変更)。「この画面 ▾」の「この週の承認の履歴」。
- **週の資料(PDF)**: 「この画面 ▾」の「週の資料を PDF で書き出す」で、印刷の画面を開く(送り先を「PDF に保存」)。1 枚目に、週の状態・確認の一覧・配信の一覧・承認の履歴。2 枚目からは、配信ごとのプレビュー。

### 5.13 やり取り・引き継ぎ・タスク・リンク先
- やり取り(書き込みとタスクの 1 本の流れ)・素材・渡すもの(引き継ぎ)は、配信カードの**左のバー**にある。リンク先は、プレビューのメイン画像・ボタン・画像を押したときの部品のペイン。
- **やり取り**: 質問・指摘・相談を書く(以前の「質問」と「コメント」を 1 つにした)。場所は、プレビューで選んでいる部品から自動で入る。宛先を入れると、その人に返事を求める(だれからでも、だれにでも)。返信でやり取りし(スレッド)、決着したら「**解決にする**」(「返信して解決にする」もある)。解決したものは消さずに、たたんで残す。未解決の数を、左のバー・週の表示・確定の前に直すことに出す。
- **プレビューの場所への書き込み(ピン)**: 配信カードのプレビューの右上のピン → プレビューの場所(件名・メイン画像・ヘッドライン・ボタン・セクション・商品の枠・アプリの通知 など)を押すと、やり取りが開いて場所が入る(「場所を外す」もできる。Esc でやめる)。書き込むと、プレビューのその場所に番号のピンが出る。承認する人がプレビューの場所を指して指摘し、企画担当とやり取りする使い方を想定。場所は座標ではなく「どのブロックの中のどのあたりか」で持つので、スマホ / PC の切り替えや倍率を変えても同じ場所に出る。スレッドの札(「プレビューでこの場所を見る」)を押すとプレビューのその場所までスクロールして光り、ピンを押すとそのスレッドが出る(解決してたたんでいれば開く)。ピンは、プレビューの横のフロートで書き・読み・返信・解決する(宛先も選べる。「この部品を直す」で、その部品を選ぶ)。プレビューの右クリックの「ここにピンを打って、コメントを書く」でも打てる。ピンを打つ間は、プレビューの上に「コメントを書く場所を押してください(Esc でやめる)」の帯。書いたときの様子(その場所の画像と文字)を残し、あとで場所の中身が変わると、ピンの右上に点と「書いたあとに、この場所が変わりました」。解決したスレッドのピンは、ふだんは出さない(ピンのボタンの横の切り替えか、右クリックで出せる。人ごとに覚える)。ピンへのリンクをコピーでき、開くとそのピンのフロートが開く。セクションのピンは、テンプレートの構成を変えた版でも同じセクションに付く。制作のページのプレビューにも置ける(4.6。制作のやり取りに入る)。
- **渡すもの(引き継ぎ)**: 制作の担当・締め切り・渡す文章(制作指示)・参考の画像・資料・URL を決め、「**制作に渡す**」で制作のページへ進む(アプリからの通知は送らない。4.6)。
- **タスク**: 質問などのやり取りから、AI がタスクの案を出し、採用したものを担当・期日・完了で管理する。未完了の数を、左のバー・週の表示・一覧に出す。
- **素材(Creative Assets)**: 制作に使ってほしい画像・資料(ファイル。画像・PDF・Office、1 つ 20MB まで)や、参考のページ(URL)を、配信ごとに置く。ファイルは欄に置くか「ファイルを選ぶ」、URL は題名を付けて追加。ひとこと(「この雰囲気で」など)も付けられる。素材を押すと大きく見られ(画像・PDF はその場で。ほかはダウンロード。URL は**見本カード** = ページの題名・説明・代表の画像を、足したときに 1 回だけ取って出す。ページそのものは新しいタブで開く。取り直しもできる)、**その素材についてやり取り**できる(返信・解決は、やり取りと同じ。やり取りの一覧にも「素材: 〜」の札で出る)。だれでも足せて、その場で保存する。だれでも消せる(一覧の行の右上のごみ箱・素材のフロートの「消す」。人の入れた素材は、確かめの文に入れた人の名前を出す)。一覧は**制作へのメッセージが主役**(1 行に、小さな画像・題名・メッセージの全文・だれがいつ・未解決のコメントの数)。置き場所は、計画では左のバーの「**渡すもの**」(「参考の画像・資料・URL」。指示の文章と参考をひと組で添える)と「**素材**」、制作のページでは**左の制作指示のすぐ下**と、右の「素材」のタブ。どこも同じものを見る。
- 絞り込みの「担当」は、企画・制作の担当に加え、未解決のやり取りの宛先・書いた人、未完了のタスクの担当の配信も出す。
- **リンク先**(部品のペイン): メールは、メイン画像・ボタンごとに、実際の URL と計測用のパラメーターを決める。計測用のパラメーターは自動で決まる: `utm_source`・`utm_medium` = ⚙ の設定の「差出人の名前・店の URL・計測用の値(utm)」(全社の既定と国の上書き。5.17)、`utm_campaign` = 配信日 + 配信カードの ID の先頭 8 文字(例 `20261021-1a2b3c4d`)、`utm_content` = 押された所の ID(表の形のテンプレートでは、部品の中の要素の ID。例: メイン画像 `sec_hero.image`、文字のボタン `btn_….label`、商品の箱は押せる要素ごと `box_….image`・`box_….name` など。それより前の形のテンプレートと、前の作り方で依頼した写しは、`hero`・ボタンの番号 `btn1`…・商品の枠の番号と商品コード `p01-ABC123`。見せるだけで直せない)。GA で、どの配信のどのリンクが押されたかを見分けるため。メールのいちばん上の帯(左に差出人の名前、右に MEN / WOMEN の文字のリンク。行き先は設定の「店の URL」から)にも計測用のパラメーターが付く。制作のページの HTML の下書きでは、メイン画像・ボタン・商品の枠が、この URL のリンク(`<a href>`)になる。AB テストの配信は、計測用のパラメーターの campaign の末尾に案の印(-a・-b・-c)が付き、案ごとに成果を分けられる(部品のペインには、いま編集している案の値が出る。制作のページでは、案ごとのリンクをまとめてコピーできる)。アプリは、開くアプリの画面を決める(5.6.1)。

### 5.14 結果の振り返り
- **結果の取り込み**: 結果の面の「この画面 ▾」から、CSV(配信名・配信日・送った数・開封・クリック・注文・売上・前年の売上)を取り込む。「取り込みの見本」もある。CSV で取り込むのは、配信ごとの数字。リンクごとのクリック・商品ごとの結果は、データにあれば、ヒートマップや商品の表に出す。
- **月**: 計画の面と同じカレンダーで、配信ごとに売上・開封率(アプリはタップ率)・前年比。左の線の色は前年比(上なら緑、下なら赤)。結果がまだの配信は灰色。上に「**この月の振り返り**」のメモ(週の振り返りと同じ形。表 `months` に 1 か月 1 行で保存)。
- **週**: 日ごとに、**クリックを重ねたプレビュー**(ヒートマップ)と主な数字。上に「**この週の振り返り**」のメモ(週全体で気づいたこと・次の週に生かすこと。ふだんは 1 行にたたみ、「書く」「直す」で開いて、その場で保存)。ツールバーの「**先週を振り返る**」で、先週の週表示に 1 回で移れる。
- **AI で下書き**(週・月の振り返り): その期間に送った配信の数字(国 × チャネルごとの合計、配信ごとの数字・前年比・次に生かすメモ)を、前の期間(週は 4 週、月は 3 か月の平均)と比べて、良かったこと / 悪かったこと / 次に試すこと と根拠の強さを、AI が書く。月は、その月の週の振り返りも渡す。下書きはメモの欄にそのまま入り、人が直してから保存する(保存しなければ残らない)。
- **前週の振り返り**: 計画の面の週の表示に、前の週に書いた振り返りが出る(「前週の結果を見る」で、結果の面の前週へ)。**前月の振り返り**も同じく、計画の面の月の表示に出る(「前月の結果を見る」で、結果の面の前月へ)。
- **一覧**: 計画の面と同じ表(左にサムネイル。列見出しで並べ替え)。開封率・クリック率・売上・前週比・前年比。**テーマ / テーマの種類 / テンプレート / 商品**ごとにまとめて見ることもできる。書き出しもできる。
- **比べる**: ツールバーの絞り込みと、テンプレート・テーマの種類・配信名で絞った、直近 5 / 10 / 20 回の配信を、ヒートマップと数字で並べる。AI の評価も出せる。
- **詳しい結果**(配信を押すと上に重なる): 主な数字、プレビューの上に**リンクごとのクリックを濃さで重ねる**(メイン画像・ボタン・商品)、リンクの表、商品ごとのクリック・売れた数と配信の前後の販売・在庫、**販売チャネルごとの順位**(全社・EC・配信経由。配信前 4 週に上位に入った週の数と、配信の週・翌週の順位。上位とみなす線 Top N は変えられ、既定は 60)、採用したテーマ・見出し・テンプレート・メイン画像と AI の理由。
  - **過去の配信と比べる**: 同じテンプレート、または同じテーマの種類の、この配信より前の 3 / 5 / 10 回と、数字・位置ごとのクリックの割合を並べる。
  - **AI で振り返る**: 良かったこと / 悪かったこと / 次に試すこと(数字入り)と、根拠の強さ。1 行ずつ「メモに採用」できる(振り返りそのものは保存しない)。
  - **次に生かすメモ**: 配信ごとに残す。同じテンプレート・テーマの種類の、次の配信カードの「この配信に使う学び」に出て、AI の案にも渡される。
  - **AB テストの結果**(AB テストの配信だけ): 案ごとの送った数・開封率・クリック率・注文率・1 通あたりの売上を並べ、配信カードで決めた指標で**勝ち案**と、その差が偶然の範囲かの目安(送った数が少ないときは「まだ判断できない」)を出す。勝ち案と仮説の結果は、1 行で「メモに採用」できる。結果の CSV に、案(A / B / C)と区分(テスト分 / 勝ち案の残り分)の列を足して取り込む(省略すると、配信全体の 1 行)。配信全体の数字は、案ごとの行の合計。「案から選ぶ」配信には出さない。
  - 「**制作の詳細**」で配信カードを上に重ねて開ける(閉じると結果に戻る)。「**PDF で書き出す**」で、配信 1 本のレポート(A4 縦 1 枚)。
- **テーマの種類**(値下げ / 期間限定価格 / セール / 新作 / コラボ / 会員向け / 季節の特集 / 再入荷 / その他): 「AI でテーマの種類を分ける」で、まだ決まっていない送った配信を AI が分ける。直すのは配信カード(「この配信に使う学び」の帯)。詳しい結果では見るだけ(結果を読んでいる途中で、比べる相手が入れ替わらないように)。

### 5.14.1 効果(配信が売上を増やしたか、学びが効いているか)

- 結果の面の見せ方「**効果**」。絞り込みの国・チャネルの配信を、上の欄で選んだ**対象の期間**(配信日の開始〜終了。近道: すべて・直近 4 / 12 / 26 週・今年。既定は「すべて」。少ないと比べられないため)で見る。期間はブラウザごとに覚え、欄の右に、実際の最初〜最後の配信日・本数・測定の条件(購買を数えた日数・送らなかった割合)を出す。
- **増えた売上**: 送った人と送らなかった人(ホールドアウト)の、1 人あたりの売上(店舗・EC を含む、配信から 7 日)の差 × 送った人数。**リフト率**は、その差 ÷ 送らなかった人の 1 人あたり。率は国をまたいで比べ、金額は国ごと。詳しい結果の主な数字にも「増えた売上」「リフト率」が出る。
- **学びの記録**: 配信ごとに、AI の依頼に渡した学び(配信カードの「この配信に使う学び」)。表の右に、選んだ配信に渡した学びの中身。詳しい結果にも「この配信に渡した学び」。
- **学びの評価**: 学びごとに、その学びを渡した配信と、渡さなかった配信(同じ国・チャネル、その学びができたあと)の増えた売上を比べ、「残す / 外す / 様子を見る」のおすすめを出す(どちらかが 3 本未満は「材料不足」)。決めるのは人。
- 学びの評価は、国を選ぶと、その国の判定(残す / 外す / 様子を見るは、学びと国の組ごと)。
- いまは見本のデータ(設定の「開発・管理」→「見本のデータ」の「効果の見本を作る」)。本物のホールドアウトの数字の取り込みは、まだ(9 章)。

### 5.14.2 学び(学びのカード)

- 結果の「**次に生かすメモ**」は、1 つずつ**学びのカード**になる。結果の面の見せ方「**学び**」で、すべての学びをカード(手札)で並べる。
- カード: 名前(一言の見出し。空ならメモの 1 行目。「名前を付ける」「名前を直す」で、「AI に名前の案を出してもらう」もできる。保存したときだけ書く)・状態・メモ・**効く条件**(国・チャネル・種類・季節)・**強さ**(5 段。渡した配信と渡さなかった配信のリフト率の差から。比べる配信が 3 本未満は「材料不足」)・効き目・「使われた n 本」・最後に使った日・**根拠**(何本の配信から学んだか。押すと元の配信の結果)。よく使われ効き目も上向きの学びは、カードの左の縁が少し濃くなる(育つ)。演出はない。
- 手札の絞り込み・並べ替え: 名前・メモ・配信名で探す、チャネル・テーマの種類・状態、「○○のデッキだけ」、強い順・新しい順・よく使われた順。カードの … から、名前を直す・**使う / 休ませる / 外す**(国ごと。国の全員に効くので確かめる)。
- **似た学びをまとめる**: AI が似ている組を挙げ(同じ出元の国の中だけ)、人が組ごとに「まとめる」。まとめた学びは「根拠 n 本」になり、全文でまとめた学びが並ぶ。「元に戻す」で分けられる。
- **国のデッキ**: 学びは全部の国で共通に 1 つで、どの国で使うかは設定の「国」→「**使う学び**」(学びのカードで、この国の学びを先に、強い順)。出元の国は、決めていなければ使う。ほかの国の学びは、決めていなければ使わない。
- **配信カードの「この配信に使う学び」**(左のバーの「学び」): 同じチャネルで、同じテンプレートか同じテーマの種類の、この国で使い、休ませていない学び(新しい順)を自動で付け、AI の下書きに渡す。カードごとに「この配信では外す(AI に渡さない)」、「**学びを足す**」でこの国で使う学びから付けられる。ほかの国の「使えるかもしれない学び」には「この国で使う / 使わない」。「**効き目を見る**」で、その学びを渡した配信と渡さなかった配信の比べ(見立て・リフト率の差・クリック率の差・おすすめ・渡した配信・比べた相手)を、配信カードの上のフロートで見る(「結果の画面で開く」で結果の面の ④ 学びの評価へ)。

### 5.15 アラート
- **在庫切れの見込み・在庫僅少**: まだ送っていない配信に載っている商品について、配信日の在庫を、直近 4 週の販売の速さと、それより前の配信で上乗せされる販売から見込む。配信日に在庫がなくなる見込み、または何週分を切る見込みなら知らせる。
- **商品画像のモデルの使用期限**: 配信に載せた商品の画像(配信で選んだ画像、なければ商品のメイン画像)のモデルの使用期限が、配信日より前に切れる(切れている)と知らせる(期限が入っている画像だけ。期限は商品ページか、取り込んだ商品画像のデータから読む)。配信カードの左のバーのアラート・プレビューの枠の印・部品のペイン・商品のフロート(画像を替えるか、商品を入れ替える案内)に出る。
- **MD 方針の変更・日程の変更**: 商品の販売方針・位置づけ・販促の期間、配信日時が変わったら、変更の前と後を知らせる。
- **アラートのフロート**: ヘッダーの「アラート」で、いまの画面の上に重ねて開く(閉じれば、見ていた期間・見せ方・絞り込みのまま)。左に一覧(商品の画像つき。日程の変更は配信の画像)、右に、商品の画像・商品コードと、影響を受ける配信(日付・配信のサムネイル(マウスを重ねるとプレビュー)・チャネル・状態・載っている場所・配信日の在庫の見込み)。ここから開いた配信カードは、さらに上に重なり、閉じるとアラートに戻る。
- **対応**: 配信ごとに、**差し替え**(差し替える商品といまの在庫を上に出し、AI が、配信日に在庫が見込める同じカテゴリの商品を 3 つ提案。候補ごとに、いまの在庫・配信日に何週分・今週と前週に載せた回数)、**開く**(問題の商品を選んだ状態で配信カードを開く)、**延期**、**取りやめ**。変更の理由は記録に残り、確定・承認済みの配信はレビューに戻る。変更のアラートは「対応済み」にできる。
- **対応の記録**: 誰が・いつ・どう対応したか。
- **アラートの基準(国)**: 在庫僅少にする週数(1〜8 週分)・**週の上限**(同じ商品を、同じ週に何本の配信まで載せてよいか。既定 2 本)・販売順位の上位とみなす線は、**国ごと**の基準(設定の「国」→「アラートの基準」。国の全員に効くので、変えた人・日時を残す)。配信の国の基準を使う。マーケティングの決まりに「上限 週 N 回」があり、配信の国・チャネル・配信日に当てはまれば、そちらが優先(決まりは設定の「全社」→「方針・決まり」の「週の上限の決まりを足す」で、画面から作れる。どの国で使うかは「国」→「使う決まり」)。アラート・確認の一覧には「上限 3 本(決まり: 〜)」のように、どこから来た値かを出す。
- **アラートの条件(人ごと)**: 出す種類・対象にする種類(テーマの種類)・対象にする担当。人ごとに(ブラウザごとに)覚え、ヘッダーの件数にも効く。
- **マーケティングの決まりを画面で直す**(設定の「全社」→「方針・決まり」): ルール系の決まりを、画面で**足す・直す・消す**。項目は取り込みのファイルと同じ(番号・題名・対象・強さ・市場・チャネル・期間・確かめ方・本文)で、確かめ方は種類(上限 週 N 回・含めない・含める・除く 段階=)を選んで値を入れる。確かめは取り込みと同じ。「**週の上限の決まりを足す**」で、「同じ商品は週 2 回まで」のひな形から作れる。画面で足した決まりは「画面で作成」に入り、ファイルを取り込み直しても消えない。取り込んだ決まりを直すと、同じファイルを取り込み直したときにファイルの内容に戻る(取り込みの確かめで、戻る決まりの番号を知らせる)。「**Markdown に書き出す**」(すべて・ファイルごと)で、いまの決まりを取り込めるファイルにして、元のファイルを直せる。「**直した記録**」のタブに、日時・人・足した / 直した / 消した・変わったところ。
- 配信カードの「この配信のアラート」の帯、商品情報とカレンダーの印でも分かる。
- **配信カードの中での対応**: 帯の商品名・「対応する」、プレビューの商品の枠に重なる札(在庫切れ・在庫僅少など。枠が狭いときは印だけ)、商品情報の行の札の、どこから押しても、**商品のフロート**(5.9)が「このアラートへの対応」として開く。在庫のアラートは、左の AI の差し替え案(残りの候補・ほかの商品を探す、からも選べる)を押して右で詳しい情報を確かめ、「**差し替える**」で、その配信の中で商品を置き換える(**保存で確定**。保存しなければ元のまま。差し替えた理由(任意)は、保存のときに配信のメモに残る)。ほかに「**配信日を変える**」(左の配信日時の欄へ)と「**アラートの画面で詳しく**」(その商品のアラートを選んだ状態で開く)。方針・日程の変更は、アラートの画面で確かめて「対応済み」にする。

### 5.16 取りやめ・削除
- 配信カードの「⋯」のメニューから。
- **取りやめ**: 理由を残して、消さずに残す。カレンダー・週・一覧に、取り消し線と「取りやめ」の印で薄く出し、アラート・週の確認・件数からは外す。取り消すこともできる。
- **削除**: 間違いで作ったものだけ。元に戻せないことを確かめてから消す。

### 5.17 設定の画面(⚙)

- ヘッダーの ⚙ で開く**設定**の画面。左の並びから選び、右に中身を出す(大きさを変えられ、並びの幅も変えられる)。
- **自分の設定**(このブラウザに覚え、ほかの人には効かない): 言語(日本語 / English)・AI(テンプレートが見つからない配信カードを開いたとき、自動で下書きし直す)・ヒント(閉じた案内を「ヒントをもう一度出す」)。表示の大きさは、右上の「あなた」のメニュー(4.1)。
- **国: ○○**(ヘッダーの国。「すべての国」のときは、項目の中で国を選ぶ。国の全員に効く): **使う決まり**(全社のマーケティングの決まりのうち、この国で使うもの。AI の依頼と週の上限に効く)・**アラートの基準**(5.15)・**使うテンプレート**(見本の縮小を並べて選ぶ)・**使う学び**(5.14.2)・**配信の型**(曜日・時刻・チャネル・種類・テンプレートの組。「まとめて作る」が、この型どおりに行を作る。型は既定値で、行ごとに変えられる)・**差出人の名前・店の URL・計測用の値(utm)**(全社の既定を、この国だけ変える)。使う / 使わないを変えた記録(だれが・いつ)も見られる。
- **全社**: **差出人の名前・店の URL・計測用の値(utm)**(受信箱・メールの上の帯・アプリの通知に出す差出人の名前と、リンクの既定・商品のページの元になる店の URL。すべてのリンクに付ける utm_source・utm_medium(メール用・アプリ用。既定は newsletter・email・app。2026-10-28 に配信カードの ⑤ から移した。前から配信カードに上書きがある配信は、その値のまま。制作に渡すと、そのときの値を写しに残すので、あとで変えても渡した URL は変わらない)。国で上書きできる)・**方針・決まり**(5.15)・**テンプレート**(5.10)・**画像のライブラリ**(5.4)・**ユーザーと承認グループ**(承認の決まりもここ。5.12)。
- **開発へのリクエストの一覧**(5.18)。
- **開発・管理**(畳んである。ふだんの作業では使わない): 取り込み・書き出し(BigQuery から取り込む・商品・カテゴリの指標を取り込む(CSV)・データと画像を書き出す(別の環境へ移す)・商品・メイン画像の写真の ZIP を取り込む・種類が未設定の配信を、AI で分ける)・見本のデータ(外部広告・効果・素材・見本の SKU の見本を作る / 削除・AB テスト・案から選ぶの例を作る・配信の型の見本を作る(US))・見本の商品ページ(見本の商品ページと、載っている画像の一覧。商品ごとに写真の種類・説明・モデルの使用期限。押すと見本の商品ページを新しいタブで開く)。
- **全社の決まり + 国ごとの使う / 使わない**: テンプレート・学び・マーケティングの決まりは、全社で 1 つずつ持ち、国ごとに使うかだけを決める(国ごとに写しを作らない)。決めていなければ、テンプレートと決まりは使う(決まりは、書いてある市場の国だけ)、学びは出元の国だけで使う。

### 5.18 開発へのリクエスト

- 画面のどこでも、右クリック →「**開発に伝える**」で、その場所にピン(墨色のひし形に黄色の電球)を打ち、フロートで「直してほしいこと・足してほしいこと」を書く(名前は初めの 1 回だけ聞き、ブラウザが覚える)。書いたときの様子(その場所の画像)も残る。
- ヘッダーの「**リクエスト**」(ヘッダーを隠すフロートでは「⋯」の「開発へのリクエストの一覧」)で一覧を開く: 「まだ済んでいない(n)/ 未対応 / 検討中 / 対応中 / 対応済み / 見送り / すべて」、並べ方(新しい順・賛同の多い順)、「この画面を開く」(その画面を開いてピンを見せる)、「まとめてコピー」(添付の画像は開ける URL で入る)。ヘッダーの「リクエスト」の横の目の印で、ピンを出す / 隠すを切り替えられる(人ごとに覚える。隠しても、一覧と右クリックの「開発に伝える」は使える)。
- 返信・**賛同**(1 人 1 回。もう一度押すと取り消す)ができ、状態は 未対応 / 検討中 / 対応中 / 対応済み / 見送り。画面に出すピンは、まだ済んでいないもの(未対応・検討中・対応中)だけ。
- リクエストにも返信にも、**画像**(書く欄に貼り付け・ファイル)と **URL** を付けられる。画像を付けると「個人情報・機密が写っていないか」を一言出す。本文・返信の URL は押して開ける。送らずに閉じた画像は消す。Workbench の取り込み(import-pack)で DB を入れ替えても、添付の画像ごと残る。画面の作りが変わってピンの場所が見つからないリクエストは、左下の置き場に、書いたときの場所の文で出す。いまは、だれでも削除できる(フロートの「⋯」と一覧の「削除」)。
- 使っている人みんなが見る所なので、設定の画面でも、畳んだ「開発・管理」の外に置く。

### 5.19 使い方を AI に聞く(「？ 聞く」)

- ヘッダーの「**聞く**」(？ の印)で、どの画面からでもフロートを開き、やりたいことや分からないことを書くと、AI が答える(チャットの形。Enter で送る、Shift + Enter で改行)。画面が English なら英語で答える。
- 答えは、① 手順(画面にある実際のボタン・欄の名前を太字で)② 「**ここを開く**」(その画面へ移るボタン。計画・制作・結果の面と見せ方、アラート)③ 「**根拠**」(畳んである。どの機能の説明をもとにしたか・関係するファイル)。材料で分からないことは「分からない」と答える。
- 材料は、この機能の説明の文書(FEATURES・SOURCE_MAP・FEATURE_REASONS)と、画面に出ている文言の一覧(ビルドのたびにソースから作る)。答えの中の名前が画面の文言の一覧にないときは、太字にせず点線を引く(画面では違う名前かもしれない印)。
- 画面のどこでも、右クリック →「**ここについて聞く**」で、押した所の部品について聞ける(フロートの下に「この部品について: ○○」の札。✕ で外すとふつうの質問に戻る。例「これは何?」「ここで何ができる?」「ここを変えたい」)。
- **スポットライト**: 「ここを開く」で画面を移ると、手順にあるボタン・欄(太字の名前)を、その画面の中で黄色の脈打つ枠で光らせる。画面を移らずに場所だけ知りたいときは「**画面で示す**」。8 秒たつか、どこかを押すと消える。見つからないときは、画面の下に「この画面には、答えのボタン・欄が見つかりませんでした」。
- 答えの下の「**開発に伝える**」で、質問と答えを書きかけにして、開発へのリクエストを書き始める(右クリックから聞いたなら、その点にピン。5.18)。
- 質問と答えは、よく聞かれる質問を作るために保存する(だれが聞いたかは残さない)。フロートの最初の画面に、よく聞かれる質問が出る(押すと、その答え)。

## 6. AI の仕組み(概要)

- AI は、**Google の Gemini**(Vertex AI)。アプリが、必要な情報(配信の国・日時・テーマ、候補の商品・画像、過去のメモなど)を渡し、AI が**候補の中から選ぶ**・**文案を出す**。商品・画像を作り出すことはない。
- AI を使う場面: 下書き(テーマ・テンプレート・メイン画像・文言・セクション・制作指示・件名・アプリの文言)、まとめて作る、配信カードの部品ごとの依頼(文言の案と指示して直す・メイン画像・商品・セクションの商品・配信の全体・制作指示)、使い方を AI に聞く(5.19)、よく聞かれる質問のまとめ、AI チャット(制作のページ)、テンプレートを AI で作る、学びの名前の案と似た学びのまとめ、AB テスト・案から選ぶの B・C 案、アラートの差し替えの候補、タスクの案、テーマの種類の分類、振り返り(配信ごと・週・月)、比べるの評価、上げた画像の名前・タグ・説明の下書き(画像を見て)、商品ページの画像のアングルを見分けて配信に合う画像を勧める。
- 在庫・売上トレンド・評価・季節・天候・週次の実績・MD の方針・配信の結果は、**アプリのデータベース**に取り込んだデータを元にする。

## 7. データ(初期のサンプルデータ)

動かし始めたときに入っている、架空のサンプルデータ。実際の商品・画像・実績を取り込めば、それに置き換わる。

| データ | 内容 |
|---|---|
| 商品 | JP 30点(円)、US 30点(ドル)。カテゴリ: アウター / トップス / ボトムス / シューズ / 小物 / バッグ / ホーム |
| メイン画像 | JP 20点、US 20点(新作 / 特集 / セール / 会員 / イベント) |
| 配信カード | US 向け・JP 向けの、2026年9〜10月の予定 |
| 週次実績 | 全商品 × 12週(販売数、売上、在庫) |
| 販売方針 | 全商品(MD の方針、販促計画、期間、位置づけ) |
| 配信の結果 | 送った配信の結果(開封・クリック・売上、リンクごとのクリック) |
| 画像 | サンプル用のイラスト(実際の商品写真ではない) |

サンプルデータは、すべて**架空のデータ**。

## 8. 技術(概要)

- ブラウザで使う Web アプリ。画面は React + TypeScript。デザインは **Fluent 2**(Microsoft の UI)。
- サーバーは Python(FastAPI)。データは **PostgreSQL**、AI は **Google の Gemini(Vertex AI)**。
- 同じアプリを、クラウドのサーバーでも、社内のデータ分析環境(ノートブックの環境)でも動かせる。データと画像は、動かす環境ごとに持つ(引っ越し用のファイルで、データと画像をまとめて移せる)。
- 本物のログインは、まだない。右上の「あなた」で選んだ人を、ログインしている人とみなし、承認・やり取りの「誰が」に残す。アクセスは、パスワードなどで守る(動かす環境に合わせる)。

## 9. 未実装・制限(**できないこと**)

- 制作のページの「配信のしくみに送る」は、送り先の窓口だけで、実際にはまだ送らない(送り先のしくみが決まったら、窓口の中を作る)。書き出す HTML は、プレビューと同じ見た目の下書き(表で組んで書式を直接書いた、配信のしくみにそのまま入れる完成品ではない)。
- 商品の性別(配信の対象で商品を絞るのに使う)は、データの側にまだ入っていない環境がある。入っていない商品は、どの対象にも出る。
- **メール・アプリの実配信**は、しない(このアプリは、配信内容の**企画・レビュー・振り返り**まで。配信システムとは連携していない)。結果は、取り込みで入れる。
- **通知**(レビューに出した・引き継いだ、などを、メール・チャットで知らせる)は、しない。
- 商品の売上・在庫・方針・画像は、**取り込んだデータ**を使う。基幹システムとの自動の連携はない。
- **変更の履歴**(4.3): 配信カードの中身の項目の変更は残るが、**載せた商品の足し外し・並べ替え**は、まだ残らない(差し替えの理由は残る)。
- **制作の依頼の承認の止めは、当面外している**: 承認の前でも制作のページを開いて依頼できる(4.6)。実際の運用で使い始めるときに、承認済みからだけに戻すかを決める(戻しても、それまでに依頼した写しはそのまま残る)。
- **テンプレートの部品 ID**(途中): 部品 ID を持つのは、表の形で保存したテンプレートから(以前の版は、そのまま描く)。配信カードの見出し・コピーは、これまでどおりセクションの番号で持つ(セクションのピンは、セクションの ID でも探す)。テンプレートの部品の書き換え(5.3)は、画像の URL を手で入れる欄がなく(ライブラリから選ぶ・上げるだけ)、AI の下書きは部品の文を書かない。テンプレートごと・部品ごとの成績の比べは、まだ。**AI でテンプレートを作る**のは、メールのテンプレートだけ(アプリはまだ)。
- **箱のセールの見せ方**: 元の価格(商品の `regular_price`)は、BigQuery の取り込みにまだ入れていない。入っていない商品は、取り消し線なしの赤い価格になる。
- **配信カード**: 商品をカテゴリでまとめる・カテゴリの見出しを出す、リンク先を一覧でまとめて直す、AI とのチャット(配信カード全体で自由に頼む)は、詳しい配信カードを消したときに、なくした(2026-10-28 利用者。代わりは、部品ごとの AI と「AI で全体を下書きする」)。
- **プレビューのピン**: 書いたときの様子の画像は、よそのサーバーの画像だと写らないことがある(そのときも、文字で「変わった」かを比べる)。
- **制作のページの AI チャット**: 見た目の直しは、HTML の中の文字の置き換えで行うので、AI の返す直しが HTML に一字一句当たらないと、その直しは入らない(知らせる)。会話は保存しない。
- **商品ページの画像を選ぶ**: 外に出られない環境では、本物の商品ページを読めない(画像のコピー&貼り付け・ファイル・画像の URL で選ぶ)。いまのデータの商品ページの URL は仮のものなので、見本の EC サイトのページを読む。
- **リンクごとの計測用のパラメーター(utm_content)**: URL に付けるだけで、リンクごとのクリック・売上の取り込みにはまだつないでいない。アプリの通知の data には content を付けていない。もう制作に依頼した配信の URL は、前の作り方のまま。
- **月の表示でのドラッグによる日付の移動**(週の「時刻」の見方では動かせる)、**祝日などの予定の重ね合わせ**は、まだない。
- **AI に頼むときの会話の保存・再開**はできない(画面を閉じると消える)。**条件のピン留め**(以後のすべてのAI生成に効かせる)も、未実装。
- 承認できるのは、依頼で指名された人と承認グループのメンバーだけ。ただし本物のログインはなく、右上の「あなた」で人を選べば、だれでもその人として押せる。
- AI の案は、**採用するまで反映されず、保存もされない**(一部の選定は、反映して「元に戻す」)。
- 商品が数千件以上の規模では、読み込み・検索・AI の候補の絞り込みの対策が、今後必要。
- AI の返答は、毎回同じとは限らず、まれに形式が崩れて、自動でやり直すことがある。
- AI の利用には、費用(従量課金)が発生する。
- **効果**の数字は見本だけ(本物のホールドアウト(送らなかった人)の数字は、配信の仕組み・データ基盤と調整してから取り込む)。
- **キャンペーン**: キャンペーンを作るのは、ヘッダーの新規作成だけ(まとめて作る・週の枠で作った配信は、キャンペーンに入らない。キャンペーンに入っていない配信は、これまでどおり 1 枚ずつ並ぶ)。配信カードを別のキャンペーンへ移す・キャンペーンを分ける・キャンペーンごとまとめて取りやめる、はできない。結果の面で、キャンペーンの合計 → 配信 → 案の順に見る画面は、まだない(計測用のパラメーターも配信カードの単位)。週の状態・週の上限は、配信カードの単位。
- **学びのカード**: 強さ・効き目は、効果のデータ(いまは見本)から計算する。
- **開発へのリクエスト**: だれでも削除できる(書いた人に限らない)。
- **使い方を AI に聞く**: 質問と答えは、よく聞かれる質問を作るためだけに保存する(会話そのものは保存しない。だれが聞いたかは残さない)。答えの「ここを開く」で開けるのは、面と見せ方・アラートまで(設定の画面や、配信カードの中の場所は開けない)。光らせるのは、いま画面に出ているボタン・欄だけ(タブの奥・畳んだ所・メニューの中は、開くまで光らない)。
- **案から選ぶ**: 承認の画面では案を選べない(配信カードの案の段で決める)。「B 案を AI で作る」は、比べる要素に文言があれば、選び直した画像・商品に合わせて、A 案と違う切り口の文言(ヘッドライン・コピー・セクションの見出しとコピー・件名とプリヘッダー、アプリなら通知の文)も作る(2026-10-21)。決める前は、制作に依頼できない(制作のページの「この内容で依頼する」と「制作を通さずに、配信のしくみに送る」が押せず、① の段に「1 案に決めてから依頼できます」。2026-10-21 利用者の判断)。


## 10. デモの流れの例(約10分)

1. **カレンダー**を見せる: 色分け、メールとアプリの見分け、絞り込み(国 = US)、日英の切り替え。
2. 空の配信カードを開く → 真ん中の「**AI で下書きする**」→ 進み具合 → 結果(テーマ、メイン画像、ヘッドライン・コピー、セクションの商品、制作指示)。
3. **プレビュー**: ヘッドラインを押して「AI で変える」→ 案を押して試す → 確定。セクションの名札を押して「グリッド1 の商品を AI で選ぶ」。
4. 商品の ⇄ →「**AI に頼む**」で「レインブーツを必ず入れて」→ 試す → 確定。
5. 右の**商品の一覧**の商品を押す → **売上・在庫のグラフ**、MD の方針。
6. **週の表示**: 確定の前に直すこと → 項目を選ぶ → やり取り → 承認(配信カードの左のバーの「承認」) → 週を確定 → PDF。
7. **アラート**: 在庫切れの見込み → 影響を受ける配信 → AI の差し替えの候補で差し替え。
8. **結果の面**: 月のカレンダー → 詳しい結果のヒートマップ → 過去の配信と比べる → AI で振り返る → メモに採用 → 次の配信カードの「この配信に使う学び」。
9. **English に切り替え**: 画面と AI の出力が英語になる。
10. ヘッダーの「**聞く**」で「承認を依頼するには?」と聞く → 手順と「ここを開く」。
