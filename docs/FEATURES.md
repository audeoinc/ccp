# 機能説明

「Campaign Contents Planner(CCP)」の機能の説明。
画面の用語は、実際の画面の表記(日本語 / English)に合わせてある。**「未実装・制限」の章に書いたことは、できないこと。**
機能ごとの「なぜその機能があるか」は、[FEATURE_REASONS.md](FEATURE_REASONS.md)(機能の理由の台帳)を参照。

---

## 1. 一言で

メール・アプリの**配信コンテンツ**(テーマ、メイン画像、ヘッドライン・コピー、セクションごとの商品、制作指示)を、**AI の提案を選びながら**企画し、**週ごとにレビュー・承認**し、送ったあとの**結果を振り返る**アプリ。
配信前には、在庫切れや方針の変更などの**アラート**で、事故を防ぐ。US チームと JP チームが、日本語・英語のどちらでも使える。

## 2. 解決する課題と、価値

| 課題 | このアプリでの解決 |
|---|---|
| 企画の素案づくりに時間がかかる | 「すべてAIで下書き」で、テーマから制作指示まで一度に下書きを作る。週の表示で、週の枠を作って配信名と種類を入れ、まとめて AI で中身を作ることもできる |
| 商品の選定が属人的 | 在庫・売上トレンド・評価・季節・天候などを踏まえた AI の選定と、**その理由**を表示する |
| 国ごとに、商品・言語が違う | 配信カードの「国」(US / JP)に合わせて、商品・画像・コピーの言語を使い分ける |
| デザイナーが、商品情報を探し回る | 商品情報ペインで、掲載商品の情報を一覧し、売上・在庫の推移や MD の方針も見られる |
| メールの構成を、毎回、作り直す | テンプレート(構成の型)を選ぶ。自分でも作って、チームで共有できる |
| AI の案が、気に入らない | チャットで指示を足して、案を作り直す(「この商品を必ず入れて」など) |
| 週の計画のレビューが、資料づくりと確認で重い | 週の表示で 1 週間をまとめて見て、確認の一覧(同じ商品の回数・主力の漏れなど)・コメント・承認までを同じ画面で行う。資料は PDF で書き出す |
| 配信のあとで、在庫切れや方針の変更に気づく | 配信前の在庫の見込みと、方針・日程の変更を**アラート**で知らせ、差し替え・延期・取りやめまでその場で対応する |
| 振り返りが、次の企画に生きない | 結果をカレンダー・一覧・ヒートマップで振り返り、「次に生かすメモ」を、次の配信カードと AI の案に渡す |

**人が決める、AI は提案する**、という立場。AI の案は、**採用するまで反映されない**(一部は、反映して「元に戻す」で戻せる)。

## 3. 想定する利用者

- **企画担当(販促・CRM・EC)**: 配信を企画し、AI の案を選んで、内容を決める。週の計画をレビューに出す。
- **レビュー・承認する人**: 週の計画を見て、コメントを残し、承認・差し戻し・週の確定をする。
- **デザイナー・制作担当**: 決まった内容(ヘッドライン、コピー、商品、制作指示、リンク先)と商品情報を見て、制作する。質問を返す。
- **MD(商品担当)**: 商品の販売方針・販促計画を、AI の選定と制作の判断に使えるようにする(データとして登録されている)。
- 国: **US チーム / JP チーム**。

## 4. 画面の流れ

### 4.1 ヘッダーと、共通のツールバー

- **リンクで画面を伝える**: 面・見せ方・期間・国と、開いているフロート(配信カードとその工程のタブ・詳しい結果・アラートの商品・制作のページ)を、URL に持たせる。フロートの右上の「**リンクをコピー**」で写して送ると、相手も同じ画面で開ける。ブラウザの「戻る」でフロートが閉じ、再読み込みしても開いたまま。リンクの国は、そのときだけ合わせる(ふだんの国の設定は変えない)。リンクの配信が見つからなければ、知らせていつもの画面で開く。

- ヘッダー: アプリ名、**国**(「すべての国 / US / JP」。どの国の仕事をしているか。画面のすべて(計画・結果・週の帯・アラート・依頼の件数・新規作成の既定の国)に効き、人ごと(ブラウザごと)に覚える。全体を見る人は「すべての国」)、**[計画 | 結果]** の切り替え、「**アラート**」(未対応の件数。在庫切れがあれば赤)、「**依頼**」(自分宛ての承認の依頼)、「**＋ 新規作成 ▾**」(本体で 1 本作る。▾ から「この週の枠を作る」(5.1.1))、「**あなた**」(履歴・依頼・承認に残す人。ユーザーが登録されていれば選んで切り替え(デモ)、「**ログアウト**」で最初の「だれでログインしますか?」に戻る。1 人も登録されていなければ名前の入力)、**⚙**(システム全体の設定: テンプレートの管理・ユーザーと承認グループ・方針と決まり・BigQuery からの取り込み・データと画像の書き出し・言語・開いたとき自動で下書き)。
- ツールバー(計画と結果で共通。切り替えても、期間・見せ方・絞り込みはそのまま):
  - 絞り込み: **チャネル / 種別 / ステータス / 担当**(国はヘッダー。ステータスは計画の面だけ。結果の面は送ったあとの配信なので出さない)。名前を札の中に入れた 1 行の細い札(「国: すべて ▾」)で、すべて見えたまま。「すべて」以外を選んでいる札は、色が付く。担当は、企画・制作の担当のどちらか(5.13 も)。
  - 期間: ‹ › で移動。期間の文字(例: 2026年10月)を押すと**ミニカレンダー**が開き、月・週・日へ移れる。
  - 見せ方: **[月 | 週 | 一覧 | 比べる]**(「比べる」は結果の面だけ)。計画の面の週のときは「週の見方」(**商品 / 進み具合**。結果の面では出さない)。
  - ツールバーの右端に「**この画面 ▾**」: いま見ているものへの操作をまとめたメニュー(どの面・見せ方でも同じ位置)。計画: まとめて AI で下書き(週の表示: この週。月・一覧: この月の空いている週 = 配信がいちばん少ない確定前の週に移って始める)・配信を CSV で書き出す(表示中の月・週)・週の資料を PDF で書き出す・この週の承認の履歴(週の表示のとき)・表示する列(一覧のとき)。結果: 結果の CSV の書き出し・結果の取り込み・取り込みの見本・AI でテーマの種類を分ける。
- 国: US / JP。チャネル: **メール / アプリ**。種別: **販促 / CRM / EC**。
- ステータス(4段階・色分け): **未起案 → 検討中 → 承認済み → 確定**。

### 4.2 計画の面

- **月**: カレンダーに配信が並ぶ。1 行目はチャネルの印と名前、2 行目は時刻・国・チャネル。**ステータスの色**(左の線と薄い色)で状態が分かる。メールとアプリは、名前の前の**塗りつぶしの印**(メール = 青の地に白い封筒、アプリ = ベリー色の地に白いスマートフォン)で見分ける。
  - 印: アラートのある配信、配信日が近いのに未着手の配信、取りやめた配信(取り消し線で薄く)。
  - 各週の先頭(日曜日)の「**週 ›**」を押すと、その週の週表示に移る(結果の面でも同じ)。
  - 上に「**月の要約の帯**」(見るだけ): この月の配信の状態ごとの件数(未起案 › 承認待ち › 承認済み n / 全体)と「確定した週 n / n」。「確定した週」を押すと、確定していない最初の週の週表示へ。一覧の表示にも同じ帯。
  - **日付のマスを押すと、その日の 10:00 を配信日時にして、新規作成**が開く(マウスを乗せると「＋」が出る)。絞り込み中の国・チャネル・種別も最初から入る。
- **週**: 1 週間の配信を、日ごとに、縮小プレビューつきで並べる(箱の上の帯が、メール = 青、アプリ = ベリー色の塗りつぶしに白抜きの文字・アイコン)。上に、週の状態(と状態ごとの件数)とレビュー・確定の操作を並べた**週の帯**(5.12)。
  - 週の見方「**商品**」は、載せた商品の画像、「**進み具合**」は、工程の進み具合を出す。
- **一覧**: 配信を表で並べる。左にサムネイル(マウスを重ねるとプレビュー)。列見出しで並べ替え、表示する列を選べる。**CSV で書き出す**。
- どの見せ方でも、配信を押すと、**配信カード**が開く。

### 4.3 配信カードの編集画面(ダイアログ)

**4つのペイン**で構成する。ペインの境界はドラッグで幅を変えられる(幅は保存される)。

| ペイン | 内容 |
|---|---|
| ① 左: 配信情報 | 青い大きなボタン「**すべてAIで下書き**」。配信名、配信日時、国、チャネル、種別、ステータス、担当者。制作への引き継ぎ(担当・締め切り・引き継ぎ済み)は表示だけで、押すと「やり取り → 引き継ぎ」のタブが開く。「工程」として、テーマ・ヘッドライン・コピー(それぞれ、AI の理由・切り口つき)。制作指示は、中ペインの ⑥ で作り、右のプロセスのペインの引き継ぎで確かめる |
| ② 中: コンテンツ生成 / やり取り | 上の切り替えで、2 つの面を切り替える。**コンテンツ生成**: 6つの工程のタブ(メール: テーマ / テンプレート / ヒーロー / セクション / リンク先 / 制作指示。アプリ: テーマ / テンプレート / 通知 / メッセージ / リンク先 / 時刻・相手)。幅に収まらないときは番号(①〜⑥)だけになり、名前はマウスを重ねると出る。下半分に、**AIチャット**。**やり取り**: **引き継ぎ**(質問と返信を含む)・**タスク**・**コメント**のタブ(AIチャットはない)。切り替えには、未対応の質問・タスク・コメントの数が出る。面ごとに、最後に開いたタブを覚える |
| ③ 右: プレビュー | メール / アプリ(通知とメッセージ)のプレビュー。倍率の変更(スライダー、「全体」ボタン) |
| ④ 右端: 商品情報 | 掲載商品の参照用の一覧。**既定では開いている**(右上の「>」で、右端の細い帯に折りたためる) |

- 題名の左: **チャネルの札**(メール = 青の封筒、アプリ = ベリー色のスマートフォン。週の表示の配信の帯と同じ色)。開いた瞬間に、どちらの配信かが分かる。見るだけ(変えるのは左の「チャネル」)。
- 題名の横: 工程の進み具合「**工程 n / 6**」、送ったあとの配信なら「**結果を見る**」、「**…**」のメニュー(取りやめ・削除)。
- 題名の下: 「**この配信のアラート**」の帯(ふだんは 1 行にたたみ、種類ごとの件数だけ。「見る」で開く。アラートの画面から開いたときは開いた状態。問題の商品を押すと、プレビューで目立ち、そのまま「このアラートへの対応」が開く。行ごとの「対応する」でも開く)、「**これまでの学び**」の帯(同じテンプレート・テーマの種類の、過去の配信のメモ)。
- 下: 「あなたの名前」「**保存して承認**」「**差し戻す**」「キャンセル」「**保存して次へ**」「**保存**」。確定した週の配信は、保存に理由が必要。
- 「保存して次へ」は、保存したあと、閉じずに次の配信を開く。週の表示で確認の一覧の項目を選んでいれば、その項目の配信の中で、それ以外は同じ週の中で、配信日時の順。次がないときは、押せないだけ。
- **AI の案は、保存しない**(画面を開いている間だけ)。保存されるのは、採用した内容と、その補足(理由・切り口)。

### 4.4 結果の面

- 計画の面と同じ見せ方(**月 / 週 / 一覧 / 比べる**)で、送った配信の結果を見る(5.14)。
- 配信を押すと、**詳しい結果**が上に重なって開く。
- 月・一覧の上に「**この月**」の要約の帯(配信の数と結果のある数・売上・前月比・前年比・開封率・クリック率。国が混ざるときは、金額と増減を通貨ごとに)。チャネルは、計画の面と同じ塗りつぶしの札(週の箱・一覧の列・詳しい結果の題名の左・比べるの列)。

### 4.5 アラートの画面

- ヘッダーの「アラート」から開く。左にアラートの一覧、右に影響を受ける配信と対応の操作(5.15)。

## 5. 機能の詳細

### 5.1 すべてAIで下書き
- 左ペイン上部のボタン。**テーマ → テンプレート + メイン画像 → ヘッドライン・コピー → 各セクション(見出し・コピー・商品)→ 制作指示**の順に、AI の第1候補で、下書きを作る(アプリの配信は、通知・メッセージの文言)。
- 進み具合が、全画面の「AIが下書きを作っています」で表示される(「スキップして開く」で中断できる)。
- 結果は、**画面に反映するだけで、保存はしない**。気に入らなければ、保存せずに閉じられる。
- 1回で、AI を **6〜9回**呼ぶ(セクションの数による。所要時間は、数十秒程度)。
- 前提: 配信日時が入っていること。
- **自動下書き**: ⚙ の「開いたとき自動で下書き」がオンのとき、**テーマも商品も空のカードを開く**と、自動で下書きを始める(同じカードで1回だけ)。
- 下書きには、「これまでの学び」(過去の配信の、次に生かすメモ)も渡す。

### 5.1.1 週の枠と、まとめて AI で中身を作る
- ヘッダーの「**新規作成 ▾**」の ▾ から「**この週の枠を作る**」(週の表示のときだけ選べる。確定した週では選べない)。「新規作成」の本体は、1 本作るだけ。
- まず、この週に作る配信の、**国とチャネル**を 1 回だけ選ぶ(既定は、画面の絞り込み)。この週の、その国・チャネルの配信がない日(今日以降)が出て、その日に、中身のない配信カード(**枠**。未起案)を 1 本ずつ作る。いらない枠は消せる。
- 枠は、週の表示で、破線の枠と「枠」の印で出る。その場で、**配信名**と**種類**(値下げ・期間限定価格・セール・新作・コラボ・会員向け・季節の特集・再入荷・その他)を入れる(すぐ保存)。配信名は、AI の案を 1 枠ずつ、または帯の「名前のない N 本に、配信名の案を入れる」で、まとめて出せる。
- 配信名と種類が入った枠は、中身を作れる。帯の「**そろった N 本の中身を作る**」「**選んだ N 本の中身を作る**」(枠のチェック)、または枠ごとの「作る」。AI は、配信名と種類に沿って、テーマ・テンプレート・メイン画像・見出し・コピー・商品・制作指示を作る(同時に 3 本まで。すでにある配信とテーマ・商品が重ならないように)。
- 作った中身は保存され、「**AI 下書き・未確認**」の印が付く。印を押すと、右に引き出しが出る。[**中身**]: プレビューと全項目・AI の理由。[**比べる**]: 同じチャネルのすぐ前・すぐ後と、同じ日のもう一方のチャネル(重なる商品は枠、同じテーマは印)。「**確認した**」で印が外れる。「開いて直す」で配信カードを開いて直し、保存しても印は外れる。
- 「確定の前に直すこと」に「未確認の AI 下書き」が出る。承認の履歴に「AI でまとめて作成した」が残る。
- 週の帯の「まとめて依頼」は、中身のない枠を依頼しない。未確認の AI 下書きが入っていれば、依頼の前に知らせる。

### 5.2 ① テーマ(配信全体の前提。メールには出ない)
- 「AIで案を出す」で、テーマの案を **3つ**出す(各案に、理由つき)。ほかの配信と重ならないテーマを出す。
- 案から「採用」を押すと、「現在のテーマ」に入る。採用中の案の**理由**(「AIの理由」)は、保存され、あとで見られる。
- 手で書き換えると、理由は消える(文と理由が食い違わないように)。

### 5.3 ② テンプレート(メールの構成の型)
- 一覧から選ぶ。選ぶと、③④のセクションの構成が変わる。
- **標準のテンプレート 10種**:
  | 名前 | 構成 |
  |---|---|
  | 自由(カテゴリ見出しを自動) | 商品の数に決まりがない |
  | Standard Hero + 4 Grid Items | メイン画像 + 2×2 の商品 4点 |
  | Collaboration Hero + 2 Features + 2 Grid | コラボ用ヒーロー + 特集 2点 + グリッド 2点 |
  | Price: Limited Offer & Value Hero | 赤基調のヒーロー + 価格を強調した 4点 |
  | Standard Hero + 2 Category | カテゴリ 2つ(各 2点)。カテゴリごとに見出し |
  | Standard Hero + 3 Category | カテゴリ 3つ(各 2点)。カテゴリごとに見出し |
  | セール(大きく 1 点 + グリッド) | お知らせ帯 + 文字を大きく重ねたヒーロー。大きく 1 点とグリッドを交互に、最後に写真だけのタイル(12点) |
  | 特集(モザイク + グリッド) | 大 1 点 + 小 2 点のモザイク + 見出し付きグリッド(7点) |
  | ストーリー(写真 + 文) | 写真と商品の説明を左右交互 + 見出し付きグリッド(7点) |
  | コレクション(大きな写真中心) | 大きな写真・モザイク・3 列グリッド(11点) |
- **アプリのテンプレート**(標準 4 つ: お知らせ / 特集 / 商品の紹介 / セール): 「通知の形(テキスト / 画像 / 商品 1 点 + ボタン)」と「メッセージの本文(メールと同じ部品)」の組。
- **セクションの部品**(テンプレートを作るとき): グリッド(2 / 3 列)、写真だけ(2 / 3 列)、大きく(全幅)、モザイク(左が大 / 右が大)、ストーリー、特集。どれにも、見出し(AI が作る)とコピーの有無を決められる。**ボタン**は、セクションとは別の部品で、好きな位置(ヒーローの直後、セクションの間、最後)に 1〜2 個ずつ置ける。ボタンごとに、文言・見た目(塗り / 枠線)・リンク先の種類を持つ。ヒーローは、ヘッドラインの見せ方(帯で重ねる / 大きく重ねる / 写真の下)、画像のリンク先の種類、お知らせ帯を選べる。
- 構成のプレビューは、メールに近い縦長の見取り図で表示する。
- AI も、テーマや時期から、**テンプレートを選べる**(「すべてAIで下書き」のとき)。

### 5.4 ③ ヒーロー(メイン画像 / ヘッドライン・コピー)
- **メイン画像**: 登録済みの画像から、AI がテーマ・季節・用途・タグに合う画像を選ぶ。選定理由つき。候補が3件まで出る。「元に戻す」で戻せる。一覧から手で選ぶ、ドラッグ&ドロップでプレビューに置く、もできる。画像は、国(JP / US)に合うものだけが対象。
- **ヘッドライン・コピー**: 「ヘッドライン」(メイン画像の上に載る大見出し)と「コピー」(その下の導入文)を、**組で** 3案出す(各案に「切り口」つき)。言語は、配信の国に合わせる(US は英語、JP は日本語)。「採用」で、両方が反映される。
- プレビューでは、ヘッドラインが**自動で縮小して、1行に収まる**。

### 5.5 ④ セクション(見出し・コピー・商品)
- テンプレートのセクションごとに、**サブタブ**がある(例: グリッド / 特集 / セクション1 …)。
- 各セクションは、3つのブロック: **① 見出し(切り口)**(カテゴリ系のテンプレートのみ)/ **② コピー** / **③ 商品**。
- 「**このセクションをまとめてAIで選定**」で、見出し・コピー・商品を一度に選ぶ。各ブロックにも、「作り直す」「選び直す」がある。
- **商品の選定**: AI が、在庫(少ないものは避ける)、売上トレンド、評価、季節、天候、テーマ、メイン画像・ヘッドラインとの整合などから選び、**理由**を表示する。選定済みの商品と、「残りの候補」(最大3件)が出る。1 つの配信の中で、同じ商品を複数のセクションに入れない。
- 商品の操作(このタブだけで行う): 並べ替え(矢印、ドラッグ)、「外す」(候補へ戻る)、候補の「選ぶ」、理由の編集、**すべての商品から探す**(検索。検索語かカテゴリを指定すると、商品が出る。20件ずつ表示)。
- 商品は、配信カードの**国に合う市場(JP / US)のものだけ**が、AI の対象と検索の対象になる。
- AI の選定結果は、そのまま反映され、「**元に戻す**」で復元できる。

### 5.5.1 ⑤ リンク先
- メール: メイン画像・ボタンごとの URL と、計測用のパラメーター。アプリ: 開くアプリの画面(5.6.1)。詳しくは 5.13。
- リンクの場所すべてに行き先が決まったら、完了(テンプレートの既定の行き先も含む)。「配信カードで指定」のボタンは、配信ごとに決めるまで未完了。

### 5.6 ⑥ 制作指示
- 制作担当に渡す指示文の案を **3つ**出す(各案に、方針の「切り口」つき)。目安は、日本語で200〜240文字。
- 採用すると、左ペインにも反映される。理由・切り口は、保存される。

### 5.6.1 アプリの配信の工程(③ 通知 / ④ メッセージ / ⑤ リンク先 / ⑥ 時刻・相手)
- **③ 通知**: 通知のタイトル・本文の案を、AI が出す(文字数と上限を表示)。
- **④ メッセージ**: アプリの中のメッセージボックスに届くメッセージ。メールと同じ部品(メイン画像・見出し・セクション)で作る。
- **⑤ リンク先**: 通知は Firebase Cloud Messaging(FCM)で送る想定。開く画面は URL ではなく、通知の data に入れる **screen(画面の名前)と、画面に渡す値**で伝える。
  - 通知を押したときに開く画面: このメッセージ・配信のページ・紹介する商品・カテゴリ・アプリのホーム・画面の名前を指定。
  - メッセージのメイン画像・ボタンごとに開く画面: 既定は、テンプレートのリンク先の種類から決まる(配信のページ → 配信のページ、カテゴリのページ → カテゴリ、ショップのトップ → アプリのホーム)。変えるときは、配信のページ・カテゴリ・商品・ホーム・画面の名前から選ぶ。
  - 商品のリンクは、商品のページ(商品コード)を自動で開く。
  - 各欄の下に、data に入れる値(例: `{"screen":"product","product_code":"…","campaign":"…"}`)を出す。どの画面にも、配信を表す campaign を付ける。
- **⑥ 時刻・相手**: 送る日時(左の配信情報で決める)と、送る相手(全員・会員など)。

### 5.7 AIチャット(中ペインの下半分)
- **開いているタブ**の案づくりに、**ユーザーの指示を加える**ためのチャット(「AIチャット — ○○」)。
- 使い方の例: 「もっとカジュアルに」「レインブーツを必ず入れて」「もっと手頃な価格の商品で」「新作を優先して」。入力欄の近くに、**よく使う頼み方**のボタンが出る。
- 動作: 指示を送ると、そのタブの案(または、メイン画像・セクションの選定)が、**指示を反映して作り直される**。AI は、どう直したかを一言で返す。前の指示の条件(「必ず含める」など)は、会話の中で引き継ぐ。
- **質問・相談**(「この商品ラインアップはどう思う?」)のときは、**案を変えずに、答えだけ**を返す。返答の言語は、ユーザーの発言に合わせる。
- 会話は、**タブごと**。画面を開いている間だけ保持する(保存しない)。
- 高さは、上端のつまみのドラッグで変えられる。折りたたみもできる。
- 対象外: **テンプレート**のタブ。

### 5.8 プレビュー(メール / アプリ)
- **メール**: ヒーロー(メイン画像 + ヘッドライン + コピー)、セクションごとの見出し・コピー・商品タイル(画像、名前、価格、ボタン)。テンプレートの構成に従う。メイン画像・ボタンにマウスを重ねると、設定したリンク先が出る。
- **アプリ**: 通知の見た目(iOS / Android の切り替え)と、通知を押したあとのメッセージ。
- **直接編集**: プレビューの上で、セクションの見出しとコピーを書き換えられる。商品のドラッグで並べ替え、ホバーで「前へ / 後へ / 削除」。
- **倍率**: スライダーと、「全体」ボタン(押すと全体が収まる倍率。もう一度押すと **100%** に戻る)。開いたときの既定は「全体」。
- 価格の表記: JP の商品は円(¥)、US の商品はドル($)。

### 5.9 商品情報ペイン(参照専用。操作しない)
- 掲載商品を、**メールの並び順**に、セクションごとに一覧する。1行は、画像、名前、「コード・価格・在庫」、売上トレンドの矢印(↑ ↓ →)。**在庫が少ない商品には「残少」**の印。アラートのある商品にも印が付く。
- 行にマウスを置くと、プレビューの**該当商品が枠で光る**。
- 行を押すと、**詳細のフロート**が開く(位置は固定。右上の × 、外側のクリック、Esc で閉じる):
  - **売上・在庫**: 指標3つ(直近4週の販売数と増減%、在庫が何週分か、12週の売上)、**週ごとの販売数の棒グラフ**、**在庫の推移の折れ線グラフ**(在庫が少ないラインつき)。グラフは12週分。マウスを乗せると、その週の値が出る。
  - **販売方針・販促**: MD の販売方針、販促の期間、販促計画(週ごとの予定)。位置づけ(主力 / 定番 / 在庫調整 など)がバッジで出る。
  - **基本情報**: 価格、在庫、売上トレンド、評価、季節、天候適性、説明。
- 選定や並べ替えなどの**操作は、ここでは行わない**(中ペインだけ)。

### 5.10 テンプレートの管理(⚙ の「テンプレートの管理」)
- 左に一覧(「作成したテンプレート」と「標準」。2 列で見比べられる。メールとアプリ)、右に詳細・編集、構成の見取り図(プレビュー)。
- **標準のテンプレートは、編集・削除できない**。「**複製して編集**」で、自分用に作り変える。
- 作成・編集できる内容: **テンプレート名、説明、ヒーロー(種類・ヘッドラインの見せ方・画像のリンク先・お知らせ帯)、構成**。構成は、セクションとボタンの部品を、上から順にカードで並べる(追加・削除・上下の並べ替え)。各セクションで、**商品の並び方**、**商品の枠の数(1〜8点)**、**見出しの有無**、**コピーの有無**を決める。ボタンの部品では、ボタンごとに**文言・見た目・リンク先の種類**を決める。セクションは最大6つ、ボタンの部品は最大8つ。
- リンク先は、テンプレートでは**種類(配信のページ / カテゴリのページ / ショップのトップ / 配信カードで指定)**を決め、実際の URL は配信カードの「リンク先」のタブで決める(5.13)。
- 作ったテンプレートは、**組織の全員が選べる**(アプリのデータベースに保存)。他の人が作ったものも編集できる。
- 削除すると、そのテンプレートを使っていたカードは、Standard4 として扱われる。

### 5.11 日本語 / English
- ⚙ の言語の切り替えで、**画面全体**が、日本語・English になる(初期値は English。選んだ言語はブラウザごとに覚える)。
- **AI の出力**も、画面の言語に合わせる(理由・切り口・制作指示など)。コピー・ヘッドラインは、配信の国の言語で作る(US は英語、JP は日本語)。
- 日付・価格の表記も、言語に合わせる。

### 5.12 週のレビューと承認
- **週の状態**: 確定前 → 確定。状態は、週の帯の左端の印に出す(マウスを重ねると、確定した日時)。
- **週の帯**(週の表示の上。その週のレビューと確定だけを置く): 左端に週の状態の印と、状態ごとの件数(未起案・承認待ち・承認済み。確定は承認済みに数える)。右に「**まとめて依頼**」「**自分宛てを承認**」「**確定の前に直すこと**」の印・「**週を確定**」「確定を取り消す」。
- **配信 1 本ずつの承認**: 配信カードの下で、名前を入れて「**保存して承認**」、または理由を付けて「**差し戻す**」(理由はコメントにも残る)。承認者の制限はない(誰でも押せる)。
- **確定後の変更の制限**: 確定した週の配信では、右のプロセスのペインの状態の下に説明が出る。内容を変えた時点で、上に知らせの帯が出て、保存には理由が必要。保存すると、配信は「検討中」、週は「レビュー中」に戻り、理由は記録に残る。承認済みの配信の内容を変えても、「検討中」に戻る。
- **確定の前に直すこと**(確認の一覧。「週を確定」の左の印): 週を確定する前に、0 にしておくことの一覧。同じ商品の週の回数(上限を超えたもの)、メールとアプリ、主力の商品の漏れ、テーマ・メイン画像の連続、未対応のコメント、未解決の質問、承認の数。
  - 印は、問題のある項目の数(⚠ と数)。なければ ✓。押すと、一覧が重なって開く(画面は移らない)。
  - 問題のある項目を、**何をするか**(例: 「ほかの商品に差し替える」「質問に返信して、解決にする」)と一緒に出す。問題のない項目は「OK の項目」にまとめ、押すと出る。
  - 項目を選ぶと、週の表示で、かかわる配信・商品が目立つ。帯の左に「選択中: …」の札が出る(× で外す)。「**最初の配信を開く**」から配信カードを開き、「保存して次へ」で、その項目の配信を順に直せる。
  - 残っているまま「週を確定」を押すと、確かめる。
- **承認の履歴**: 誰が・いつ・何から何にしたか(週の操作と、配信のステータスの変更)。「この画面 ▾」の「この週の承認の履歴」。
- **週の資料(PDF)**: 「この画面 ▾」の「週の資料を PDF で書き出す」で、印刷の画面を開く(送り先を「PDF に保存」)。1 枚目に、週の状態・確認の一覧・配信の一覧・承認の履歴。2 枚目からは、配信ごとのプレビュー。

### 5.13 コメント・質問・リンク先
- 引き継ぎ・タスク・コメントは、配信カードの中ペインの「**やり取り**」の面にある。リンク先は「**コンテンツ生成**」の面。
- **コメント**(「コメント」のタブ): 配信全体、または載せた商品を選んで指摘を残す。指摘ごとに返信でやり取りし(スレッド)、決着したら「**対応済みにする**」。対応済みは消さずに、たたんで残す。未対応の数を、タブ・週の表示・確認の一覧に出す。
- **引き継ぎ**(「引き継ぎ」のタブ): 制作の担当・締め切りを決め(入力はここだけ。左の配信情報は表示)、「制作に知らせる」で引き継ぎ済みにする(アプリからの通知は送らない)。**質問と返信**もここで。質問は、**誰からでも、誰にでも**できる(質問する人・宛先を選ぶ)。返信する人も選べる(既定は宛先の人)。
- **タスク**: 質問などのやり取りから、AI がタスクの案を出し、採用したものを担当・期日・完了で管理する。未完了の数を、タブ・週の表示・一覧に出す。
- 絞り込みの「担当」は、企画・制作の担当に加え、未解決の質問の宛先・質問した人、未完了のタスクの担当の配信も出す。
- **リンク先**(コンテンツ生成の ⑤): メールは、メイン画像・ボタンごとに、実際の URL と計測用のパラメーターを決める。アプリは、開くアプリの画面を決める(5.6.1)。リンク先のタブを開いている間は、プレビューのリンクの場所に番号が出る(未設定は色が変わる)。

### 5.14 結果の振り返り
- **結果の取り込み**: 結果の面の「この画面 ▾」から、CSV(配信名・配信日・送った数・開封・クリック・注文・売上・前年の売上)を取り込む。「取り込みの見本」もある。CSV で取り込むのは、配信ごとの数字。リンクごとのクリック・商品ごとの結果は、データにあれば、ヒートマップや商品の表に出す。
- **月**: 計画の面と同じカレンダーで、配信ごとに売上・開封率(アプリはタップ率)・前年比。左の線の色は前年比(上なら緑、下なら赤)。結果がまだの配信は灰色。
- **週**: 日ごとに、**クリックを重ねたプレビュー**(ヒートマップ)と主な数字。上に「**この週の振り返り**」のメモ(週全体で気づいたこと・次の週に生かすこと。ふだんは 1 行にたたみ、「書く」「直す」で開いて、その場で保存)。ツールバーの「**先週を振り返る**」で、先週の週表示に 1 回で移れる。
- **前週の振り返り**: 計画の面の週の表示に、前の週に書いた振り返りが出る(「前週の結果を見る」で、結果の面の前週へ)。
- **一覧**: 計画の面と同じ表(左にサムネイル。列見出しで並べ替え)。開封率・クリック率・売上・前週比・前年比。**テーマ / テーマの種類 / テンプレート / 商品**ごとにまとめて見ることもできる。書き出しもできる。
- **比べる**: ツールバーの絞り込みと、テンプレート・テーマの種類・配信名で絞った、直近 5 / 10 / 20 回の配信を、ヒートマップと数字で並べる。AI の評価も出せる。
- **詳しい結果**(配信を押すと上に重なる): 主な数字、プレビューの上に**リンクごとのクリックを濃さで重ねる**(メイン画像・ボタン・商品)、リンクの表、商品ごとのクリック・売れた数と配信の前後の販売・在庫、採用したテーマ・見出し・テンプレート・メイン画像と AI の理由。
  - **過去の配信と比べる**: 同じテンプレート、または同じテーマの種類の、この配信より前の 3 / 5 / 10 回と、数字・位置ごとのクリックの割合を並べる。
  - **AI で振り返る**: 良かったこと / 悪かったこと / 次に試すこと(数字入り)と、根拠の強さ。1 行ずつ「メモに採用」できる(振り返りそのものは保存しない)。
  - **次に生かすメモ**: 配信ごとに残す。同じテンプレート・テーマの種類の、次の配信カードの「これまでの学び」に出て、AI の案にも渡される。
  - 「**制作の詳細**」で配信カードを上に重ねて開ける(閉じると結果に戻る)。「**PDF で書き出す**」で、配信 1 本のレポート(A4 縦 1 枚)。
- **テーマの種類**(値下げ / セール / 新作 / 会員向け / 季節の特集 / 再入荷 / その他): 「AI でテーマの種類を分ける」で、まだ決まっていない送った配信を AI が分ける。直すのは配信カード(「これまでの学び」の帯)。詳しい結果では見るだけ(結果を読んでいる途中で、比べる相手が入れ替わらないように)。

### 5.15 アラート
- **在庫切れの見込み・在庫僅少**: まだ送っていない配信に載っている商品について、配信日の在庫を、直近 4 週の販売の速さと、それより前の配信で上乗せされる販売から見込む。配信日に在庫がなくなる見込み、または何週分を切る見込みなら知らせる。
- **MD 方針の変更・日程の変更**: 商品の販売方針・位置づけ・販促の期間、配信日時が変わったら、変更の前と後を知らせる。
- **アラートのフロート**: ヘッダーの「アラート」で、いまの画面の上に重ねて開く(閉じれば、見ていた期間・見せ方・絞り込みのまま)。左に一覧(商品の画像つき。日程の変更は配信の画像)、右に、商品の画像・商品コードと、影響を受ける配信(日付・配信のサムネイル(マウスを重ねるとプレビュー)・チャネル・状態・載っている場所・配信日の在庫の見込み)。ここから開いた配信カードは、さらに上に重なり、閉じるとアラートに戻る。
- **対応**: 配信ごとに、**差し替え**(差し替える商品といまの在庫を上に出し、AI が、配信日に在庫が見込める同じカテゴリの商品を 3 つ提案。候補ごとに、いまの在庫・配信日に何週分・今週と前週に載せた回数)、**開く**(問題の商品を選んだ状態で配信カードを開く)、**延期**、**取りやめ**。変更の理由は記録に残り、確定・承認済みの配信はレビューに戻る。変更のアラートは「対応済み」にできる。
- **対応の記録**: 誰が・いつ・どう対応したか。
- **アラートの条件**: 在庫僅少にする週数(1〜8 週分)・出す種類・対象の種別・担当。人ごとに(ブラウザごとに)覚え、ヘッダーの件数にも効く。
- 配信カードの「この配信のアラート」の帯、商品情報とカレンダーの印でも分かる。
- **配信カードの中での対応**: 帯の商品名・「対応する」、プレビューの商品の枠に重なる札(在庫切れ・在庫僅少など。枠が狭いときは印だけ)、商品情報の行の札の、どこから押しても「**このアラートへの対応**」が開く。在庫のアラートは、AI の差し替えの候補から「**使う**」で、その配信の中で商品を置き換える(**保存で確定**。保存しなければ元のまま。差し替えた理由は、保存のときに配信のメモに残る)。ほかに「**配信日を変える**」(左の配信日時の欄へ)と「**アラートの画面で詳しく**」(その商品のアラートを選んだ状態で開く)。方針・日程の変更は、アラートの画面で確かめて「対応済み」にする。

### 5.16 取りやめ・削除
- 配信カードの題名の横の「…」から。
- **取りやめ**: 理由を残して、消さずに残す。カレンダー・週・一覧に、取り消し線と「取りやめ」の印で薄く出し、アラート・週の確認・件数からは外す。取り消すこともできる。
- **削除**: 間違いで作ったものだけ。元に戻せないことを確かめてから消す。

## 6. AI の仕組み(概要)

- AI は、**Google の Gemini**(Vertex AI)。アプリが、必要な情報(配信の国・日時・テーマ、候補の商品・画像、過去のメモなど)を渡し、AI が**候補の中から選ぶ**・**文案を出す**。商品・画像を作り出すことはない。
- AI を使う場面: 下書き(テーマ・テンプレート・メイン画像・文言・セクション・制作指示・アプリの文言)、まとめて作る、AI チャット、アラートの差し替えの候補、タスクの案、テーマの種類の分類、振り返り、比べるの評価。
- 在庫・売上トレンド・評価・季節・天候・週次の実績・MD の方針・配信の結果は、**アプリのデータベース**に取り込んだデータを元にする。

## 7. データ(初期のサンプルデータ)

動かし始めたときに入っている、架空のサンプルデータ。実際の商品・画像・実績を取り込めば、それに置き換わる。

| データ | 内容 |
|---|---|
| 商品 | JP 30点(円)、US 30点(ドル)。カテゴリ: アウター / トップス / ボトムス / シューズ / 小物 / バッグ / ホーム |
| メイン画像 | JP 20点、US 20点(新作 / 特集 / セール / 会員 / イベント) |
| 配信カード | US 向け・JP 向けの、2026年9〜10月の予定 |
| 週次実績 | 全商品 × 12週(販売数、売上、在庫) |
| 販売方針 | 全商品(MD の方針、販促計画、期間、位置づけ) |
| 配信の結果 | 送った配信の結果(開封・クリック・売上、リンクごとのクリック) |
| 画像 | サンプル用のイラスト(実際の商品写真ではない) |

サンプルデータは、すべて**架空のデータ**。

## 8. 技術(概要)

- ブラウザで使う Web アプリ。画面は React + TypeScript。デザインは **Fluent 2**(Microsoft の UI)。
- サーバーは Python(FastAPI)。データは **PostgreSQL**、AI は **Google の Gemini(Vertex AI)**。
- 同じアプリを、クラウドのサーバーでも、社内のデータ分析環境(ノートブックの環境)でも動かせる。データと画像は、動かす環境ごとに持つ(引っ越し用のファイルで、データと画像をまとめて移せる)。
- 利用者のログインはない。承認・コメントなどの「誰が」は、画面で入れた名前で記録する。アクセスは、パスワードなどで守る(動かす環境に合わせる)。

## 9. 未実装・制限(**できないこと**)

- **メール・アプリの実配信**は、しない(このアプリは、配信内容の**企画・レビュー・振り返り**まで。配信システムとは連携していない)。結果は、取り込みで入れる。
- **通知**(レビューに出した・引き継いだ、などを、メール・チャットで知らせる)は、しない。
- 商品の売上・在庫・方針・画像は、**取り込んだデータ**を使う。基幹システムとの自動の連携はない。
- 配信カードの**複製**、**変更の履歴**(項目ごとに、いつ誰がどう変えたか)は、まだない(承認の履歴と、配信日・方針の変更の記録はある)。
- **件名・プリヘッダー**、**プレビューの PC / スマホの切り替え**、**カレンダーでのドラッグによる日付の移動**、**祝日などの予定の重ね合わせ**は、まだない。
- **週の比較画面**(当週と前週を並べる)、**商品ごとの露出回数の一覧**は、まだない(週の確認の一覧で、上限を超えた商品は分かる)。
- **AIチャットの会話の保存・再開**はできない(画面を閉じると消える)。**条件のピン留め**(以後のすべてのAI生成に効かせる)も、未実装。
- 承認できる人の制限はない(誰でも押せる)。週の状態は、メールとアプリで分けず、週に 1 つ。
- AI の案は、**採用するまで反映されず、保存もされない**(一部の選定は、反映して「元に戻す」)。
- 商品が数千件以上の規模では、読み込み・検索・AI の候補の絞り込みの対策が、今後必要。
- AI の返答は、毎回同じとは限らず、まれに形式が崩れて、自動でやり直すことがある。
- AI の利用には、費用(従量課金)が発生する。

## 10. デモの流れの例(約10分)

1. **カレンダー**を見せる: 色分け、メールとアプリの見分け、絞り込み(国 = US)、日英の切り替え。
2. 空の配信カードを開く → 「**すべてAIで下書き**」→ 進み具合 → 結果(テーマ、メイン画像、ヘッドライン・コピー、セクションの商品、制作指示)。
3. **プレビュー**: ヘッドラインの縮小、商品のドラッグ。
4. **商品選定の理由**を見せる → **AIチャット**で「レインブーツを必ず入れて」→ 反映 →「どう思う?」→ 答えだけが返る。
5. **商品情報ペイン**を開く → 商品を押す → **売上・在庫のグラフ**、MD の方針。
6. **週の表示**: 確認の一覧 → 項目を選ぶ → コメント → 保存して承認 → 週を確定 → PDF。
7. **アラート**: 在庫切れの見込み → 影響を受ける配信 → AI の差し替えの候補で差し替え。
8. **結果の面**: 月のカレンダー → 詳しい結果のヒートマップ → 過去の配信と比べる → AI で振り返る → メモに採用 → 次の配信カードの「これまでの学び」。
9. **English に切り替え**: 画面と AI の出力が英語になる。
