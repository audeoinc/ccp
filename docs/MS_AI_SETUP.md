# 別の環境で、CCP の AI を Copilot Studio につなぐ手順

2026-11-04 作成(案)。CCP の AI を、Gemini から Microsoft の AI(Copilot Studio・AI Builder)に替えたいとき、**CCP を動かす環境と、使う Microsoft の組織(テナント)が、検証したときと違っても**同じ手順で作り直せるように書いた。

- 検証の手順と、測った数字の記録は [MS_AI_VERIFY.md](MS_AI_VERIFY.md)(この文書の数字は、そこの記録から写した。推測のものは推測と書く)。
- CCP の側の出口(設定と、層との約束)は [AI_OUTLET.md](AI_OUTLET.md)。考え方は [AI_OUTLET_PLAN.md](AI_OUTLET_PLAN.md)。
- 本命は **Direct Line 版**(2 章)。**AI Builder 版**(3 章)は、組織の都合で Power Platform の流れを使いたいときのために残す。比べた結果は 4 章と、MS_AI_VERIFY.md の「暫定の評価」。

この文書には、組織・環境の名前、ID、URL、鍵を書かない。値は `<環境の ID>` のように書く。実際の値は、各自の秘密の置き場に置く。

## 1. 全体像

```
  CCP の画面 ──► CCP のサーバー
                    │  AI が要る所(4 か所。AI_OUTLET.md)
                    │  ⚙「AI の設定」の出口の URL が入っていれば
                    ▼
               層(CCP のフォルダの外に置く。この文書で作るもの)
                    │
          ┌─────────┴──────────┐
          ▼                    ▼
  Direct Line(2 章)       Power Automate の流れ(3 章)
          │                    │
          ▼                    ▼
  Copilot Studio の         AI Builder のプロンプト
  エージェント
  (先方の Microsoft の組織の、Power Platform の環境に作る)
```

- **CCP のコードは変えない。** CCP には、外の AI に頼む出口(`AI_OUTLET_URL`、約束の版 1)がすでにある。作るのは、出口と Microsoft の AI の間の **層** だけ。
- **エージェント・プロンプト・流れは、先方の組織で作り直す。** 検証で作ったものは、検証の組織の中にあり、持ち出せない(ソリューションで書き出す手もあるが、試していない。設定が少ないので、画面で作り直すほうが確実)。
- **利用者から見て、何も変わらないようにする。** 画面は変えず、違いは層で吸収する(2.4・2.6、MS_AI_VERIFY.md の 16 章)。

#### 2.1.1 「認証なし」が組織のポリシーで選べないとき

検証の組織では選べたが、**別の組織の CCP 用の開発環境では、エージェントの「認証」の「認証なし」がグレーアウトし、組織のポリシーで設定できない旨が出た**(2026-11-05)。組織の管理者が DLP のポリシーで、Entra ID の認証なしのチャットを止めているためと見込む(原因は管理者に確かめる)。このままでは、Direct Line の鍵だけでサーバーから呼ぶ形(この章の形)は作れない。

| 案 | 中身 | 利用者から見た差 | 見込み |
|---|---|---|---|
| **A. CCP の環境だけ例外にする**(第一の案) | 管理者が、CCP 用の環境だけ「認証なしのチャット」を許す DLP のポリシーを作る(か、その環境を全体のポリシーから外す) | なし | 組織の決まりで許されるかによる。相談の材料は下 |
| B. 認証ありのまま Direct Line で呼ぶ | エージェントを Entra ID の認証にし、会話の中で利用者のトークンを渡す | **利用者に Microsoft のサインインが増える** | サーバーだけで呼ぶ形は取れない見込み(Agents SDK と同じ問題) |
| C. AI Builder の流れを、Entra ID の認証つきで呼ぶ | 流れの HTTP のトリガーを組織の中だけにし、層は Entra のアプリで券をもらって流れを呼ぶ | なし(写真の枚数の工夫は要る。3 章) | **未確認**。アプリだけの券でトリガーを呼べるか、DLP で HTTP のトリガーが止められていないかを試す |

管理者に相談するときの材料(案 A):

- 例外にするのは CCP 用の環境だけで、ほかの環境のポリシーは変えない。
- エージェントは「セキュリティで保護されたアクセスを要求する」をオンにし、Direct Line の鍵を必須にする。鍵は CCP のサーバーの秘密の置き場だけにあり、鍵なしの入口は断られる(検証で確かめた。MS_AI_VERIFY.md 8 章)。
- エージェントを呼べるのは、鍵を持つ CCP のサーバー(層)だけ。だれが AI を使えるかは、CCP の入口のサインイン(Entra ID の SSO など)で絞る。
- エージェントには、ナレッジ・ツール・Web の検索を付けない。頼まれた文に答えを返すだけ。

### 2.2 CCP を動かす側の準備(サーバー)

| こと | 中身 |
|---|---|
| 層の置き場 | CCP のサーバーと同じマシンか、同じネットワークの中。**CCP のフォルダの外**(CCP を新しい版に入れ替えても消えないように) |
| 外への通信 | 層から `https://directline.botframework.com`(HTTPS・443)に出られること。中継(プロキシ)を通すなら、その設定 |
| 待ち受け | 層は外から呼ばれないようにする(同じマシンの中だけで待つ `127.0.0.1`、か、合言葉 `AI_OUTLET_TOKEN` を確かめる) |
| 秘密の置き場 | Direct Line のシークレットと、層の合言葉。環境変数か、サーバーの秘密の置き場。リポジトリ・ZIP・ログに入れない |
| 起動 | CCP のサーバーと一緒に起動し、止まったら起こし直す(サービスとして登録するなど) |
| 時刻 | 正しい時刻に合わせる(トークンの期限を使うため) |

### 2.3 先方の環境で確かめ直す(検証の道具で)

検証の道具(`tools/ms-verify/`)を、CCP の開発から ZIP で受け取る(`npm run pack:ms-verify` で作る。鍵や結果は入らない)。Node 22 以上で動く。設定は、ホームのフォルダの `.ccp/ms-verify.env` に書く(MS_AI_VERIFY.md 12.4)。

| 順 | 試すこと | 動かし方 | 合格の目安(検証での値) |
|---|---|---|---|
| 1 | 道具が動くか | `node measure.mjs --self-test` | すべて OK |
| 2 | つながるか(T1 を 1 回) | `node measure.mjs --via dl --only T1 --runs 1` | JSON が返る |
| 3 | 戸締まり(鍵なしの入口) | `node check-token-endpoint.mjs` | **403** で断られる |
| 4 | 文の頼み T1〜T5 | `node measure.mjs --via dl --runs 1` | JSON・決まりとも 5 / 5。本文まで 3〜5 秒 + 会話を始める 1 秒未満 |
| 5 | 画像の頼み T6〜T10 | `--only T6 --image <写真>` など(T9 は `--image` を並べる) | JSON・決まりとも ○。T9 の 7 枚でアングルが写真のとおり。7 枚で 11 秒ほど |
| 6 | 写真の大きさ | 同じ写真を大きさを変えて送る | 1 回の送信が 4MB を超えると 400「MessageSizeTooBig」(確か)。4MB 未満は通る |
| 7 | 待ち時間を何回か | `--runs 3` | 大きくばらつかないか(検証では多くを 1 回ずつしか測っていない) |
| 8 | データの扱い | 組織の管理者と | 2.1 の 4 を確かめた記録がある |

- 写真は、人の顔・社外秘の写らない服の写真を各自で用意する(道具の `images/` に置く。Git に入らない)。
- 結果(`results/`)には答えの全文が入る。共有するときは表(`.md`)だけにする。
- 決まりを外れたら、モデル・指示の文を見直して測り直す。

### 2.4 層の仕事

層は、CCP の出口から約束の版 1(AI_OUTLET.md 2 章)で受け、Direct Line を呼んで、`{"text": …}` で返す。呼び方の詳しい形は MS_AI_VERIFY.md 9 章、注意は 16 章。

| 仕事 | 中身 | しないと(利用者から見た差) |
|---|---|---|
| 呼ぶ | 鍵 → 短い期限のトークン → 頼みごとに新しい会話 → 送る → 答えを取りに行く(終わりの合図はないので、自分の頼みへの返事が届いたら終わり) | — |
| 画像を組み替える | CCP の `parts`(文と画像が交互)を「文 + 添付」にする。添付は upload の入口で送る(`data:` の URL は断られる)。番号は添付の順にそろえ、文で伝える | 画像の頼みが通らない |
| 写真を縮める | 1 回の送信の合計が 4MB 以下になるよう、長い辺 1024〜2048 ほどの JPEG に。小さく切り出した寄りの写真はそのまま | **画面で受け付けた写真なのに失敗する** |
| エラーの文を見分ける | エージェントの側のエラーは、ふつうの答えの文として届く。「エラー コード」などを見分けて `{"error": …}` で返す。混み合いは 429 | 「応答に JSON が含まれていません」と出て、理由が分からない |
| JSON を取り出す | 囲み(```` ``` ````)や前置きを外し、JSON だけにして返す(画像の 3 か所は、CCP のサーバーが答えをそのまま JSON として読むため) | 画像の頼みが失敗する |
| 番号を確かめる | 答えの画像の番号が、渡した枚数の外を指していたら消す | 存在しない画像が選ばれる |
| やり直し・時間切れ | 各段の一時的なエラーを数回やり直す。時間切れは画面の待ち(180 秒)より短く(例: 120 秒) | 画面が待ったまま止まる |
| 同時の数 | 出口の「同時の上限」と合わせる(Direct Line に同時に何本まで投げてよいかは未確認) | 「AI で下書き」が遅くなる・断られる |
| ログ | 指示文・画像の中身をログに残さない(配信の企画の中身が入る) | — |

### 2.5 CCP につなぐ

1. 層を起動する(2.2)。
2. CCP のサーバーの環境変数に `AI_OUTLET_TOKEN=<層と同じ合言葉>` を足し、サーバーを起動し直す。
3. CCP の画面の ⚙ →「AI の設定」(管理する人だけ)で、出口の URL に層の窓口(例: `http://127.0.0.1:8090/ask`)を入れて保存する。次の呼び出しから効く。
4. `python -m ccp.cli check` の「■ AI」の段に、「AI の出口 … に届きます」と出るのを確かめる(AI は呼ばない)。
5. 画面で 1 度だけ試しに呼ぶ(下の 2.6 の 1 つめ)。
6. 替えたことを、CCP を使う人に知らせる(どちらの AI が書いたか分からなくならないように)。

### 2.6 CCP の画面で確かめること(利用者から見た差)

| 画面の所 | 確かめること |
|---|---|
| 配信の「AI で下書き」 | 6〜9 回の呼び出しが、ふだんと同じくらいの時間で終わるか(4 本ずつ並べて 10〜15 秒の見込み。未確認) |
| 見出し・コピーの候補 | 候補が出る。英語の画面でも出る |
| メイン画像・部品の画像の説明 | 大きな写真(4MB 超)でも失敗しない(層が縮める) |
| 商品ページの画像の提案 | 枚数の違う商品で、アングルと選ぶ画像が出る |
| 「？ 聞く」 | 長い資料を付けた頼みで失敗しないか(**頼みの文の長さの上限は未確認**) |
| 混み合い・失敗 | 利用者に分かる文で出る(「応答に JSON が含まれていません」だけにならない) |

### 2.7 戻すときの注意

- 出口の URL を空にすると、Gemini に戻る。**Gemini を使えない(Google の設定がない)環境では、空にすると AI が使えなくなる。** 戻すときは、層を直すか止めるかを先に決める。
- 層が失敗しても、自動で Gemini には回らない(AI_OUTLET.md 1 章)。

## 3. AI Builder 版(念のため)

Power Automate の流れを窓口にして、AI Builder のプロンプトを呼ぶ形。**プロンプトは外のプログラムから直接は呼べない**(Dataverse の `Predict` は「Source is null」で断られた。推測: 流れ・アプリの中から呼ぶ作り)。

### 3.1 Microsoft の側の準備

| # | すること | 気をつけること |
|---|---|---|
| 1 | Dataverse のある環境・Copilot のクレジット | 2.1 の 1〜4 と同じ。プロンプトはトークンの量で払う(画像 1 枚の頼みでクレジット 3。測った値) |
| 2 | 流れのライセンス | 「HTTP 要求の受信時」「応答」は **プレミアムのコネクタ**。検証の Developer の環境では案内なしに動いたが、**本番の環境ではプレミアムのライセンスが要る見込み**(未確認) |
| 3 | DLP のポリシー | HTTP のトリガー、Dataverse(AI Builder)のコネクタが許されているか |
| 4 | 文の頼み用のプロンプト | 入力は文 1 つ(`request`)。指示の文は `{request}` だけでよい(頼みの文は層が作る) |
| 5 | 画像の頼み用のプロンプト | 入力は文 1 つ + **画像の欄を 8 つ**(`image1`〜`image8`。種類は「画像またはドキュメント」)。指示の文に、`{request}` と、画像の欄を順に置く |
| 6 | 文の頼み用の流れ | 「HTTP 要求の受信時」→「プロンプトを実行する」(Request に `request`)→「応答」(本文に、答えの Text だけ) |
| 7 | 画像の頼み用の流れ | 「HTTP 要求の受信時」の JSON に `request` と `imageBase64_1`〜`imageBase64_8`(文字)を書く。「プロンプトを実行する」の画像の欄ごとに、**fx(式)で** `if(empty(triggerBody()?['imageBase64_1']), null, base64ToBinary(triggerBody()?['imageBase64_1']))`(番号を 1〜8 に)。動的なコンテンツから選ぶと、2 重の base64 になって読めない(確か) |
| 8 | 流れの持ち主 | 流れの接続は、作った人のサインインで動く。**その人のアカウントが止まると流れも止まる**(見込み)。組織の決まりに合わせ、持ち主を決める |
| 9 | 流れの URL | 署名の鍵が入っている。URL そのものを秘密として扱い、CCP を動かす側の秘密の置き場に入れる |

- プロンプトの入力の名前を変えたら、流れの「プロンプトを実行する」でプロンプトを選び直す(前の欄が見えない形で残り、保存が「WorkflowOperationParametersExtraParameter」で断られた)。
- プロンプトの画面のテストでは WebP の写真を付けられないが、流れから渡せば WebP も読めた。

### 3.2 CCP を動かす側の準備(Direct Line 版との違い)

- 外への通信の先が、流れの URL の住所になる(先方の組織の Power Automate)。
- 秘密は、流れの URL(文用・画像用)。Direct Line のシークレットは要らない。

### 3.3 先方の環境で確かめ直す

設定に `AIB_FLOW_URL`(文用)・`AIB_FLOW_IMAGE_URL`(画像用)・`AIB_FLOW_IMAGE_MAX=8` を書き、`--via flow` で送る(MS_AI_VERIFY.md 15.6〜15.8)。

| 順 | 試すこと | 動かし方 | 合格の目安(検証での値) |
|---|---|---|---|
| 1 | 文の頼み | `node measure.mjs --via flow --runs 1 --model "<モデル>"` | JSON 5 / 5。英語のコピーの文字数は外れやすい(1 回の測定) |
| 2 | 画像 1 枚 | `--only T10 --image <写真>` | JSON ○ |
| 3 | 画像の欄を埋めない(2 枚) | `--only T9 --image a --image b`(`--pad` なし) | **断られる**(「入力パラメーターがモデルに対して無効です」)のが今の作り |
| 4 | 白い画像で埋める(2・4 枚) | 同じに `--pad` | 通り、白い画像は答えに出ない。6〜7 秒 |
| 5 | 8 枚 | `--pad --image …`(8 枚) | 8〜10 秒(**1 回目は 89 秒かかった**。温まっていなかったと推測。何回か測る) |
| 6 | 写真の大きさの上限・呼び出しの回数の上限 | — | **未確認**。流れの呼び出しの回数の上限は、ライセンスで決まる見込み |

### 3.4 層の仕事(Direct Line 版との違い)

| 仕事 | 中身 |
|---|---|
| 呼ぶ | 流れの URL に 1 回 POST すると答えが返る(1 段)。会話・取りに行く手順は要らない |
| 画像を欄に入れる | `parts` の画像を、順に `imageBase64_1`〜`_8` に入れる |
| **枚数をそろえる** | 画像の欄は空にできないので、**足りない欄を小さな白い画像で埋め**、頼みの文に「画像 N 以降は空の白い画像。無視する」と足す(測るプログラムの `--pad` と同じ) |
| 8 枚より多いとき | 8 枚ずつに分けて呼び、答えをまとめる(試していない)。分けると、写真どうしを見比べる判断はできなくなる |
| 番号を確かめる | 渡した枚数の外の番号は消す(白い画像で埋めた分、取り違えやすい。1 回あった) |
| エラー | 流れの中の失敗は、502「NoResponse」で返る(理由は流れの実行の記録にしか出ない)。利用者に分かる文にして返す |
| 写真の形式 | JPEG・PNG・WebP は通った。縮める基準は Direct Line 版と同じでよい(上限は未確認) |

## 4. 2 つの比べ

| 項目 | Direct Line 版 | AI Builder 版 |
|---|---|---|
| 作るもの | エージェント 1 つ | プロンプト 2 つ + 流れ 2 つ(+ 流れの接続) |
| ライセンス | Copilot のクレジット | Copilot のクレジット + 流れのプレミアム(見込み) |
| 秘密 | Direct Line のシークレット(2 つ。入れ替えられる) | 流れの URL(署名の鍵入り) |
| 止まりやすい所 | 会話の手順(層で持つ) | 流れの接続の持ち主のアカウント |
| 画像の枚数 | 自由(1 回 4MB まで) | 欄の数(8)まで。層が白い画像で埋める |
| 頼みを変えたとき | 層の頼みの文だけ | 層の頼みの文。画像の欄を変えるなら流れも直す |
| 呼ぶ手順 | 4 段 | 1 段 |
| 決まりを守る力(検証) | すべて ○ | 英語の文字数を外れた(1 回) |

詳しい評価と理由は、MS_AI_VERIFY.md の「暫定の評価」。

## 5. 層の作り方(案)

- **1 つの層で、Direct Line と流れを設定で切り替える**形にする(例: 環境変数で `directline` / `flow` を選ぶ。案で、まだ作っていない)。CCP の側は、どちらでも同じ出口の URL を見るだけ。
- 土台は、見本の層 `tools/ai-outlet/sample_layer.py`(受けた依頼を Gemini に回すだけの層。CCP のサーバーと同じ Python で動き、足すライブラリはない)。その中の、AI を呼ぶ関数を書き換える。
- 呼び方は、検証の道具 `tools/ms-verify/measure.mjs` の `--via dl`(Direct Line)と `--via flow`(流れ)の部分を写す(Node で書いてあるので、Python に書き直す)。
- 層は CCP のフォルダの外に置く(2.2)。

## 7. 後片付けと、鍵の入れ替え

- **Direct Line のシークレットの入れ替え**: 「Web チャネルのセキュリティ」に 2 つある。使っていない方を作り直し、層の設定をそれに替えてから、古い方を作り直す(止まらずに入れ替えられる)。漏れたと思ったら、すぐに作り直す。
- **流れの URL の入れ替え**: 流れのトリガーを作り直すと URL が変わる(見込み)。層の設定を替える。
- **試しに作ったもの**: 検証の道具の `results/`(答えの全文)・`.ccp/ms-verify.env`(鍵)を消す。試しのエージェント・プロンプト・流れは、使わないなら消す(MS_AI_VERIFY.md 11 章)。
- **やめるとき**: 出口の URL を空にする(2.7 の注意)→ 層を止める → エージェント・流れを止めるか消す → 鍵を作り直して無効にする。
