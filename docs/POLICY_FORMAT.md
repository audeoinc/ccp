# 方針・決まりのファイルの書き方(変換する人・Claude 向け)

CCP に取り込む、マーケティングポリシーのファイルの形の仕様です。クライアントの Excel・Confluence・文書から、この形に変換してください。
設計の背景(なぜこの形か)は [POLICY.md](POLICY.md) にあります。

- 状態: 案(2026-10-17)。CCP 側の取り込みはできている(⚙ →「方針・決まり(取り込み・一覧)」。`server/ccp/policies.py`)
- ファイルは 2 種類: **販売系の方針 = CSV**(2 章)、**ルール系の決まり = Markdown**(3 章)
- 利用先の名前・社内のページの URL は、ファイルに書いてかまいませんが、CCP のリポジトリには入れないでください

---

## 1. 全体のルール

| ルール | 内容 |
|---|---|
| 文字コード | UTF-8 |
| 市場 | `JP` / `US` など、大文字の 2 文字(CCP の配信カードの国と同じ値) |
| 日付 | `YYYY-MM-DD`。期間は `YYYY-MM-DD - YYYY-MM-DD` |
| 取り込みの単位 | 販売系: ファイルに入っている週 × 市場の行を置き換える(ファイルにない週・市場は、そのまま残す)。ルール系: ファイルごとに置き換える(同じファイル名で取り込み直すと入れ替わる) |
| 個人情報 | 書かない(担当者の名前は、役割にする) |

## 2. 販売系の方針(CSV)

1 行 = どの週・どの市場の・何についての方針か。1 行目は、下の列名(順番は自由。余分な列は無視する)。

| 列 | 必須 | 中身 |
|---|---|---|
| `week_start` | ○ | 週の始まり(月曜)。`YYYY-MM-DD` |
| `market` | ○ | 市場 |
| `scope` | ○ | `product`(商品)/ `category`(カテゴリ)/ `all`(その週・市場の全体の方針) |
| `target` | `scope` が `product`・`category` のとき ○ | 商品コード(SPU)、またはカテゴリの名前(BigQuery の SPU の出力の `category` と同じ書き方) |
| `stage` | | 段階。`主力` / `定番` / `在庫調整` / `新作`(英語なら `Core` / `Staple` / `Clearance` / `New`) |
| `priority` | | 優先度。1 が最も高い。空は普通 |
| `promo_period` | | 販促の期間 |
| `focus` | | その週の重点・重点の顧客(主に `all` の行。例: 「防寒を主役に。既存会員の再購入」) |
| `note` | | 自由な文(方針・販促の予定)。200 字ほどまで |

例:

```csv
week_start,market,scope,target,stage,priority,promo_period,focus,note
2026-10-19,US,all,,,,,"Outerwear first; win back lapsed members",
2026-10-19,US,product,410023,主力,1,2026-10-19 - 2026-11-15,,Lead item for the fall campaign
2026-10-19,US,category,Knitwear,定番,2,,,Rotate colors weekly
2026-10-19,US,product,410087,在庫調整,,,,"Sale themes only"
```

## 3. ルール系の決まり(Markdown)

1 ファイルに、決まりを何件でも書けます(ファイルは分かれていてかまいません)。

```markdown
# ルール集: 表現の決まり
- 版: 2026-10-17
- 出どころ: ブランドガイドライン(社内のページ)

## R-COPY-001 価格は税込みで書く
- 対象: copy, headline
- 強さ: must
- 市場: JP
- 確かめ方: 含めない /\d[\d,]*円(?!\s*[(（]税込)/

価格を書くときは「1,980円(税込)」のように、税込みであることを添える。

## R-SEL-010 新作の配信に、在庫調整の商品を入れない
- 対象: selection
- 強さ: must
- 確かめ方: 除く 段階=在庫調整
- 期間: 2026-10-01 - 2026-12-31

新作・新入荷のテーマの配信では、在庫調整の商品を選ばない。

## R-TONE-002 口調は、落ち着いた丁寧語
- 対象: headline, copy, instructions
- 強さ: should

あおる表現(「今だけ!」「急いで!」の連続)は避け、落ち着いた丁寧語で書く。
```

### 3.1 書き方の決まり

| 部分 | 決まり |
|---|---|
| `# …` | ファイルの題名(1 つ)。その下の `- 版:` `- 出どころ:` は任意 |
| `## <番号> <題名>` | 決まり 1 件の始まり。番号は、ファイルをまたいで重ならないもの(英数字と `-`) |
| `- 項目: 値` | 見出しのすぐ下に、下の項目を箇条書きで。英語の名前(`applies_to:` など)でもよい |
| 本文 | 箇条書きのあとの文章。AI にそのまま渡す。短く、具体的に(1 件 300 字ほどまで) |

### 3.2 項目

| 項目(英語の名前) | 必須 | 値 |
|---|---|---|
| `対象`(`applies_to`) | ○ | `theme` / `selection` / `hero` / `headline` / `copy` / `instructions` / `schedule` を、`,` で区切って 1 つ以上 |
| `強さ`(`strength`) | ○ | `must`(必ず守る)/ `should`(なるべく)/ `info`(背景として知っておく) |
| `市場`(`market`) | | `JP`、`US` など。複数は `,` で。書かなければ、すべての市場 |
| `チャネル`(`channel`) | | `email` / `app`。書かなければ、両方 |
| `期間`(`period`) | | `YYYY-MM-DD - YYYY-MM-DD`。書かなければ、いつでも |
| `確かめ方`(`check`) | | 機械で確かめられる決まりだけ(3.3)。書かなければ、AI に伝えるだけ |

### 3.3 確かめ方

| 書き方 | 意味 |
|---|---|
| `含めない <言葉>, <言葉>, …` | その言葉を含めない(大文字・小文字を区別しない) |
| `含めない /<正規表現>/` | その形の文字を含めない |
| `含める /<正規表現>/` | その形の文字を必ず含める |
| `除く 段階=<段階>` | 商品の選定の候補から、その段階の商品を除く(販売系の方針の `stage`) |
| `上限 週 <数> 回` | 同じ商品(`selection`)・同じチャネルの配信(`schedule`)を、週に何回まで |

- 正規表現は JavaScript の書き方。`/…/` の中に `/` を書くときは `\/`。
- 確かめられない決まり(口調・世界観 など)に、無理に確かめ方を書かない。

### 3.4 変換するときの目安

- **強さ**: 破ったら作り直す・法令や表示の決まり → `must`。ブランドの好み → `should`。知っておくと判断がよくなる背景(顧客像・季節の傾向)→ `info`。
- **対象**: 「商品をどう選ぶか」→ `selection`。「どう書くか」→ `headline` / `copy`。「制作への伝え方」→ `instructions`。「配信の回数・組み合わせ」→ `schedule`。
- 1 つの文書に、強さや対象の違う決まりが混ざっていたら、分けて別の決まりにする。
- 元の文書の、どの節から作ったかを、本文の最後に `(出どころ: …)` と書いておくと、あとで確かめやすい。
