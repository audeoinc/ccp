# シンプルな配信カード(SU1・SU2)の設計

2026-10-22 に利用者と決めた。項目と決めたことの一覧は [backlog-archive/DONE.md](backlog-archive/DONE.md) の SU1・SU2(2026-10-24 に済み。続きは [BACKLOG.md](BACKLOG.md) の 14 章)。この文書は、それを作るための設計(どのファイルに、何を、どの順で)。
前提: PC で使う(ノート PC の画面で使えること)。今の配信カード(`CardDetail`)は残し、ヘッダーのトグルで切り替える。

---

## 1. ねらい

- 日別のテーマ(と配信の型 ST9)があれば、AI が下書きを全部作れる。人の仕事は「出来上がりを見て、気になる所を直す」。
- 今の配信カードはメニュー・欄が多く、どこを触ればよいか分かりにくい。**プレビューを主役**にし、プレビューの部品を押すと、その部品だけを直すペインが出る形にする。
- 触っている部品は、プレビューの上でいつも分かる(枠と色)。直している間も、プレビューは隠れない。

## 2. 画面の形

```
┌ 上の帯: 配信名 · 配信日時 · チャネル · ステータス ……………… [次にやること] [⋯] ┐
├ 概要の帯(メールの枠の外): テーマ · 切り口 · 制作指示 · 国 · ターゲット · 担当 · 締め切り ┤
├──────────────────────────┬────────────────┬──────┬───┤
│ プレビュー(いちばん広い)       │ 選んだ部品のペイン  │商品の│コミ│
│  受信箱の 1 行(差出人・件名・      │ (選んだものによって │一覧  │ュニ│
│  プリヘッダー / 通知の見え方)      │  中身が替わる)     │(畳め │ケー│
│  [テンプレート] の札               │                │ る) │ショ│
│  メール本文(部品を押すと選ばれる)  │                │      │ン  │
│  [AB のタブ A|B|C|＋] SU2         │ AI の入力欄(段階 b) │      │(後)│
└──────────────────────────┴────────────────┴──────┴───┘
```

- コミュニケーションのペインは段階 (d)。それまでは場所だけ空けて畳んでおく(あとで足してもレイアウトが変わらないように)。
- 商品の一覧は畳める。畳んでいても細い帯に商品ごとの点を出し、アラートのある商品は色で分かる。
- 幅・開閉は人の設定(localStorage。今の `cardDetail.paneWidths` などと同じ考え。キーは `simpleCard.*`)。

## 3. 作りの方針(いちばん大事)

**状態と保存の処理は、今の `CardDetail` のものをそのまま使う。新しく書き直さない。**
`CardDetail.tsx`(約 2,300 行)は、フォームの状態・載せた商品・AB の案・保存(`save`。承認済みの内容を変えたら承認待ちに戻す、確定した週は理由を聞く、`syncItems`、変更の記録)を持っている。これを複製すると、2 つの画面で振る舞いがずれる。

- 段階 (a) は、`CardDetail` の中で、トグルがシンプル側なら、描画だけを `SimpleCardLayout` に切り替える。
  `CardDetail` の中で、シンプルな画面が使う値と操作を 1 つのまとまり(例 `editor`: `form`・`setField`・`items`・`heroOf`/`textsOf`・`template`・`save` …)にして渡す。
- これは、あとで状態と保存を `useCardEditor` のようなフックに切り出すための下ごしらえも兼ねる(切り出し自体は、段階 (a) が動いてから。大きな書き換えを先にしない)。
- 部品を選ぶ仕組み(5 章)は、制作のページ・結果でも使えるように、配信カードに依存しない部品として作る。

## 5. 部品を選ぶ仕組み

### 5.1 部品の型

```ts
type PartRef =
  | { kind: 'subject' } | { kind: 'preheader' }          // 受信箱の 1 行
  | { kind: 'pushTitle' } | { kind: 'pushBody' }         // アプリの通知
  | { kind: 'headline' } | { kind: 'copy' }              // メイン画像の上の大見出し・コピー
  | { kind: 'hero' }                                     // メイン画像
  | { kind: 'sectionTitle'; index: number } | { kind: 'sectionCopy'; index: number }
  | { kind: 'product'; itemKey: string } | { kind: 'slot'; index: number }  // 載せた商品・空いた枠(index は商品の並び全体の位置。作るときに section から改めた)
  | { kind: 'button'; id: string } | { kind: 'link'; id: string }
  | { kind: 'template' } | { kind: 'overview'; field?: string } | { kind: 'meta'; field: string }  // テンプレート・概要・上の帯
```

### 5.2 プレビューの目印

- `Preview.tsx` には、すでに `data-anchor`(`subject`・`hero`・`herotext`・`section:N`・`button:<id>`・`push` など)と、商品の `data-item-key` がある。
- **`data-anchor` の名前は変えない**(書き込み(ピン)の場所の目印。変えると、置いたピンが見つからなくなる。`Preview.tsx` の 158 行目のコメント)。
- 足りない細かさ(`herotext` は見出しとコピーが同じ名前、セクションの見出しとコピーの区別がない、空いた枠に目印がない)は、**別の属性 `data-part` を足して**見分ける(例 `data-part="headline"`・`data-part="sectionTitle:2"`・`data-part="slot:1"`)。
- 見分ける順: `data-item-key`(商品)→ `data-part` → `data-anchor`。`PreviewPins.tsx` の `place`(176 行目あたり)と同じく `closest()` で探す。

### 5.3 プレビューを「見る専用」にする

- 今の `Preview` は、見出し・コピー・セクションの見出しをその場で入力でき、商品・画像をドラッグできる。シンプルな画面では、**入力はペインで行う**ので、プレビューの中の入力欄は文字の表示にする(`Preview` に `pickMode` のような引数を足し、そのときは入力欄を出さない)。
- 並べ替えのドラッグは残す(SU1 ⑪。プレビューの上で商品の枠をつかんで動かす)。
- 入力中の内容は、反映の前からプレビューに写す(ペインの入力を、そのまま `editor` の状態に書けば、プレビューは今と同じく追いかける)。

### 5.4 選んだ部品の見せ方

- `PartPicker` は、選んだ要素の外形(`getBoundingClientRect`)に、枠と淡い色を重ねる(プレビューの倍率 `zoom` に注意。ピンと同じ計算を使う)。
- マウスを乗せた部品にも薄い枠(押せると分かるように)。
- 選んだら、その部品が見えるようにスクロール(`scrollIntoView({ block: 'nearest' })`)。
- キーボード: Tab で次の部品、Shift+Tab で前、Esc で選ぶのをやめる。

## 7. 商品の一覧のペイン

- 今の `ProductInfoPane` を使う(載せた商品の在庫・アラート)。行を押すと、今と同じ商品のフロート(`ProductActionFloat`)で詳細が出る。
- **選んでいる枠との連動**: プレビューで商品の枠を選んでいれば、フロートに「この枠の商品と入れ替える」を出し、選んだ部品のペインに、今の商品と押した商品を並べて見比べられるようにする。空いた枠を選んでいれば「この枠に入れる」。何も選んでいなければ、今と同じ(詳細を見て、差し替え先はフロートの中で選ぶ)。
- 畳んだときの細い帯: 商品ごとの点(アラートの色は `cardAlerts.ts` の強さ)。

## 8. 反映と元に戻す

- **入力が止まって約 1.5 秒で、自動で保存する**(2026-10-25。以前は別の部品を選んだときだけで、タブを閉じると消えた。部品を選び直したときも保存する)。保存は `save({ after: 'stay' })`。上の帯に「保存中… / 未保存 / 保存済み · 12:03」をいつも出し、保存していない変更がある間は、ブラウザを閉じる前に確かめる(beforeunload)。すべて AI で下書きした中身は、人がそこから直すまで自動では保存しない。直後に「元に戻す」を出す(今の「保存しました」の知らせ `justSaved` と同じ所。このリポジトリでは Fluent の `Toast` はまだ使っていない)。
- **確定した週の配信**は、今と同じく変更の理由を聞く必要があるので、自動で保存せず、ペインに「反映」のボタンを出して、理由を入れてから保存する(`changeReason` の流れ)。
- 承認済みの配信の内容を変えると、今と同じく承認待ちに戻る(`save` の中の `revoke`)。自動の反映でこれが起きることを、最初の反映の前に一度だけ知らせる。
- **元に戻す**: 反映のたびに、その前の `editor` の中身(フォーム・載せた商品・案の中身・メイン画像・テンプレート)を履歴に積む。戻すときは、その中身に戻して保存する。AI で作り直した分も戻せる。履歴は開いている間だけ(閉じたあとは変更の記録 `change_logs` で見る)。

## 9. 上の帯と次にやること

- 帯: 配信名・配信日時・チャネル・ステータス(押すと、選んだ部品のペインでその項目を直す)。
- 次にやること(ステータスから 1 つ。比べるときは `statusRank` を使う):

| 状態 | ボタン |
|---|---|
| 未起案・検討中 | 承認に出す |
| 承認待ち | 承認する番の人だけ「承認する・差し戻す」(SU11。26 章) |
| 承認済み・確定 | 制作に依頼 |
| 制作に依頼済み | 制作のページを開く |

  コミュニケーションの段階 (d) ができるまでは、承認・制作への依頼は、このボタンから今の配信カード(承認のバー・プロセスのペイン)に移って行う。
- 「⋯」: すべて AI で下書き・保存して次へ・結果を見る・複製・取りやめ・削除(今の `CardMenu`)・詳しい画面へ(トグルを変えずに、この配信だけ今の配信カードで開く)。

## 11. 気をつけること

- 画面の文言は `t('日本語', 'English')`。色は `tokens`(選んだ部品の枠も)。プレビューの中(受信側の見た目)だけは直書きの例外。
- X47(並べ替え・外すは中ペインだけ、商品情報のペインに操作を置かない)は今の配信カードの約束。この画面では、選んだ部品のペインと商品のフロートで商品を操作するので、段階 (a) で CLAUDE.md・ARCHITECTURE の書き方を「今の配信カードでは」に直す。
- 新しい localStorage のキーは ARCHITECTURE の 8 章の表に足す。
- 標準のテンプレートの構成(セクションの種類・数・順)は変えない(保存済みのカードがずれる)。
- 撮影用の画面で配信カードを開くと、中身が空の配信では自動の下書きが始まる(確かめるときは `cardDetail.autoDraft` を `off`)。

## 12. 段階 (a) で作ったもの(2026-10-22)

- 上の 10 章の (a) のとおり。作り・決まりは [ARCHITECTURE.md](ARCHITECTURE.md) の「シンプルな配信カード」にまとめた。
- 作りながら決めたこと: シンプルな画面は保存済みの配信だけ(新規作成・まとめて作った案は今の画面。自動の反映で新しい配信を作らないため)。AB テストの配信は A 案だけを直す(段階 c まで)。テンプレートの札は、いまは名前と説明だけ(選び直しは段階 b)。リンク先はメイン画像・ボタンを選んだときに直せる(アプリの開く画面は詳しい画面で)。制作の担当・締め切りは概要に出すが、決めるのは今までどおり引き継ぎのタブ。
- 空いた枠に入れた商品は、前から埋まる(テンプレートの枠は、商品の並びの順に埋まるため)。

## 13. 段階 (a) の見直し(2026-10-22、利用者に見てもらって)

- 切り替えはヘッダーではなく、配信カードの上の帯の「シンプル | 詳しい」。最後に選んだ方を、次に開くときも使う。「⋯」の「詳しい画面へ」はなくした。
- プレビューのペインは、メールの幅に合わせる(広すぎた)。余りは選んだ部品のペインへ(段階 b の AI のチャットを置く)。
- プレビューは、画像を見るソフトのように: Ctrl + ホイールで拡大縮小(ホイールだけはスクロール)、部品の外をつかんで移動(スペース + ドラッグでどこでも)、右下に「− 倍率 +」。
- 概要の帯は、なくした(ごちゃつく。国・担当・制作指示・締め切りは、文言を直すときに使わない)。テーマと切り口だけを「ねらい」として、選んだ部品のペインの上に小さく出す。ほかは「配信の情報」に。
- 次は段階 (b): 選んだ部品のペインの下に、指示の候補つきの AI のチャット。案を 2〜3 個出し、乗せるとプレビューに仮で写り、押すと採用(元に戻すで戻せる)。

## 14. 段階 (b) の 1 つ目: 文言の部品を AI に頼む(2026-10-22)

- 文言の部品を選ぶと、入力欄の下に「AI に頼む」。指示の例の札(コピーなら「もっと短く」「ベネフィットを先に」「親しみやすく」「行動を促す一文を足して」、見出しなら「言い切る形に」「別の切り口で」など)と、自由に書く欄(Enter で送る)。
- 案は 3 つ(文言と、そう直した理由)。乗せるとプレビューに仮で写り、押すと採用。採用は元に戻すで戻せる。質問・相談には答えだけを返す。
- 残り(段階 b): メイン画像・商品を AI に頼む(「もっと明るい写真」「在庫の多いものに」)、何も選んでいないときの配信の全体への依頼、目印(未確認・アラート・学び)、テンプレートの選び直し。
- 商品のペインは、商品の箱を押すと詳しい情報(「詳しい情報・差し替え・画像…」のボタンは外した)。
- 追記(同じ日): メイン画像・商品も AI に頼めるようにした(札: 画像「もっと明るい写真に」「人物が入ったもの」…、商品「在庫の多いものに」「価格帯を下げて」…、空いた枠「この配信に合うもの」…)。案は候補の中から 3 つ、乗せるとプレビューに写り、押すと採用。残り(段階 b): 何も選んでいないときの配信の全体への依頼、目印、テンプレートの選び直し。
- 追記(同じ日): 何も選んでいないときは、配信の全体を AI に頼める(札「もっとカジュアルに」「季節感を強く」「高級感を出して」「全体を短く」)。案は 2〜3 つで、変える文言とメイン画像をまとめて持ち、乗せるとまとめて写り、押すとまとめて入る。商品は変えない(枠ごとに頼む)。(b) の残りは、目印とテンプレートの選び直し。
- 追記(同じ日): 目印(「目印」のメニューで、AI 下書き・未確認の点 / アラートの印 / これまでの学びの帯を出し分ける)と、テンプレートの選び直し(見取り図つきの一覧、乗せるとプレビューに仮で写り、押すと替わる。枠外の件数を知らせる)を作り、段階 (b) は一通りできた。次は (c) AB テスト(SU2)・(d) コミュニケーション。

## 15. 段階 (c): AB テスト(SU2)(2026-10-22)

- 作ったもの: 案のタブ・案を足す(A / B を写す・AI で別の案)・並べて比べる・⚙ の設定。比べる要素は A と違う所から自動(保存のときに決める)。B・C の A と違う部品に目印、違いが 3 か所以上なら知らせる(AB テストのときだけ)。A を直すと、B・C のまだ直していない部品も合わせる。テーマ・リンク先は全部の案で共通(ペインに出す)。

## 19. テンプレートが見つからない配信の AI ドラフトのやり直し(2026-10-24)
