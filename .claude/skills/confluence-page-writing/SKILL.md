# Confluence のページを書く

AI が書いた資料が読みにくいのは、中身ではなく作法のずれが原因であることが多い。どのセクションも同じ分量で、立場がなく、抽象的な言葉で言い切り、社内の文脈を使わない。このスキルは、特定の読者に向けて人が書いたページに近づけるための手順と決まりをまとめたもの。

英語のページは `confluence-page-writing-en` を使う。

## 1. 書く前に方向性を確かめる

Confluence に直接ページを作る・既存のページを書き換えるとき(コネクタやブラウザで書き込むとき)も、書き込む前にこの手順に従う。

本文を書き始める前に、必ず方向性を確かめる。ゼロから質問するのではなく、会話から推測できることは推測して「こう考えています」と案を出し、それでよいかを確かめる形にする。

確かめること:

- 読者: 誰が読むか(例: 営業の課長、新しく入ったエンジニア、承認する部長)
- 目的: 読んだあと、読者に何をしてほしいか(決める / 理解して作業する / 知っておく)
- 結論・立場: 書き手として何を推すか、何を決めたいか
- 分量と深さ: 1 画面でさっと読めるものか、細部まで書き込む資料か

聞き方:

- 質問はまとめて 1 回、最大 4 つまで。選択肢で答えられる形にする。選択肢を出せる道具があれば使う。
- **読者と用途(読んだあと何をしてほしいか)は、毎回必ず最初に聞く。** 会話から推測できても省かず、推測した案を「推奨」として最初の選択肢に置いて確かめる。
- ほかの項目は、推測できる案を「推奨」として最初の選択肢に置く。会話ではっきりしている項目は聞かない。
- 答えをもらったら、本文の前に「見出しの並び」と「各見出しで言うこと(1 行ずつ)」を見せて確認を取る。直しがあれば、直してから本文に入る。
- 利用者が「おまかせ」「聞かずに作って」とはっきり言ったときと、予約で動いていて返事が来ない状況でだけ、聞かずに進める。そのときは読者と用途(読んだあと何をしてほしいか)も含めて、仮に決めた内容をページの冒頭に書いて進める。

`examples/` に見本がある場合は、書く前に必ず読む。`good/` は写すべき作法、`bad/` は避けるべき書き方とその理由。

## 2. 構成

冒頭の 3 行で、このページの用件が分かるようにする。

```
目的: このページで何を伝えるか(1 文)
結論: 決まったこと・提案すること(1〜2 文)
お願い: 読者にしてほしいこと(期限があれば期限も)
```

そのあとは、読者が必要とする順に並べる。決まった型に当てはめない。目安:

- 意思決定を求めるページ: 結論 → 理由 → 他の案と比べてどうか → 懸念と対策 → 決めてほしいこと
- 作業の説明: 何ができるようになるか → 手順 → つまずきやすい所 → 困ったときの連絡先
- 共有・報告: 何が変わったか → 影響を受ける人 → 次の予定

最後に、決定事項と次のアクション(担当と期限)を置く。「まとめ」で本文を繰り返さない。

## 3. 分量にでこぼこをつける

- いちばん大事なセクションに分量を寄せる。どのセクションも同じ長さにそろえない。
- 読者が知っていることは 1 行で済ませるか、書かない。
- 箇条書きの数をそろえない。3 つずつ並べるのは AI の書き方の典型。

## 4. 文章の決まり

- 説明は段落で書く。箇条書きは、手順・並列の項目・比較のときだけ使う。
- 太字は、ページ全体で数か所まで。
- 主張には、具体的な例・数字・画面・リンクのどれかを 1 つ付ける。
- 書き手の判断をはっきり書く。「A を推奨します。理由は〜」「ここはまだ不安があります」。どちらとも言えない書き方で終わらせない。
- 社内での呼び名をそのまま使う。略語は最初に出たときだけ説明する。

避ける言い回し:

| 避ける | 代わりに |
|---|---|
| 〜の最適化を図る / 〜の実現 / 〜を推進する | 何をどう変えるかを具体的に書く |
| 〜となります / 〜することが可能です | 〜です / 〜できます |
| 重要なのは〜です / 〜と言えるでしょう | 言い切る、または理由を書く |
| 体言止めの連続、コロンやダッシュの多用 | ふつうの文にする |
| 「以下に〜をまとめます」などの前置き | 前置きなしで本題に入る |

## 5. Confluence での見せ方

- 見出しは 2 段階(H2・H3)まで。
- 詳しい補足・ログ・長い表は、展開マクロに入れる。
- 注意事項は注意パネル、補足は情報パネルに入れる。パネルは 1 ページに 2〜3 個まで。
- 状態(検討中・決定・保留)はステータスマクロで示す。
- 表は比較のときだけ使う。文章で書けるものを表にしない。
- スクロール 3 画面を超えそうなら、子ページに分けて親ページから案内する。
- 目次マクロは長いページだけに置く。
- 担当者はメンション、期限は日付で書く。

出力が Markdown の場合は、Confluence に貼り付けて崩れない書き方にし、マクロを使う箇所は「(展開マクロ)」のように明記する。

## 6. 仕上げの見直し

書き終えたら、そのページを初めて開く読者になったつもりで読み、次を確かめる。直してから出す。

- 冒頭の 3 行だけで、用件と自分がすべきことが分かるか
- いちばん大事な所が、いちばん厚く書かれているか
- 具体例のない主張が残っていないか
- 書き手の意見がどこにあるか分かるか
- 上の「避ける言い回し」が残っていないか
- 太字・箇条書き・パネルが多すぎないか

## 見本の置き場所

- `examples/good/`: 社内で読みやすいと評判の、人が書いたページ(顧客名・数字は伏せる)
- `examples/bad/`: 読みにくいと言われたページと、どこが読みにくいかのコメント

見本から読み取れる作法は、このファイルの決まりにも書き足していく。このリポジトリは公開(public)なので、見本は機密を含まないものだけを置く。
